# CallAgent workspace troubleshooting

- **Progress missing or stale**: “No progress reported” is normal for agents that
  do not opt in. Staleness alone is not failure. `RUN_PROGRESS_INVALID` is a bad
  payload, `RUN_PROGRESS_FENCE_LOST` a superseded attempt,
  `RUN_PROGRESS_TERMINAL` a late report, `RUN_PROGRESS_RATE_LIMITED` throttling,
  and `RUN_PROGRESS_UNAVAILABLE` a storage/configuration outage.

- **“Build the agent project”**: run the agent project's build command. A
  workspace loads compiled JavaScript and compiled copies of both manifests.
- **Duplicate IDs or ambiguous aliases**: every selected agent source must
  expose unique canonical IDs. Rename one agent and rebuild it.
- **Environment conflict warning**: the first value wins: inherited process
  environment, then the CallAgent workspace `.env`, then agent-source `.env`
  files in registry order. Warnings intentionally never show values.
- **Infrastructure preflight failure**: start/configure Postgres, NATS, and
  Hatchet before `callagent start`. From a workspace, use `npm run infra:up` for
  the packaged local Hatchet/NATS profile; Postgres remains an external service.
- **Database schema is missing**: set `MEMORY_DATABASE_URL` in the workspace
  `.env`, then run `npm run db:setup` from that workspace. Do not run framework
  repository scripts for a consuming workspace.
- **Hatchet says `UNAUTHENTICATED: invalid auth token`**: open this workspace's
  `HATCHET_DASHBOARD_URL`, create a new token under **Settings → API Tokens**,
  update `HATCHET_CLIENT_TOKEN` in its `.env`, and restart `npm run start`.
  Tokens are specific to one Hatchet instance; do not reuse one from another
  workspace or from a stack whose Docker volumes were removed.
- **Host/worker fingerprint mismatch**: stop the runtime, validate again, and
  restart. Both processes must use the descriptor generated by one CLI run.
- **Global command uses an unexpected version**: use `npm run start` from the
  CallAgent workspace. The project-pinned CLI is authoritative.
- **Local checkout overlay is missing or stale**: run `callagent local status`,
  then `callagent local sync`. A source checkout must have dependencies and
  built `core`, `runtime`, and `cli` packages. `callagent local install` installs
  non-CallAgent dependencies without changing the publishable manifest or lockfile.
- **Yarn says a local project is missing from its lockfile**: after
  `callagent local install --package-manager yarn`, use `npm run build` or the
  relevant binary from `node_modules/.bin`. Plain `yarn install` and `yarn run`
  resolve unpublished CallAgent semver dependencies by design and cannot be used
  until that package set has been published.

Run `callagent workspace validate --json` for a structured description of a
composition problem.
