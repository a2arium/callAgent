# 2.3 Learning Single-Writer Rule — Control / Cognition Separation

This document defines the normative specification for removing framework-level `llmState` injections into `MentalState`, enforcing strict cognitive purity where only `Learning` acts as the single writer.

**REMEMBER: We do not support backwards compatibility.**
After these changes are implemented, final migration instructions will be saved to `apps/docs/migration/2.3-learning-single-writer-migration.md`.

---

## Problem Statement

The current orchestration persistence mechanisms (`TurnRunner.ts`, `TaskExecutor.ts`, `taskEngine.ts`, `init.ts`) manually inject the LLM conversation history (adapter's `exportState()` / `getMessages()`) directly into `M.memory.sensory.llmState` during context flushing.

This violates:

1. **APLRET Rule 2 — Single writer for cognition** (`0-aplret_contracts.md` §2): Only `Learning` may update `MentalState`. The framework infrastructure must never natively inject key-value pairs directly into the cognitive tree.
2. **APLRET Rule 7 — Explicit control ownership** (`0-aplret_contracts.md` §7): Cognition (`MentalState`) and control (transport/history) are separate systems. "Never persist control flags in MentalState." The LLM dialogue tracking payload (`historyMode: 'full'`/`'dynamic'`) is infrastructural control state, not agent reasoning material.
3. **types-rules.md Rule 1 — Types Must Reflect Runtime Behavior**: The `Snapshot` type (`types.ts` line 171) must include `llmState` if the runtime stores it at the snapshot root. Currently any access requires `as any` casting.
4. **types-rules.md Rule 5 — `any` Is Forbidden in Public APIs**: All LLM state access currently goes through `(ctx as any).llm as any`. The refactoring must not introduce new `any` casts or hidden context mutations.

### Current Blast vs Actual Usage

No agent in the codebase reads `M.memory.sensory.llmState`. The framework injects it silently during persistence and reads it back during restoration — the agent never sees it. The real-world migration risk on agent code is **zero**. This is purely a framework infrastructure cleanup.

The LLM conversation history will continue to be persisted and restored transparently. The only change is *where* it lives in the snapshot: `snapshot.llmState` (typed on `Snapshot`) instead of `snapshot.M.memory.sensory.llmState` (untyped, cast via `as any`).

## Type Safety Requirements (types-rules.md Compliance)

These requirements address issues flagged by `types-rules.md`:

| Rule | Current Violation | Required Fix |
|------|-------------------|-------------|
| **Rule 1** — Types must reflect runtime | `Snapshot` type has no `llmState` field, but runtime writes it there | Add `llmState?: unknown` to `Snapshot` type |
| **Rule 5** — No `any` in public APIs | All LLM access via `(ctx as any).llm as any` | Pre-existing tech debt (out of scope for this ticket), but **no new `as any` introductions** allowed |
| **Anti-pattern: hidden context mutations** | `(ctx as any).__lastSnapshotBase = baseSnap` is an undocumented side-channel between `restoreCtx` and `attachAndRestoreLLM` | **Eliminate**. Pass `baseSnap` as an explicit parameter to `attachAndRestoreLLM(ctx, agentName, M, baseSnap)` |
| **Anti-pattern: implicit undefined states** | Legacy fallback chain silently degrades across 3 locations | **Remove** all legacy fallbacks. Single canonical read: `baseSnap.llmState` |

### No New `any` Rule

The implementation MUST NOT introduce new `as any` casts beyond those already present. Specifically:

- `__lastSnapshotBase` must be eliminated (hidden mutation)
- The `Snapshot` type update enables typed access to `llmState` without casting
- Comments referencing old behavior (e.g., init.ts line 3) must be corrected

## Migration Plan

Following implementation, `apps/docs/migration/2.3-learning-single-writer-migration.md` must be created covering:

1. **Breaking change**: `M.memory.sensory.llmState` is no longer populated. Any agent code that read this property (none exist today, but third-party agents may) will find it `undefined`.
2. **Framework transparency**: LLM conversation history continues to be persisted and restored automatically via `snapshot.llmState`. No agent configuration changes needed.
3. **If you need LLM history in cognition**: Agents that want to reason about past conversation turns must emit them as explicit `internal` observations and store derived insights in `episodic` or `worldModel` memory through the standard loop pipeline.
4. **Type update**: The `Snapshot` type now includes `llmState?: unknown`. Code that previously cast `(snap?.snapshot as any)?.M?.memory?.sensory?.llmState` should use `(snap?.snapshot as Snapshot)?.llmState`.
