# How-to: Build the Official APLRET Test Harness

Use this guide when you maintain the callagent framework and need a first-class harness for deterministic, turn-by-turn tests.

## Goal

Provide a harness that:

- runs **exactly one turn** at a time
- allows deterministic injection of inbox observations
- supports async resumes for input/tool/child tokens
- captures TurnTrace per turn
- exposes high-signal assertion helpers

The harness is a framework product: it defines how teams test agents and how LLM coding tools learn to make safe changes.

## Non-goals

- end-to-end UI automation
- mocking external vendor SDKs directly
- building a statechart runner

## Harness design principles

1. **Turn as unit**: one API call runs one turn.
2. **Inbox as input**: Perception must see only staged inbox observations.
3. **Determinism**: tests control time, randomness, and tool/LLM outcomes.
4. **Trace-first**: tests assert TurnTrace, not only user-visible text.
5. **Ergonomics**: common assertions are one-liners.

## Minimal harness API surface

### Construction

- `createHarness(agent)`

### State seeding

- `seedMentalState(m)`
- `seedControlState(control)` (optional)
- `seedPending(pending)` (optional)
- `seedManifestSources(agentCardSource, runtimeManifestSource)` (optional, for overrides)

### Injection

- `injectObservation(observation)`
- `injectUserInput(value)` -> converts to `user / input.provided`
- `injectToolCompleted({ token, tool, result })`
- `injectToolFailed({ token, tool, error })`
- `injectChildCompleted({ token, agentId, childTaskId, result, metadata })`
- `injectEnvEvent({ kind, payload })`

### Execution

- `runTurn()` -> returns harness (chainable) or a `TurnResult`

### Introspection

- `lastTrace()`
- `traces()`
- `lastAwaitToken()`
- `currentStage()`
- `pendingSummary()`
- `mentalState()` (optional for deep tests)

### Assertions

- `expectIntent(kind)`
- `expectShield(action)`
- `expectExecAction(kind)`
- `expectTransition(kind)`
- `expectAwait(kind)`
- `expectAwaitToken(token)`
- `expectInboxKinds([...])`
- `expectInvariantError(code)`
- `expectMemoryChanged()` / `expectMemoryUnchanged()`
- `expectStage(before?, after?)`
- `expectStageTransition(from, to)`
- `expectAgentCardSource(source)`
- `expectRuntimeManifestSource(source)`
- `expectAgentCardHash(hash)`
- `expectRuntimeManifestHash(hash)`

## Step-by-step implementation

### Step 1: Make the runtime injectable

The harness needs control over:

- current time
- randomness
- tool results
- child completion injection
- LLM outputs

Implement runtime adapters:

- `Clock` (now, sleep)
- `Rng` (uuid, random)
- `ToolRunner` (sync/async)
- `ChildRunner` (sync/async)
- `LlmClient` (deterministic stub)

Rule:

- production runtime uses real adapters
- harness uses deterministic adapters

### Step 2: Build an inbox staging layer

Harness should maintain:

- `inbox.all` (append-only)
- `inbox.current` (staged for next `runTurn()`)

Rule:

- `runTurn()` must pass only `inbox.current` to Perception
- after the turn, the harness clears `inbox.current`
- all injected observations are appended to `inbox.all` in order

### Step 3: Implement await/resume token mechanics

When a turn returns `await_*`:

- store the awaited token
- store pending category (`input` | `tool` | `child`)

Provide helpers:

- `lastAwaitToken()`
- `injectToolCompleted({ token: lastAwaitToken(), ... })`

Validation:

- injecting a completion with an unknown token should fail loudly

### Step 4: Capture TurnTrace per turn

`runTurn()` should:

- capture the TurnTrace emitted by the runtime
- store it in an ordered list
- allow tests to assert on it
- include manifest provenance hashes (useful for detecting config drift)

Rule:

- one `runTurn()` -> one TurnTrace record

### Step 5: Provide assertion helpers that map to trace fields

Assertions should not require test authors to hand-parse JSON.

Examples:

- `expectTransition('await_tool')` checks `trace.transition.kind`
- `expectAwaitToken(x)` checks token match between execAction and transition
- `expectInboxKinds([...])` checks `trace.inboxCurrent` summary

### Step 6: Implement deterministic stubs

#### LLM stub

Provide:

- canned responses by prompt key
- forced timeout
- forced error
- usage metadata

#### Tool stub

Provide:

- mapping of toolName -> response
- mapping of toolName -> async token + later completion

#### Child stub

Provide:

- mapping of agentId -> response
- mapping of agentId -> async token + later completion

Rule:

- async stubs must model the same resume path as production

### Step 7: Ship canonical test templates

Provide sample tests that demonstrate:

- golden path
- await_tool resume
- await_child resume
- invariant failure
- idempotency collision

These templates become de-facto training data for LLM coding tools.

## Harness acceptance tests (framework-level)

The harness is “done” when these pass:

1. **One turn -> one trace**
2. **Inbox staged correctly**
3. **Await token propagation**
4. **Resume injection works** for tool/child/input
5. **Invariant failures are observable**
6. **Manifest provenance works**: TurnTrace asserts correct manifest resolution
7. **Determinism**: repeated runs with the same injections produce the same trace skeleton

## Common pitfalls

- allowing Perception to read from inbox.all instead of inbox.current
- clearing inbox.current too early (before Perception)
- letting Policy read harness/runtime context
- stubbing sync calls but not modeling async resumes
- asserting on LLM text rather than trace facts
- making assertions too brittle (e.g., full JSON snapshots)

## Recommended example: async tool test (skeleton)

```ts
const h = createHarness(agent)
  .injectUserInput({ text: 'Lookup invoice inv_123' })
  .runTurn();

h.expectIntent('call_tool');
h.expectStageTransition('idle', 'awaiting_tool');
h.expectTransition('await_tool');

h.injectToolCompleted({
  token: h.lastAwaitToken(),
  tool: 'billing.lookup_invoice',
  result: { invoiceId: 'inv_123', status: 'paid' }
});

h.runTurn();
h.expectIntent('answer_with_llm');
```

This test asserts the turn-by-turn pipeline, not just the final output.
