# 3.2 Manifest Split and Validation

## Problem Statement

The codebase currently uses a **single** `agent.json` file as a consolidated manifest. This flat bag-of-properties approach conflates two fundamentally different concerns:

1. **Public identity** (A2A discovery: name, description, skills, supported I/O modes, capabilities) — which external callers and registries must be able to read.
2. **Internal runtime config** (loop budgets, caching, HITL, safety, observability toggles, feature flags) — which must **never** leak to external callers.

The APLRET contracts (`0-aplret_contracts.md`) and the manifest specification (`2-manifest_spec_agent_card_runtime_manifest.md`) mandate a clean split into two strongly-typed files:

| File | Responsibility | Public? |
|---|---|---|
| `agent-card.json` | A2A discovery contract (skills, modes, capabilities, extensions) | Yes — served at `/.well-known/agent-card.json` |
| `agent-runtime.json` | Execution config (budgets, caching, safety, HITL, observability, flags) | No — internal only |

The current `AgentManifest` type is defined with a loose `[key: string]: unknown` index signature, allowing **any** field. This violates the types-rules contract (Rule 2: Schemas Are the Source of Truth, Rule 4: Illegal States Must Not Compile, Rule 5: No `any`). Both schemas must be defined as **Zod schemas first**, with TypeScript types inferred from them.

This task also blocks `3.5-turn-trace-provenance.md`, which requires computed hashes and resolution sources for both manifests.

#### 1.1 Agent Card Schema

File: `packages/core/src/types/agentCard.ts` **(NEW)**

> [!IMPORTANT]
> The `AgentCardSchema` does **NOT** use `.strict()`. The Agent Card is an **A2A public protocol surface** —
> external clients and registries may include additional standard A2A fields (`securitySchemes`, `security`,
> `signatures`, etc.) that callagent does not model. Using `.strict()` would reject valid A2A-compliant cards.
> Unknown fields are allowed and passed through.

> [!IMPORTANT]
> Per the normative spec (`2-manifest_spec_agent_card_runtime_manifest.md`, lines 99-111), the following
> fields are **required** (MUST), not optional: `description`, `supportedInterfaces`, `capabilities`,
> `defaultInputModes`, `defaultOutputModes`, `skills`. The Zod schema enforces this.

```typescript
import { z } from 'zod';

const SkillSchema = z.object({
  id: z.string().min(1),
  name: z.string().optional(),
  description: z.string().optional(),
  inputModes: z.array(z.string()).optional(),
  outputModes: z.array(z.string()).optional(),
});

const ExtensionSchema = z.object({
  uri: z.string().min(1),
  required: z.boolean().optional(),
  params: z.record(z.unknown()).optional(),
});

const SupportedInterfaceSchema = z.object({
  protocolBinding: z.string().optional(),
  protocolVersion: z.string().optional(),
  url: z.string().optional(),
}).passthrough();

export const AgentCardSchema = z.object({
  // Required identity
  name: z.string().min(1),
  version: z.string().min(1),
  description: z.string().min(1),

  // Required A2A discovery fields (per normative spec)
  supportedInterfaces: z.array(SupportedInterfaceSchema).min(1),
  capabilities: z.object({
    streaming: z.boolean().optional(),
    pushNotifications: z.boolean().optional(),
    extensions: z.array(ExtensionSchema).optional(),
  }),
  defaultInputModes: z.array(z.string()).min(1),
  defaultOutputModes: z.array(z.string()).min(1),
  skills: z.array(SkillSchema).min(1),

  // Optional A2A metadata
  url: z.string().optional(),
  provider: z.object({
    organization: z.string(),
    url: z.string().optional(),
  }).optional(),
  documentationUrl: z.string().optional(),
  iconUrl: z.string().optional(),
});
// NOTE: No .strict() — A2A cards may contain additional standard fields

export type AgentCard = z.infer<typeof AgentCardSchema>;
```

#### 1.2 Agent Runtime Manifest Schema

File: `packages/core/src/types/agentRuntimeManifest.ts` **(NEW)**

> [!IMPORTANT]
> **Spec amendment:** The `runMode` field is **added** to the runtime manifest schema. This field existed in
> the legacy `AgentManifest` and is required for the framework to select the execution model. It is not
> present in the normative spec (`2-manifest_spec_agent_card_runtime_manifest.md`); this document amends
> the spec to include it. The normative spec should be updated to reflect this addition.

> [!IMPORTANT]
> Unlike the Agent Card, the `AgentRuntimeManifestSchema` uses `.strict()`. The runtime manifest is an
> **internal** framework surface — unknown fields indicate a configuration mistake and must be caught early.

```typescript
import { z } from 'zod';

export const AgentRuntimeManifestSchema = z.object({
  name: z.string().min(1),
  version: z.string().min(1),
  agentCardRef: z.string().optional(),

  // Spec amendment: not in normative spec, but required for framework execution model selection
  runMode: z.enum(['loop', 'legacy']).default('loop'),

  budgets: z.object({
    maxTurns: z.number().int().positive().optional(),
    latencyMs: z.number().int().positive().optional(),
    maxConcurrentEffects: z.number().int().positive().optional(),
  }).optional(),

  hitl: z.object({
    level: z.enum(['advise', 'consent', 'guardrails']).optional(),
    requireConsentFor: z.object({
      intents: z.array(z.string()).optional(),
      tools: z.array(z.string()).optional(),
    }).optional(),
  }).optional(),

  safety: z.object({
    sanitize: z.boolean().optional(),
    piiPatterns: z.array(z.string()).optional(),
    costLimitUsd: z.number().optional(),
    mode: z.enum(['transform', 'reject']).optional(),
  }).optional(),

  cache: z.object({
    enabled: z.boolean().optional(),
    ttlSeconds: z.number().int().positive().optional(),
    excludePaths: z.array(z.string()).optional(),
  }).optional(),

  // Typed config per normative spec (lines 190-195)
  config: z.object({
    enableValidation: z.boolean().optional(),
    validationCoverageThreshold: z.number().optional(),
    featureFlags: z.record(z.boolean()).optional(),
  }).optional(),

  dependencies: z.object({
    agents: z.array(z.string()).optional(),
  }).optional(),

  // Memory config — closed shape, no passthrough
  memory: z.object({
    profile: z.string().optional(),
  }).optional(),

  observability: z.object({
    turnTrace: z.object({
      enabled: z.boolean().optional(),
      level: z.enum(['summary', 'full']).optional(),
    }).optional(),
    logs: z.object({
      level: z.enum(['debug', 'info', 'warn', 'error']).optional(),
    }).optional(),
  }).optional(),
}).strict();

export type AgentRuntimeManifest = z.infer<typeof AgentRuntimeManifestSchema>;
```

### 3. Resolution + Validation + Hashing Logic

File: `packages/core/src/plugin/manifestResolver.ts` **(NEW)**

Implement a single `resolveManifests(...)` function that runs pre-flight:

```typescript
export async function resolveManifests(
  callerDir: string,
  options?: {
    agentCard?: ManifestSource<AgentCard>;
    runtimeManifest?: ManifestSource<AgentRuntimeManifest>;
  }
): Promise<ResolvedManifests>;
```

> [!IMPORTANT]
> The function is **async** because it performs file I/O (reading JSON files from disk via `fs.readFile`).
> This affects the entire calling stack — `createAgent` must also become async (it already returns
> `AgentPlugin` which can be awaited in module-level code).

**Resolution precedence (applied independently to each manifest):**

1. `inline` object if provided → source = `'inline'`
2. `path` override if provided → source = `'pathOverride'`
3. Default file in `callerDir` (`agent-card.json` / `agent-runtime.json`) → source = `'defaultPath'`

**Validation steps (hard fail on any error):**

1. Parse JSON (if from file)
2. Validate against Zod schema — use `.parse()`, let it throw `ZodError`
3. **Identity match**: `agentCard.name === runtimeManifest.name` AND `agentCard.version === runtimeManifest.version`
4. Compute stable hashes for both resolved objects

**Hashing requirements:**

- Canonicalize JSON before hashing (sorted keys, no trailing whitespace)
- Use SHA-256 truncated to 12 hex chars (or configurable)
- Hash must be stable across whitespace/key-order changes in source files

**Error shape:** Throw `ManifestError` with typed details (see §3a below).

### 3a. Typed Manifest Error Details (Rule 11)

File: `packages/core/src/types/manifestErrors.ts` **(NEW)**

> [!IMPORTANT]
> Per types-rules.md Rule 11 (Errors Must Be Typed), manifest errors must use a typed detail union,
> not `Record<string, unknown>`.

```typescript
import { ZodError } from 'zod';

export type ManifestErrorDetail =
  | { type: 'identity_mismatch'; agentCardName: string; agentCardVersion: string; runtimeName: string; runtimeVersion: string }
  | { type: 'schema_validation'; manifest: 'agentCard' | 'runtimeManifest'; zodError: ZodError }
  | { type: 'file_not_found'; path: string; manifest: 'agentCard' | 'runtimeManifest' }
  | { type: 'parse_error'; path: string; manifest: 'agentCard' | 'runtimeManifest'; message: string };
```

`ManifestError` in `errors.ts` should be updated to accept `ManifestErrorDetail` instead of `Record<string, unknown>`:

```typescript
export class ManifestError extends PluginError {
  constructor(message: string, public detail?: ManifestErrorDetail) {
    super(message, detail ? { ...detail } : undefined);
    Object.setPrototypeOf(this, ManifestError.prototype);
  }
}
```

Example:
```typescript
throw new ManifestError(
  'Manifest identity mismatch: agent-card.json and agent-runtime.json must have the same name and version',
  {
    type: 'identity_mismatch',
    agentCardName: card.name,
    agentCardVersion: card.version,
    runtimeName: runtime.name,
    runtimeVersion: runtime.version,
  }
);
```

### 19. Clean API Constraints

- **NO backwards compatibility**: The framework will **not** support old `AgentManifest` or `agent.json`.
- **NO `any` usage** (Rule 5): All schemas use `z.unknown()` for opaque payloads. No `as any` casts for manifest access.
- **NO `[key: string]: unknown`** index signatures on runtime manifest. Uses `.strict()`.
- **NO `.passthrough()`** on internal schemas (runtime manifest, memory config). Only the Agent Card schema allows unknown fields (because it is a public A2A protocol surface).
- **Public vs Internal Separation** (Rule 10): `AgentCardSchema` and `AgentRuntimeManifestSchema` are in dedicated files under `packages/core/src/types/`.
- **Typed errors** (Rule 11): `ManifestError` uses a discriminated `ManifestErrorDetail` union, not `Record<string, unknown>`.
