# 3.5 TurnTrace, Telemetry Redesign, and Manifest Provenance

> **Internal implementation spec.** This document is for implementers (framework contributors and maintainers). It describes file-level changes, type redesigns, and acceptance criteria.
> **For framework users migrating their agents**, see the end-user migration guide: **[apps/docs/migration/3.5-turn-trace-telemetry-migration.md](../migration/3.5-turn-trace-telemetry-migration.md)** (to be created as part of this task).

**Scope:** This document covers three intertwined changes:

1. **TurnTrace as a first-class runtime artifact** — emit one structured `TurnTrace` record per turn, capturing the full APLRET pipeline (inbox, perception, learning, policy, shield, execution, transition, stage, timings, usage, correlation, pending state).
2. **Telemetry redesign** — collapse the current per-module `ModuleNode` spam into a single `TurnNode` per turn, with LLM/tool/child calls as sub-spans of the turn (not sub-spans of individual modules). Module-level timing becomes fields within TurnTrace, not separate telemetry nodes.
3. **Manifest provenance** — resolve Agent Card and Runtime Manifest when the session is created, compute stable hashes, enforce identity match, persist in session/snapshot metadata, and stamp every TurnTrace with provenance fields.

Out of scope: test harness helpers (`expectStage`, `expectTurn`, `seedControlState`) — those are owned by 3.7. This task produces the data that 3.7 will consume.

Implement manifest resolution, validation, identity match, and stable hash computation.

```typescript
import type { z } from 'zod';
import type { ManifestProvenance, ManifestSource } from '../types/turnTrace.js';
import { AgentCardSchema, AgentRuntimeManifestSchema } from '@a2arium/callagent-types';

type AgentCard = z.infer<typeof AgentCardSchema>;
type AgentRuntimeManifest = z.infer<typeof AgentRuntimeManifestSchema>;

export type ManifestResolutionInput = {
    agentCard?: { source: ManifestSource; content: AgentCard };
    runtimeManifest?: { source: ManifestSource; content: AgentRuntimeManifest };
};

export function resolveManifestProvenance(input: ManifestResolutionInput): ManifestProvenance;
export function computeStableHash(obj: AgentCard | AgentRuntimeManifest | Record<string, unknown>): string;
export function validateManifestIdentity(
    agentCard: AgentCard,
    runtimeManifest: AgentRuntimeManifest
): void;
```

Implementation requirements:

1. **Stable hash** — canonicalize JSON (sorted keys, no trailing whitespace) before hashing. Use SHA-256. Do not hash raw file bytes.
2. **Identity match** — Agent Card `name` + `version` must match Runtime Manifest `name` + `version`. Fail fast if mismatch.
3. **Source tracking** — record whether each manifest was resolved from `'defaultPath'` (`./agent-card.json`, `./agent.runtime.json`), `'pathOverride'` (explicit path), or `'inline'` (passed directly).
4. **Session-level constants** — compute once when the session is created, persist them in session metadata / snapshot metadata, and copy them into each TurnTrace on every resume path.
5. **Fail-fast** — if resolution or validation fails, the runtime MUST NOT start the loop. Throw a structured error.

### 3. Redesign telemetry: remove per-module nodes, make TurnNode carry TurnTrace

**Rule enforcement: APLRET contracts §TurnTrace ("one TurnTrace record per turn"), telemetry clarity**

This is the core architectural change. The current approach creates 7+ `ModuleNode`s per turn plus a `TurnNode` that carries no structured data. The new approach:

- **`TurnNode` carries the full `TurnTrace`** as structured data (not just raw input/output)
- **No `ModuleNode`s** — module timings become fields within `TurnTrace.timings`
- **LLM/tool/child sub-spans** are children of `TurnNode`, not children of module nodes
- **One emission per turn** instead of 7+ emissions per turn

#### 3a. Redesign `TurnNode`

File: `packages/core/src/telemetry/nodes/TurnNode.ts` **(MODIFY)**

```typescript
import { TelemetryNode } from './TelemetryNode.js';

export class TurnNode extends TelemetryNode {
    public readonly turnIndex: number;
    public turnTrace?: TurnTrace;

    constructor(turnIndex: number, parentId: string, id?: string, traceId?: string) {
        super('turn', parentId, id, traceId);
        this.turnIndex = turnIndex;
    }
}
```

#### 3b. Remove `ModuleNode` usage from `oneTurn`

File: `packages/core/src/loop/oneTurn.ts` **(MODIFY)**

Replace `runWithTelemetry` (which creates `ModuleNode` per module) with a simple timing wrapper. Module timings are accumulated in the `timings` record (already done) and will be stamped into TurnTrace by the caller.

**Remove:**
- Dynamic `import('../telemetry/TelemetryCollector.js')` inside `oneTurn`
- Dynamic `import('../telemetry/nodes/ModuleNode.js')` inside `oneTurn`
- `ModuleNode` creation, registration, and lifecycle per module

- `ModuleExecutionError` wrapping for module failures
- `InvariantError` passthrough
- `stageTrace` plumbing from 3.4

**New: `oneTurn` return type**

The new return fields use types defined in `turnTrace.ts`; when implementing `oneTurn`, import `JsonValue`, `PerceptionTrace`, `IntentTrace`, `ShieldTrace`, and `InboxObservationSummary` from the turnTrace types module so the return shape is consistent with the assembled TurnTrace.

`oneTurn` must now:
1. Snapshot `inboxCurrent` before any module runs (compact summary: `source`, `kind`, `hasToken`, `token`)
2. Hash `MentalState` before and after Learning (using `computeStableHash` from the provenance module)
3. Capture compact representations of attention output, perception output, intent, and shield outcome
4. Return all of the above in the result object

#### 3c. Collect TurnTrace in `loopRunner`

File: `packages/core/src/loop/loopRunner.ts` **(MODIFY)**

After each `oneTurn` call, `loopRunner` assembles the full `TurnTrace` from:
- `oneTurn` result (timings, stage trace, inbox snapshot, hashes, module outputs)
- Manifest provenance (session-level constant, passed in via options or context)
- Turn metadata (`turn`, `turnId`)
- Pending state summary (computed from `env.pending`)
- LLM/tool usage (aggregated from sub-spans or from `ctx.recordUsage`)
- Correlation context

The assembled `TurnTrace` is:
1. Attached to the `TurnNode` as `turnNode.turnTrace = trace` for in-process inspection and tests
2. Emitted exactly once via `telemetry.emitTurnTrace(trace)`; this is the authoritative provider hook for structured per-turn export
3. Appended to an in-memory `TurnTrace[]` array on the session/context for test harness consumption (3.7)
4. Optionally logged as structured JSON via the logger
5. Followed by `telemetry.endNode(turnNode)` for node lifecycle completion only; providers MUST NOT create a second turn export from `onNodeEnd`

**New `loopRunner` options:**

```typescript
type LoopRunnerOptions = {
    maxTurns?: number;
    latencyMs?: number;
    manifestProvenance?: ManifestProvenance;
    collectTraces?: boolean;
};
```

**New `loopRunner` return:**

```typescript

    M: MentalState<Sensory>;
    outcome: TurnOutcome;
    metrics?: { timings: Record<string, number>[]; rewards: number[] };
    traces?: TurnTrace[];

```

`loopRunner` is the only place that may finalize a turn trace. `oneTurn` collects raw ingredients; providers receive only the final assembled `TurnTrace`.

### 4. Redirect LLM/tool sub-spans to TurnNode

**Rule enforcement: TurnTrace hierarchy clarity**

File: `packages/core/src/loop/oneTurn.ts` **(MODIFY)**

- `ctx.telemetry.nodeId` stays at the `TurnNode` ID for the entire turn
- LLM calls (via `CallagentBridgeProvider`) automatically become children of `TurnNode`

### 4b. Make child/subagent tracing explicit

**Rule enforcement: nested trace hierarchy must be real, not implied**

The current spec mentions child calls as sub-spans of the turn, but the runtime does not currently define that shape or plumb `parentTelemetryNodeId` through `sendTaskToAgent`. This must be explicit.

**Trace hierarchy decision:**

```text
Parent AgentNode
  -> Parent TurnNode
    -> ChildCallNode   // parent-turn dispatch span, keyed by child token
      -> Child AgentNode
        -> Child TurnNode
        -> ...
```

This gives the parent turn a stable local span for dispatch / await / completion, while also linking to the full child execution tree.

File: `packages/core/src/telemetry/nodes/ChildCallNode.ts` **(NEW)**

```typescript
import { TelemetryNode } from './TelemetryNode.js';

export class ChildCallNode extends TelemetryNode {
    public readonly childToken: string;
    public readonly childAgentId?: string;
    public childTaskId?: string;

    constructor(childToken: string, parentId: string, childAgentId?: string, id?: string, traceId?: string) {
        super('child', parentId, id, traceId);
        this.childToken = childToken;
        this.childAgentId = childAgentId;
    }
}
```

Required changes:

1. `TelemetryNode.NodeType` adds `'child'`
2. `ApiBinder.sendTaskToAgent()` creates a `ChildCallNode` under the current `TurnNode` when dispatching a child
3. The created `ChildCallNode.id` is passed through A2A start flow as `parentTelemetryNodeId`
4. `TaskEngine.startTask()` uses that `parentTelemetryNodeId` so the child `AgentNode` becomes a child of the `ChildCallNode`
5. Parent turn `TurnTrace.childCalls[]` records dispatch/completion/failure summaries and links (`childAgentNodeId`, `childTraceId`, `childTaskId`)
6. Child completion injected through inbox updates the existing `ChildCallNode` rather than inventing a second sibling span

This is required for nested subagent tracing. Without it, tools/LLM calls would be nested correctly, but child-agent trees would remain disconnected.

export class TurnTraceCollector {
    private traces: TurnTrace[] = [];

    push(trace: TurnTrace): void {
        this.traces.push(trace);
    }

    getAll(): ReadonlyArray<TurnTrace> {
        return this.traces;

### 18. Clean API Constraints

These constraints MUST hold after implementation:

1. **One TurnTrace per turn** — `loopRunner` emits exactly one `TurnTrace` per `oneTurn` call. No more, no fewer.
2. **No `ModuleNode` spans** — module timings are fields in `TurnTrace.timings`, not separate telemetry spans.
3. **LLM/tool/child sub-spans are children of `TurnNode`** — not children of modules; child-agent execution links through `ChildCallNode`.
4. **Manifest provenance on every TurnTrace** — `agentCardSource`, `runtimeManifestSource`, `agentCardHash`, `runtimeManifestHash` are required fields, validated by Zod schema.
5. **Stable hashes** — changing whitespace or key order in a manifest file MUST NOT change the hash.
6. **Identity match fail-fast** — name/version mismatch between Agent Card and Runtime Manifest prevents loop start.
7. **No `any` in telemetry code** — all `as any` casts in `oneTurn.ts`, `loopRunner.ts`, `OpikProvider.ts`, `ConsoleProvider.ts`, `CallagentBridgeProvider.ts`, `LLMCallerAdapter.ts`, `TurnNode.ts`, `ModuleNode.ts` are eliminated.
8. **TurnTrace emission MUST NOT fail the turn** — if trace collection or emission throws, log a best-effort fallback and continue.
9. **Compact traces** — `inboxCurrent` is a summary (source/kind/token), not raw payloads. Module outputs are compacted. `pendingAfter` is a normalized summary, not raw transport wrappers.
10. **Correlation propagation** — `correlationId`, `traceId`, `spanId` flow from `AgentNode` through `TurnNode` to sub-spans and into TurnTrace.
11. **No backwards compatibility** — `ModuleNode` is removed. Providers that depend on per-module spans must update. `TelemetryProvider.onTurnTrace(trace)` is required.

## Acceptance Criteria

- Every turn produces exactly one `TurnTrace` record.
- `TurnTrace` includes all fields defined in the Zod schema.
- `TurnTrace` schema validates at runtime (Zod parse succeeds for every emitted trace).
- No `ModuleNode` spans are created during turn execution.
- LLM/tool sub-spans are children of `TurnNode`, not children of removed `ModuleNode`s.
- Child dispatch creates a `ChildCallNode` under the parent `TurnNode`, and child `AgentNode` trees are linked through `parentTelemetryNodeId`.
- LLM/tool sub-spans carry `module` attribution (e.g., `'execution'`).
- `TurnTrace.childCalls[]` lists all child dispatches/completions/failures with linkage fields.
- `TurnTrace.timings` includes all seven module timings plus `totalMs`.
- `TurnTrace.usage` aggregates all LLM usage within the turn.
- `TurnTrace.llmCalls` and `TurnTrace.toolCalls` list all sub-calls with metadata.
- `TurnTrace.inboxCurrent` is a compact summary (source/kind/token), not raw payloads.
- `TurnTrace.pendingAfter` is a normalized summary, not raw transport wrappers.
- `TurnTrace.mentalStateBeforeHash` and `mentalStateAfterHash` use stable canonical hashing.
- Manifest provenance (`agentCardSource`, `runtimeManifestSource`, `agentCardHash`, `runtimeManifestHash`) is computed when the session is created, persisted in session/snapshot metadata, and restored on every turn-entry path; it is stamped on every TurnTrace.
- Hash is stable under whitespace and key order changes.
- Identity mismatch (Agent Card name/version vs Runtime Manifest name/version) fails fast before any turns.
- `correlationId`, `traceId`, `spanId` are populated on every TurnTrace.
- `ConsoleProvider` logs one compact line per turn via `onTurnTrace`.
- `OpikProvider` creates exactly one structured turn span with TurnTrace metadata via `onTurnTrace`.
- `TurnTraceCollector` accumulates traces per session; `runLoop` returns `traces` when `collectTraces: true`.
- `TurnTraceCollector` is treated as test/debug infrastructure, not durable session storage.
- TurnTrace emission failure does not fail the turn; logs a best-effort warning.
- No `as any` casts remain in `oneTurn.ts`, `loopRunner.ts`, `TelemetryNode.ts`, `TurnNode.ts`, `LLMNode.ts`, `ToolNode.ts`, `Provider.ts`, `TelemetryCollector.ts`, `ConsoleProvider.ts`, `OpikProvider.ts`, `CallagentBridgeProvider.ts`, `LLMCallerAdapter.ts`, `turnTrace.ts`, `manifestProvenance.ts`, `turnTraceHelpers.ts`, `TurnTraceCollector.ts`, `Tracing.ts`.
- `TelemetryNode.NodeType` includes `'child'` so `ChildCallNode` is a valid node type.
- `TelemetryProvider` is a `type` (not `interface`), consistent with project conventions.
- `TelemetryProvider.onTurnTrace(trace)` is required, and `onNodeEnd(TurnNode)` is not used as a second structured turn-export path.
- All new types are exported from `@a2arium/callagent-core`.
- `ChildCallNode` is exported from `@a2arium/callagent-core`.
- `ModuleNode` is deleted and removed from exports.
- All existing tests pass (updated as needed).
- All new tests pass.
- Migration guide `apps/docs/migration/3.5-turn-trace-telemetry-migration.md` is complete.
- Downstream docs are updated.
- `yarn test && yarn build` pass with zero errors.
