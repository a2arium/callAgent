# 4.1 `flow.md` standard — agent scaffolding tool

> **Internal implementation spec** for framework contributors and maintainers. **Author-facing spec:** [How-to: `flow.md` for APLRET agents](../13-flow_md_for_aplret_agents.md). **Migration:** [4.1 flow.md adoption](../migration/4.1-flow-md-adoption-migration.md).

---

## Problem

The framework has **no tooling** to scaffold a new agent. Authors must manually create `agent.ts`, `types.ts`, module files, manifest JSONs, `flow.md`, and test stubs from scratch — or copy-paste from the single `hello-agent` example (which itself does not follow canonical APLRET patterns: uses `any` casts, generic `{ kind: 'internal', intent: ... }` intents instead of domain-named closed unions, reads `env.inbox.all` instead of `env.inbox.current`, etc.).

Without scaffolding:

- New agents start with inconsistent structure.
- `flow.md` is omitted or malformed.
- Manifest files are missing or wrong.
- Types start loose (`any`, `Record<string, unknown>`) and never tighten.
- Tests are absent or do not follow the turn-script pattern.

The **primary deliverable** of this task is a **scaffold tool** that generates a canonical agent directory structure from presets, producing correctly typed files, valid manifests, `flow.md` stubs for non-trivial agents, and test stubs — so every new agent starts on the right foundation.

---

## Goals

1. **One command** to generate a new agent directory with all required files.
2. **Two presets**: `minimal` (simple one-turn agent) and `non-trivial` (multi-turn with awaits, branches, `flow.md`).
3. **Canonical patterns from day one**: closed unions, domain-named intents, proper module signatures, no `any`.
4. **Valid manifests**: `agent-card.json` and `agent-runtime.json` generated with correct structure and matching name/version.
5. **Test stubs**: generated test files using `createTestHarness` aligned with [doc 11](../11-how_to_test_aplret_agents.md).
6. **`flow.md` stub** (non-trivial preset): canonical section order per [doc 13](../13-flow_md_for_aplret_agents.md), with placeholder vocabulary and flow table.
7. **Strongly typed API**: the scaffold tool itself is schema-driven (Zod), no `any` in its public surface.

---

## Scope

### In scope

- **Programmatic API** exported from `@a2arium/callagent-core`: `scaffoldAgent(options)` function.
- **CLI entry point** at `packages/core/src/scaffold/scaffoldCli.ts` runnable via `yarn create-agent`.
- **Two presets** with generated file trees (see [Generated output](#generated-output) below).
- **Template content** for each generated file: typed stubs, not empty files.
- **`flow.md` generation** for non-trivial preset following [doc 13](../13-flow_md_for_aplret_agents.md) canonical format.
- **Manifest generation**: `agent-card.json` and `agent-runtime.json` with matching name/version.
- **Test file generation**: harness-based test stubs per [doc 11](../11-how_to_test_aplret_agents.md).
- **Refactor existing `hello-agent`** to use canonical APLRET patterns (closed unions, domain-named intents, `env.inbox.current`, no `any`) so it serves as a valid reference.
- **Reference non-trivial agent**: create or refactor one example agent under `apps/examples/` demonstrating the non-trivial layout with `flow.md`.
- **Documentation**: usage docs in this file, migration guide updates, cross-links from [4.0](./4.0-readability-phase-overview.md).

### Out of scope

- Changing APLRET runtime semantics (owned by contract + core loop).
- Replacing tests with static analysis of `flow.md`.
- Optional `flow.md` validators or CI linters (future work; document in this file when introduced).
- Backwards compatibility with the current `hello-agent` shape.
- Interactive/wizard-style CLI (simple flags are sufficient for v1).

### Relationship to task 4.2

This task **delivers the scaffold tool** (CLI + `scaffoldAgent` API) that [4.2](./4.2-agent-repository-layout-and-patterns.md) previously reserved under its **Tooling / API** placeholder. **4.2** keeps ownership of **reference agents**, layout examples, and “maintained non-trivial example” quality; **4.1** owns **generator implementation**, `flow.md` stub generation, and scaffold tests. ## No backwards compatibility

Per [4.0 §1](./4.0-readability-phase-overview.md): we do not preserve deprecated patterns. Specifically:

- The existing `hello-agent` example will be **rewritten** to follow canonical patterns. The old version is not preserved.
- If the scaffold tool introduces any changes to `createAgent` types or `Modules` signatures (e.g. tightening generic defaults, removing `any` from sugar paths), those changes ship **without** compatibility shims.
- Every breaking change ships with a migration doc in `apps/docs/migration/`.

## Design

### API surface

#### Programmatic API

```ts
import { scaffoldAgent, type ScaffoldOptions, type ScaffoldResult } from '@a2arium/callagent-core';

type AgentPreset = 'minimal' | 'non-trivial';

type ScaffoldOptions = {
  /** Logical agent id: kebab-case or snake_case, 1–64 chars; must match `^[a-z0-9]+(?:-[a-z0-9]+)*$` OR `^[a-z0-9]+(?:_[a-z0-9]+)*$` (enforced by `ScaffoldOptionsSchema`). Used in manifests and folder naming guidance. */
  name: string;
  preset: AgentPreset;
  /** Absolute or relative path; resolved against `process.cwd()` of the process running the CLI (not the framework package install dir). */
  outputDir: string;
  description?: string;
  usesLlm?: boolean;
  usesTools?: boolean;
  usesChildren?: boolean;
  usesPlans?: boolean;
  /** When true, allow writing into a non-empty `outputDir` (default: fail if directory exists and is non-empty). */
  force?: boolean;
};

type ScaffoldResult = {
  outputDir: string;
  preset: AgentPreset;
  filesCreated: string[];
};
```

`ScaffoldOptions` MUST be backed by a Zod schema (`ScaffoldOptionsSchema`) — the inferred type is the source of truth.

`scaffoldAgent` is an async function that:

1. Validates options via `ScaffoldOptionsSchema`.
2. Creates the output directory (fails if it already exists, unless `--force`).
3. Writes template files based on preset.
4. Returns a `ScaffoldResult` listing all created files.

#### CLI

```bash
yarn create-agent --name my-agent --preset minimal --output apps/examples/my-agent
yarn create-agent --name my-agent --preset non-trivial --output apps/examples/my-agent --uses-llm --uses-children
```

CLI maps 1:1 to `ScaffoldOptions` (including `--force` → `force: true`). Entry point: `packages/core/src/scaffold/scaffoldCli.ts`.

Root `package.json` adds:

```json
"create-agent": "node packages/core/dist/scaffold/scaffoldCli.js"
```

#### Downstream apps (consumers of `@a2arium/callagent-core`)

The scaffold must work **outside** the monorepo the same way other framework CLIs do (e.g. `agentsCli.js`, memory-sql `setup-database.cjs`).

**Requirements:**

1. **`packages/core/package.json`** declares a **`bin`** entry pointing at the compiled CLI (e.g. `"callagent-scaffold": "./dist/scaffold/scaffoldCli.js"` with a shebang `#!/usr/bin/env node`). Exact binary name is chosen at implementation time; document it in **Tooling / API** when shipped.
2. **Published package** includes `dist/scaffold/scaffoldCli.js` in `"files"` (already satisfied if `dist` is published wholesale).
3. **Author-facing migration / how-to** documents the **consumer `package.json` pattern**:

   ```json
   "create-agent": "node node_modules/@a2arium/callagent-core/dist/scaffold/scaffoldCli.js"
   ```

   Optional: **`npx @a2arium/callagent-core …`** if the package exposes a documented subcommand or the bin is registered on npm.

4. **`--output`** is always interpreted relative to **`process.cwd()`** of the invoking shell, never relative to the core package path.

### Generated output

#### Minimal preset

```txt
<name>/
  package.json          — workspace-friendly: name, type "module", deps on core/types, test script
  tsconfig.json         — strict; extends repo base where scaffold runs inside monorepo, or standalone minimal config for greenfield
  agent.ts              — createAgent wiring, typed generics, import.meta.url
  types.ts              — closed Sensory, Obs, Intent unions (domain-named)
  attention.ts          — minimal stub (required by Modules; may return `undefined` / empty signal per Alpha)
  perception.ts         — inbox.current routing, returns Obs
  learning.ts           — reducer-style updates; signature matches Modules.learning (incl. mem, writer)
  policy.ts             — sync, reads MentalState (+ MemoryReader per Modules.policy); returns Intent
  shield.ts             — pass-through stub (always generated for minimal)
  execution.ts          — effect boundary; signature matches Modules.execution (ctx, mem, m)
  transition.ts         — exhaustive switch; signature matches Modules.transition (incl. mem)
  agent-card.json       — valid A2A Agent Card with name/version
  agent-runtime.json    — valid runtime manifest matching card
  tests/
    golden.test.ts      — harness-based turn script for happy path
```

Optional files generated based on flags:

- `prompts.ts` — when `usesLlm: true`
- `contracts.ts` — when `usesLlm: true`

**Monorepo note:** If the output path is under an existing Yarn workspace (e.g. `apps/examples/<name>/`), the generated `package.json` MUST be consistent with root `workspaces` globs (name field, workspace deps as `workspace:*` where applicable). Implementation may offer a `--monorepo` flag or infer from `outputDir` under known roots; document the chosen behavior in **Tooling / API** when shipped.

#### Non-trivial preset

```txt
<name>/

  flow.md               — canonical sections per doc 13, placeholders filled from options
  types.ts              — closed unions: Sensory, Obs, Intent, ExecPayload, stages

  attention.ts
  perception.ts
  learning.ts
  policy.ts
  shield.ts
  execution.ts
  transition.ts

  selectors.ts          — readPolicyView stub
  reducers.ts           — reducer switch stub

  normalizers/
    user.ts
    tool.ts             — when usesTools
    child.ts            — when usesChildren
    internal.ts

  effects/
    llm/                — when usesLlm
      placeholder.ts
    tools/              — when usesTools
      placeholder.ts

  prompts/              — when usesLlm
    placeholder.ts

  contracts/
    llm/                — when usesLlm
      placeholder.schema.ts
    tools/              — when usesTools
      placeholder.schema.ts

  package.json          — same role as minimal preset (deps, scripts, workspace:* when applicable)
  tsconfig.json         — same role as minimal preset

  agent-card.json
  agent-runtime.json

  tests/
    golden.test.ts
    resume.test.ts      — await/resume test stub
    failure.test.ts     — failure path test stub
    invariant.test.ts   — invariant violation test stub
```

### Template content requirements

Every generated file MUST contain:

1. **Valid TypeScript** that compiles with strict mode.
2. **Correct imports** from `@a2arium/callagent-core` and `@a2arium/callagent-types`.
3. **Typed function signatures matching `Modules<…>` in `packages/core/src/loop/oneTurn.ts`** (authoritative for parameter lists and return types). The prose module contracts in [APLRET contracts](../0-aplret_contracts.md) describe behavior; **generated code must type-check against the real `Modules` type**, including:
   - `attention(prev, env, mem)`
   - `perception(env, alpha, mem)`
   - `learning(prev, prevAction, o, mem, writer, rPrev?)`
   - `policy(m, mem)` — second parameter is `MemoryReader` (Policy still must not read `env` / `ctx`; that is a behavioral rule, not “no second arg”)
   - `shield(m, intent, mem)`
   - `execution(intent, ctx, mem, m)`
   - `transition(env, exec, m, mem)`
4. **No `any`** — use `unknown`, closed unions, or the scaffold's domain types.
5. **Placeholder comments** indicating where the author should customize (e.g. `// TODO: Add your observation kinds here`).
6. **Domain-named intent examples** — not generic `{ kind: 'internal', intent: '...' }`.

#### `builders.ts` (explicitly omitted in v1)

Do **not** generate `builders.ts` in the non-trivial preset for v1. Optional observation / `ExecOutcome` builders belong in [4.3](./4.3-framework-readability-helpers-and-examples.md); once helpers ship, a **follow-up** may add an opt-in flag (e.g. `--with-builders`) or a new preset version. This avoids coupling scaffold output to speculative APIs.

#### `createAgent` generics vs [types-rules](./types-rules.md) Rule 3

Rule 3 says framework users should rarely write explicit generics. **`createAgent` today requires five type parameters** when wiring from a central `agent.ts` with separated modules. Templates will show `createAgent<Sensory, Obs, Alpha, ExecData, ExecError>(…)` (or equivalent) until a separate change improves inference.

**For this task:** document the tension in the migration / tutorial; **do not** block scaffold delivery on redesigning `createAgent`. Optionally track a follow-up (4.x) to infer generics from module values or a single `defineAgent({ … })` helper. Generated `types.ts` should minimize friction (export `ExecData` / `ExecError` aliases used in one place).

#### `types.ts` template (minimal preset example)

```ts
import type { MentalState } from '@a2arium/callagent-core';

export type Sensory = {
  latestUserText?: string;
};

export type Obs =
  | { kind: 'user_message'; text: string }
  | { kind: 'idle' };

export type Intent =
  | { kind: 'prompt_user'; prompt: string }
  | { kind: 'respond'; query: string }
  | { kind: 'complete'; result: unknown }
  | { kind: 'wait' };

export type ExecPayload = {
  replied?: boolean;
  text?: string;
  promptRequested?: boolean;
};

export type ExecError = {
  code: string;
  message: string;
};

export type M = MentalState<Sensory>;
```

#### Test template (golden.test.ts example)

`createTestHarness` accepts `Partial<Modules<…>>` (see `packages/core/src/testing/TestHarness.ts`). The harness runs `runLoop` internally; **generated tests must type-check** against the same module shapes as production wiring. Include **`attention`** when the agent defines it (minimal preset includes a stub).

```ts
import { createTestHarness } from '@a2arium/callagent-core';
import { attention } from '../attention.js';
import { perception } from '../perception.js';
import { learning } from '../learning.js';
import { policy } from '../policy.js';
import { shield } from '../shield.js';
import { execution } from '../execution.js';
import { transition } from '../transition.js';

describe('<name> — golden path', () => {
  it('completes the happy path', async () => {
    const harness = createTestHarness({
      attention,
      perception,
      learning,
      policy,
      shield,
      execution,
      transition,
    });

    // Align injectUserInput with how Perception reads user observations (string vs structured payload).
    harness.injectUserInput({ text: 'hello' });
    await harness.runTurn();

    // Prefer chainable assertions when using harness helpers (see [doc 11](../11-how_to_test_aplret_agents.md)):
    // await harness.expectTurn((t) => { ... }).runTurn();
    // Or use lastTrace() / allTraces() for TurnTrace field checks.
  });
});
```

**Verification task:** Before freezing templates, run a generated minimal agent through `tsc` and Jest in CI; adjust template imports (`.js` extensions for NodeNext), `HarnessConfig`, and stub LLM/tool registration if `usesLlm` / `usesTools` presets require it.

#### Manifest templates

`agent-card.json`:

```json
{
  "name": "<name>",
  "version": "0.1.0",
  "description": "<description or 'An APLRET agent'>",
  "url": "http://localhost:3000",
  "capabilities": {
    "streaming": false,
    "pushNotifications": false
  },
  "skills": []
}
```

`agent-runtime.json`:

```json
{
  "name": "<name>",
  "version": "0.1.0",
  "loop": {
    "budgets": {
      "maxTurns": 50,
      "maxLLMCalls": 20
    }
  },
  "turnTrace": {
    "enabled": true
  }
}
```

Name and version MUST match between `agent-card.json` and `agent-runtime.json` (per manifest identity invariant in [APLRET contracts](../0-aplret_contracts.md)).

## Type system requirements

Per [4.0](./4.0-readability-phase-overview.md) and [types-rules](./types-rules.md):

1. **No `any` in scaffold code or generated templates.** All template content must use `unknown`, closed unions, or explicit types.
2. **`ScaffoldOptions` uses Zod schema as source of truth** — `type ScaffoldOptions = z.infer<typeof ScaffoldOptionsSchema>`.
3. **Use `type` not `interface`** for all new exported shapes (project convention).
4. **Scaffold exports added to public API inventory** in [APLRET contracts](../0-aplret_contracts.md).
5. **`tsd` tests** for all new public exports (`scaffoldAgent`, `ScaffoldOptions`, `ScaffoldResult`, `ScaffoldOptionsSchema`, `AgentPreset`).
6. **Rule 11 (typed errors):** `scaffoldAgent` failures SHOULD use structured errors (e.g. validation `ZodError` from schema parse, or a small discriminated union `{ type: 'path_exists' | 'validation_failed'; … }`) rather than bare `Error` strings only — document the chosen shape in **Tooling / API** when shipped.

---

## Implementation constraints

1. **Template rendering**: use simple string interpolation (template literal functions), not a third-party template engine. Templates are TypeScript functions `(options: ScaffoldOptions) => string` — easy to test, no new dependencies.
2. **File system**: use `node:fs/promises`. The scaffold writes to the specified `outputDir`; it does not modify existing files elsewhere.
3. **No runtime dependency on scaffold in agents**: `scaffoldAgent` is a dev-time tool. Generated agents import only from `@a2arium/callagent-core` and `@a2arium/callagent-types`.
4. **Generated files are standalone**: a scaffolded agent directory includes **`package.json` and `tsconfig.json`** so it can compile and run tests after `yarn install` (or workspace install). Golden test should pass with harness stubs; no manual fixup before first **`yarn install && yarn test`** (or equivalent in the host monorepo).
5. **`hello-agent` fix**: The `hello-agent` package.json references `dist/AgentModule.js` as main, but the source file is `agent.ts`. Fix the build/entry mismatch as part of the rewrite.

## Tooling / API

**Shipped surface:**

- **Package:** `@a2arium/callagent-core`
- **Programmatic API:** `scaffoldAgent(options: ScaffoldOptions): Promise<ScaffoldResult>`
- **`bin`:** `callagent-scaffold` → `dist/scaffold/scaffoldCli.js`
- **Monorepo CLI:** `yarn create-agent --name <name> --preset <minimal|non-trivial> --output <dir> [--uses-llm] [--uses-tools] [--uses-children] [--uses-plans] [--description "<text>"] [--force] [--monorepo|--no-monorepo]`
- **Downstream:** `node node_modules/@a2arium/callagent-core/dist/scaffold/scaffoldCli.js …` (same flags)
- **`outputDir`:** resolved relative to **`process.cwd()`** of the invoking process
- **Presets:** `minimal` and `non-trivial`
- **Non-trivial generated tree (flag-gated):** `flow.md`, `selectors.ts`, `reducers.ts`, `normalizers/`, `effects/`, `prompts/`, `contracts/`, and non-trivial test stubs
- **Options schema:** `ScaffoldOptionsSchema` (Zod) — `name` (kebab or snake, length bounds), `preset`, flags, `force`, optional `monorepo`
- **Exports:** `scaffoldAgent`, `formatScaffoldError`, `ScaffoldOptions`, `ScaffoldResult`, `ScaffoldFailure`, `ScaffoldOptionsSchema`, `AgentPreset`
- **Errors:** structured failure shape (see [Type system requirements](#type-system-requirements))
