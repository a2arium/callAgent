# 2.1 ctx.vars / World Memory Bleed Specification

This document defines the normative specification for completely removing `ctx.vars` from the `callagent/packages/core` framework.

**REMEMBER: We do not support backwards compatibility.**
After these changes are implemented, full final migration instructions will be saved to `apps/docs/migration/2.1-ctx-vars-migration.md`.

---

## Problem Statement

The `ctx.vars` system actively proxies generic working memory directly into `MentalState.memory.vars` (via `VarsSync.assignVarsIntoMental`, `TurnRunner.ts`, and `TaskEngine.ts`).

This violates:
1. **Single Writer for Cognition**: Only `Learning` may mutate `MentalState`. `ctx.vars` allows any module to bypass Learning and write directly into cognition.
2. **Cognition vs Control Separation**: Control flags, pending state markers, and generic scratchpads must not live alongside explicit cognitive structures.
3. **types-rules.md Rule 1**: `vars: Record<string, unknown>` claims the type is a flat record but the runtime behavior (nested dot-path get/set, Map-like proxying) doesn't match.
4. **types-rules.md Rule 5**: The runtime vars object is typed as `any` in `VarsSync.createVarsProxy`'s return type — public API returning `any`.
5. **types-rules.md Rule 7**: Context mutations via `(ctx as any).vars` bypass the type system entirely — no type propagation.

## WorldModel Type Alignment

The APLRET contract defines:
```ts
worldModel?: Record<string, unknown>; // free-form beliefs bag
```

The current implementation in `loop/types.ts` (line 74–78) defines:
```ts
type WorldModel = {
    implicit: unknown | null;
    explicit: unknown | null;
    simulator: unknown | null;
};
```

**This must be changed.** The current struct prevents agents from storing arbitrary beliefs (e.g., `customerName: 'Alice'`), which is the primary migration target for `ctx.vars` cognitive state.

### Required Change

```diff
- export type WorldModel = {
-     implicit: unknown | null;
-     explicit: unknown | null;
-     simulator: unknown | null;
- };
+ export type WorldModel = Record<string, unknown>;
```

Update `initialM()` in `loop/init.ts`:
```diff
- worldModel: { implicit: null, explicit: null, simulator: null },
+ worldModel: {},
```

Update `MemoryWriter.world.set` to accept `WorldModel` (already compatible since `Record<string, unknown>` is a superset).

## ctx.world Facade Fix

`TaskEngine.ts` (line 3150) already creates a `ctx.world` facade:
```ts
ctx.world = {
    update: (fn) => fn(ctx.__mental.worldModel),
    patch: (p) => Object.assign(ctx.__mental.worldModel, p)
};
```

**Problem:** This allows any module to mutate `worldModel` directly — the same APLRET violation as `ctx.vars`.

**Required Change:** `ctx.world` must become **read-only** for all modules except Learning. Learning writes to `worldModel` via the `MemoryWriter.world.set()` interface.

```diff
- world?: { update: (fn: (wm: any) => void) => void; patch: (p: Record<string, unknown>) => void };
+ world?: { read: () => Readonly<WorldModel> };
```

The `ctx.world.patch()` and `ctx.world.update()` methods must be removed. Agents that previously used them must migrate to Learning (see Migration Strategies below).

## A2A Token Storage Replacement

`A2ACallOptions.setToken` and `tokenPath` currently reference storing tokens in `ctx.vars`. After deletion:

- Tokens MUST be stored in `env.pending.controlVars` (the control-plane surface).
- The `VarsSync.syncControlVarIntoActiveLoop()` method already does this correctly. This specific method should be **extracted and kept** (renamed to a control-plane utility), not deleted with the rest of `VarsSync`.
- Update `A2ACallOptions` JSDoc to reference `env.pending.controlVars` instead of `ctx.vars`.

## Specification (Target State)

1. **`ctx.vars` MUST NOT EXIST** — removed from types, runtime, and all orchestration code.
2. **Cognitive facts** (business state an agent remembers) → `MentalState.worldModel` via `Learning` + `MemoryWriter.world.set()`.
3. **Execution scratchpad** (ephemeral per-turn data) → `MentalState.memory.scratch` (Learning-owned, not persisted between sessions unless Learning decides).
4. **Control/stage marks** (tokens, stage flags) → `env.pending.controlVars` or `StageFacade`.
5. **A2A context transfer** → `ContextSerializer` serializes `worldModel` beliefs instead of flat vars.
6. **`ctx.world`** → read-only facade. Writes go through `Learning` only.

## Migration Strategies

Full migration guide will be created in `apps/docs/migration/2.1-ctx-vars-migration.md` post-implementation. Below are the canonical patterns.

### 1. Migrating Business State (Cognition) to worldModel

**Old:**
```ts
// Inside execution or anywhere
ctx.vars.set('customerName', 'Alice');

// Inside policy
const name = ctx.vars.get('customerName');
```

**New — Learning writes, Policy reads:**
```ts
// Learning module (the ONLY writer to MentalState)
learning: (prev, _prevAction, obs, _mem, writer) => {
  if (obs.kind === 'customer.identified') {
    const next = { ...prev };
    // Option A: direct MentalState return
    next.worldModel = { ...next.worldModel, customerName: obs.payload.name };
    return next;
    // Option B: use MemoryWriter (preferred for durable writes)
    // writer.world.set({ ...prev.worldModel, customerName: obs.payload.name });
    // return prev;  // writer applies patches after
  }
  return prev;
}

// Policy module (read-only from MentalState)
policy: (m, _mem) => {
  const name = (m.worldModel as Record<string, unknown>)?.customerName;
  // decide based on name...
}
```

### 2. Migrating Progress/Telemetry Flags

**Old:**
```ts
if (!ctx.vars.get('didSendUpdate')) {
  ctx.progress(50, 'Analyzing');
  ctx.vars.set('didSendUpdate', true);
}
```

**New:** Use `StageFacade` autoMarks (see `apps/docs/5-how_to_use_stage_facade_in_aplret.md`). Progress tracking is a control concern, not cognition — it belongs in stage invariants, not `worldModel`.

### 3. Migrating Retry Counters

**Old:**
```ts
ctx.vars.update('retryCount', (c) => (c || 0) + 1);
```

**New:** Track in `MentalState.memory.scratch` via Learning:
```ts
learning: (prev, _prevAction, obs, _mem, _writer) => {
  if (obs.kind === 'tool.completed' && obs.error) {
    const next = { ...prev, memory: { ...prev.memory } };
    const scratch = (next.memory.scratch || {}) as Record<string, unknown>;
    scratch.retryCount = ((scratch.retryCount as number) || 0) + 1;
    next.memory.scratch = scratch;
    return next;
  }
  return prev;
}
```

### 4. Migrating A2A Token Storage

**Old:**
```ts
ctx.sendTaskToAgent('child', input, { setToken: true, tokenPath: 'child.token' });
// later: ctx.vars.get('child.token')
```

**New:** Tokens are stored in `env.pending.controlVars`:
```ts
// In Execution — token is auto-stored in env.pending.controlVars
ctx.sendTaskToAgent('child', input, { setToken: true, tokenPath: 'child.token' });

// In Policy — read from env.control, not ctx.vars
policy: (m, _mem) => {
  // Token is available via env.pending.controlVars['child.token']
  // (passed to policy via the env parameter if needed)
}
```

### 5. Code Compilation

After this change, any agent compiling against the new core framework will receive TypeScript compilation errors at every `ctx.vars` usage. Each must be manually routed through the `Observation → Learning → MentalState` pipeline as shown above.
