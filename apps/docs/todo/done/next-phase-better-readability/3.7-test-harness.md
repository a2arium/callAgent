# 3.7 Official APLRET Test Harness

> **Internal implementation spec.** This document is for implementers (framework contributors and maintainers). It describes file-level changes, type redesigns, and acceptance criteria.
> **For framework users migrating their agent tests**, see the end-user migration guide: **[apps/docs/migration/3.7-test-harness-migration.md](../migration/3.7-test-harness-migration.md)** (to be created as part of this task).

**Scope:** This document defines the development requirements for the official APLRET test harness — a framework-provided, deterministic, turn-by-turn testing API. It covers: the `createTestHarness` factory function, Zod-backed configuration schemas, typed assertion helpers bound to `TurnTrace`, deterministic LLM/Tool/Child stubs, `TaskContext` construction for test environments, and deprecation of manual `runLoop`/`oneTurn` invocations in tests. Test harness helpers deferred from 3.4 (`expectStage`, `seedControlState`, `expectStageTransition`) are **in scope** for this task.

---

## Problem Statement

When testing agents locally or in CI, developers currently instantiate `TaskEngine` or run `runLoop`/`oneTurn` directly. This leads to several anti-patterns that violate framework contracts and type safety rules.

## 🏗 Requirements

### 1. Define Zod-backed configuration schemas

**Rule enforcement: Rule 2 (Schemas Are Source of Truth), Rule 5 (No `any`), Rule 4 (Illegal States Must Not Compile)**

File: `packages/core/src/testing/harnessTypes.ts` **(NEW)**

All harness types must be Zod-first with inferred TypeScript types. The harness accepts `Modules` (the actual framework type from `oneTurn.ts`), not a phantom `APLRETAgent` type.

```typescript
import { z } from 'zod';
import type { Modules, TransitionOut, ShieldOutcome } from '../loop/oneTurn.js';
import type { Intent } from '../types/intent.js';
import type { MentalState, EnvironmentState } from '../loop/types.js';
import type { Observation } from '../types/observation.js';
import type { TurnTrace } from '../types/turnTrace.js';
import type { ManifestProvenance } from '../types/turnTrace.js';
import type { ILLMCaller } from '../shared/types/LLMTypes.js';

// --- DeepPartial utility ---
export type DeepPartial<T> = T extends object
    ? { [P in keyof T]?: DeepPartial<T[P]> }
    : T;

// --- Harness configuration ---
export const HarnessConfigSchema = z.object({
    deterministicTime: z.boolean().default(true),
    seedTokens: z.boolean().default(true),
    manifestProvenance: z.custom<ManifestProvenance>().optional(),
    maxTurns: z.number().int().positive().default(1),
}).strict();

export type HarnessConfig = z.infer<typeof HarnessConfigSchema>;

// --- Deterministic LLM stub config ---
export const LLMStubResponseSchema = z.object({
    content: z.string(),
    role: z.string().default('assistant'),
    contentObject: z.unknown().optional(),
}).strict();

export type LLMStubResponse = z.infer<typeof LLMStubResponseSchema>;

// --- Harness internal state (not Zod — runtime-only) ---
export type HarnessState<Sensory = unknown> = {
    m: MentalState<Sensory>;
    env: EnvironmentState;
    traces: TurnTrace[];
    replies: unknown[];
    errors: Error[];
    turnCount: number;
};

// --- Turn assertion context ---
export type TurnAssertionContext = {
    trace: TurnTrace;
    expectIntent(kind: Intent['kind']): TurnAssertionContext;
    expectShield(action: ShieldOutcome['action']): TurnAssertionContext;
    expectTransition(kind: TransitionOut['kind']): TurnAssertionContext;
    expectAwaitToken(token: string): TurnAssertionContext;
    expectStageTransition(from: string, to: string): TurnAssertionContext;
    expectStageBefore(stage: string): TurnAssertionContext;
    expectStageAfter(stage: string): TurnAssertionContext;
    expectInboxKinds(kinds: string[]): TurnAssertionContext;
    expectMemoryChanged(): TurnAssertionContext;
};
```

> [!IMPORTANT]
> **Rule 4 compliance:** Assertion helpers use `Intent['kind']`, `ShieldOutcome['action']`, and `TransitionOut['kind']` — typed unions from the framework, not `string`. Typos in assertion arguments will fail at compile time.

### 2. Implement `createTestHarness` factory function

**Rule enforcement: Rule 3 (Prefer Type Inference), Rule 1 (Types Reflect Runtime), Rule 6 (APIs Guide Autocomplete)**

File: `packages/core/src/testing/TestHarness.ts` **(NEW)**

**Design decision — execution strategy:** The harness calls `runLoop()` with `maxTurns: 1` and `collectTraces: true`. This is preferred over calling `oneTurn` directly because:
- `runLoop` constructs `MemoryReader` and `MemoryWriter` internally — no need to replicate
- `runLoop` builds `TurnTrace` and pushes to `TurnTraceCollector` — the harness wraps this
- `runLoop` enforces transition invariants (await tokens, terminal state checks)
- `runLoop` manages `env.turn` counter and `env.control` updates

For multi-turn, the harness calls `runLoop` with `maxTurns: 1` repeatedly, allowing observation injection between turns.

```typescript
import type { Modules, TransitionOut, ShieldOutcome } from '../loop/oneTurn.js';
import type { Intent } from '../types/intent.js';
import type { Observation } from '../types/observation.js';
import type { MentalState, EnvironmentState } from '../loop/types.js';
import type { TaskContext } from '../shared/types/index.js';
import type { TurnTrace } from '../types/turnTrace.js';
import { runLoop } from '../loop/loopRunner.js';
import { initialM } from '../loop/init.js';
import { normalizeObservationInbox } from '../loop/types.js';
import { HarnessConfigSchema, type HarnessConfig, type HarnessState,
         type DeepPartial, type TurnAssertionContext } from './harnessTypes.js';
import { createDeterministicLLMStub, type DeterministicLLMStub } from './DeterministicStubs.js';
import { createTestContext } from './TestContext.js';

export type TestHarness<Sensory = unknown> = {
    // --- Seeding ---
    seedMentalState(m: DeepPartial<MentalState<Sensory>>): TestHarness<Sensory>;
    seedPending(pending: Partial<EnvironmentState['pending']>): TestHarness<Sensory>;
    seedControlVars(vars: Record<string, unknown>): TestHarness<Sensory>;

    // --- Injection ---
    injectObservation(obs: Observation): TestHarness<Sensory>;
    injectUserInput(value: unknown): TestHarness<Sensory>;
    injectToolCompleted(params: { token: string; tool: string; result?: unknown }): TestHarness<Sensory>;
    injectToolFailed(params: { token: string; tool: string; error?: unknown }): TestHarness<Sensory>;
    injectChildCompleted(params: { token: string; agentId: string; result?: unknown }): TestHarness<Sensory>;
    injectChildFailed(params: { token: string; agentId: string; error?: unknown }): TestHarness<Sensory>;

    // --- Execution ---
    runTurn(): Promise<TestHarness<Sensory>>;

    // --- Assertions (last turn) ---
    expectTurn(fn: (t: TurnAssertionContext) => void): TestHarness<Sensory>;
    expectComplete(): TestHarness<Sensory>;
    expectFail(): TestHarness<Sensory>;
    expectInvariantError(fn: (e: import('../utils/errors.js').InvariantError) => void): TestHarness<Sensory>;
    expectModuleError(fn: (e: import('../utils/errors.js').ModuleExecutionError) => void): TestHarness<Sensory>;

    // --- Accessors ---
    lastTrace(): TurnTrace;
    lastAwaitToken(): string;
    allTraces(): readonly TurnTrace[];
    currentM(): Readonly<MentalState<Sensory>>;
    replies(): readonly unknown[];
    llmStub(): DeterministicLLMStub;
};

export function createTestHarness<
    Sensory = unknown,
    Obs = unknown,
    Alpha = unknown,
    ExecData = unknown,
    ExecError extends import('../loop/oneTurn.js').ExecErrorPayload
        = import('../loop/oneTurn.js').ExecErrorPayload
>(
    modules: Partial<Modules<Sensory, Obs, Alpha, ExecData, ExecError>>,
    config?: Partial<HarnessConfig>
): TestHarness<Sensory>;
```

> [!NOTE]
> **`createTestHarness` infers generics from `modules`.** The user passes their agent's modules directly — the same object from `createAgent({ attention, perception, learning, ... })`. No need to spell out `<MySensory, MyObs, ...>` manually (Rule 3).

### 3. Implement `TaskContext` construction for tests

**Rule enforcement: Rule 1 (Types Reflect Runtime), Rule 5 (No `any`)**

File: `packages/core/src/testing/TestContext.ts` **(NEW)**

The harness must construct a complete `TaskContext` without `as any`. This module provides `createTestContext()` which builds a fully-typed `TaskContext` with:

| TaskContext field | Harness behavior |
|-------------------|-----------------|
| `task` | `{ id: 'test-task-<counter>', input: {} }` |

| `agentId` | `'test-agent'` |

| `progress` | No-op |
| `complete` | No-op |
| `fail` | Captures error into `state.errors[]` |

| `tools` | Deterministic tool stub — returns queued responses |

### 4. Create deterministic LLM/Tool stubs

**Rule enforcement: Rule 5 (No `any`), Rule 2 (Schemas as Source of Truth)**

File: `packages/core/src/testing/DeterministicStubs.ts` **(NEW)**

#### `DeterministicLLMStub`

Implements `ILLMCaller` exactly. The stub maintains a queue of responses; each `call()` dequeues the next response. If the queue is empty, returns a default response.

```typescript
import type { ILLMCaller, LLMMessage } from '../shared/types/LLMTypes.js';
import type { LLMCallOptions, LLMSettings } from '../types/llmContracts.js';
import type { UniversalChatResponse, UniversalStreamResponse } from 'callllm';

export type DeterministicLLMStub = ILLMCaller & {
    /** Queue a response for the next call() invocation */
    enqueue<T = unknown>(response: UniversalChatResponse<T> | string): void;
    /** Queue multiple responses */
    enqueueMany<T = unknown>(responses: Array<UniversalChatResponse<T> | string>): void;
    /** Get all calls made to this stub */
    getCalls(): ReadonlyArray<{ message: LLMMessage; options?: LLMCallOptions }>;
    /** Reset the stub (clear queue and call history) */
    reset(): void;
};

export function createDeterministicLLMStub(): DeterministicLLMStub;
```

Method signatures must exactly match `ILLMCaller`:
- `call<T>(message: LLMMessage, options?: LLMCallOptions): Promise<UniversalChatResponse<T>[]>`
- `stream<T>(message: LLMMessage, options?: LLMCallOptions): AsyncIterable<UniversalStreamResponse<T>>`
- `addToolResult(id: string, result: string, name: string): void`
- `updateSettings(settings: LLMSettings): void`

#### `DeterministicToolStub`

```typescript
export type DeterministicToolStub = {
    register(toolName: string, result: unknown): void;
    invoke<T = unknown>(toolName: string, args: unknown): Promise<T>;
    getCalls(): ReadonlyArray<{ tool: string; args: unknown }>;
    reset(): void;
};

export function createDeterministicToolStub(): DeterministicToolStub;
```

### 5. Implement `TurnAssertionContext`

**Rule enforcement: Rule 4 (Illegal States Must Not Compile), Rule 6 (APIs Guide Autocomplete)**

File: `packages/core/src/testing/HarnessAssertions.ts` **(NEW)**

The `TurnAssertionContext` wraps a single `TurnTrace` and provides typed assertion methods. Each method throws a descriptive `HarnessAssertionError` (not a generic `Error`) on mismatch, showing expected vs actual values.

```typescript
export class HarnessAssertionError extends Error {
    constructor(
        public readonly field: string,
        public readonly expected: unknown,
        public readonly actual: unknown,
        public readonly turn: number
    ) {
        super(`Turn ${turn}: expected ${field} to be ${JSON.stringify(expected)}, got ${JSON.stringify(actual)}`);
        this.name = 'HarnessAssertionError';
    }
}
```

Key implementation details:

- `expectIntent(kind)` checks `trace.intent?.kind === kind`
- `expectShield(action)` checks `trace.shield?.action === action`
- `expectTransition(kind)` checks `trace.transition?.kind === kind`
- `expectAwaitToken(token)` checks `trace.transition?.token === token`
- `expectStageTransition(from, to)` checks `trace.stageTransition?.from === from && trace.stageTransition?.to === to`
- `expectStageBefore(stage)` checks `trace.stageBefore === stage`
- `expectStageAfter(stage)` checks `trace.stageAfter === stage`
- `expectInboxKinds(kinds)` checks `trace.inboxCurrent.map(o => o.kind)` contains all expected kinds
- `expectMemoryChanged()` checks `trace.mentalStateBeforeHash !== trace.mentalStateAfterHash`

All assertion methods return `this` for chaining.

### 6. Handle observation normalization

**Design decision:** The harness validates injected observations through `normalizeObservationInbox()` by default. This ensures tests catch invalid observation shapes. An escape hatch `injectRawObservation(obs)` bypasses validation for testing edge cases (malformed observations).

### 8. Clean API Constraints

These constraints MUST hold after implementation:

1. **No backwards compatibility** — manual `runLoop`/`oneTurn` test patterns are deprecated. The harness is the canonical testing API.
2. **No `any` in public APIs** (Rule 5) — every file in `packages/core/src/testing/` must have zero `any`. The harness constructs `TaskContext` without `as any`.
3. **Zod-first schemas** (Rule 2) — `HarnessConfigSchema`, `LLMStubResponseSchema` are Zod schemas with inferred types.
4. **Typed assertion arguments** (Rule 4) — assertion helpers use `Intent['kind']`, `ShieldOutcome['action']`, `TransitionOut['kind']`, not `string`.
5. **Factory function** (Rule 3) — `createTestHarness(modules)` infers generics from modules. No class constructor.
6. **Aligned with doc 11** — the API matches the recommended shape in `11-how_to_test_aplret_agents.md` (`createHarness`, `expectTurn`, `lastAwaitToken`, `expectComplete`, `expectModuleError`, `expectInvariantError`).

## 📜 Mandatory Migration Guide

**File: `apps/docs/migration/3.7-test-harness-migration.md`** **(NEW)**

The migration guide must include:

1. **Overview**: The framework now provides `createTestHarness()` as the canonical way to test APLRET agents. Direct `runLoop`/`oneTurn` invocations in tests are deprecated.

2. **Before/After — state seeding**:
    ```typescript
    // Before (as any)
    const ctx: any = { task: { id: 't', input: 'hello' }, reply: jest.fn() };
    const M: any = initialM(ctx);
    M.memory.longTerm.semantic.concepts = [{ id: 'old', data: { x: 1 } } as any];
    const env = baseEnv({ inbox: undefined as any });

    // After (typed)
    const h = createTestHarness(modules)
        .seedMentalState({ memory: { longTerm: { semantic: { concepts: [{ id: 'old', data: { x: 1 } }] } } } });
    ```

3. **Before/After — running turns**:
    ```typescript
    // Before
    const result = await runLoop(ctx, M, env, modules);
    expect(result.outcome.kind).toBe('await_input');

    // After
    await h.injectUserInput('hello').runTurn();
    h.expectTurn(t => t.expectTransition('await_input'));
    ```

4. **Before/After — assertions**: Migrate from raw JSON paths to typed helpers.
