# Spec: Consolidate `ctx.semantic` into `ctx.memory.semantic`

## Summary

The `TaskContext` object currently exposes **two** separate ways to access the semantic memory service:

1. **`ctx.semantic`** — a convenience facade with `add / read / remove` methods, constructed in `taskEngine.restoreCtx`.
2. **`ctx.memory.semantic`** — the raw `SemanticMemoryBackend` registry with `set / get / delete / read / remove` methods.

Both are backed by the same PostgreSQL adapter. The `ctx.semantic` facade is an inline wrapper that translates `add/read/remove` into calls on `ctx.memory.semantic`. This means **two distinct interfaces, same data, same backend** — a design smell that creates confusion and violates the principle that the `ctx.memory` service layer is the single access point for storage.

**This spec defines the change:** Remove `ctx.semantic` entirely. Upgrade `ctx.memory.semantic` to expose the modern `add / read / remove` interface directly alongside the existing low-level methods. A single surface, clean contract.

---

## No Backwards Compatibility

This is a breaking change. The migration guide below must be written to `apps/docs/migration/2.6-ctx-memory-semantic-migration.md` as part of this implementation.

## Migration Guide — `ctx.semantic` → `ctx.memory.semantic`

> Written to: `apps/docs/migration/2.6-ctx-memory-semantic-migration.md`

### What Changed

The top-level `ctx.semantic` shortcut has been **removed** from `TaskContext`.

All semantic memory operations are now accessed through **`ctx.memory.semantic`**, which exposes both the modern agent API (`add`, `readItems`, `removeItem`) and the low-level adapter methods.

### Why

Having two surfaces (`ctx.semantic` and `ctx.memory.semantic`) backed by the same database was a design smell. It split the mental model and created a naming collision. There is now one place: `ctx.memory.semantic`.

### Migration Steps

#### Writing (add)

```ts
// Before
await ctx.semantic.add({ id: 'user:prefs', value: { theme: 'dark' }, tags: ['prefs'] });

// After
await ctx.memory.semantic.add({ id: 'user:prefs', value: { theme: 'dark' }, tags: ['prefs'] });
```

#### Reading by tag / filter

```ts
// Before
const results = await ctx.semantic.read({ tag: 'prefs' });

// After
const results = await ctx.memory.semantic.readItems({ tag: 'prefs' });
```

#### Reading by ID

```ts
// Before
const results = await ctx.semantic.read({ id: 'user:prefs' });

// After
const results = await ctx.memory.semantic.readItems({ id: 'user:prefs' });
```

#### Removing by ID

```ts
// Before
await ctx.semantic.remove('user:prefs');

// After
await ctx.memory.semantic.removeItem('user:prefs');
```

#### Removing by tag / filter

```ts
// Before
await ctx.semantic.remove({ tag: 'temporary' });

// After
await ctx.memory.semantic.removeItem({ tag: 'temporary' });
```

#### Removing by predicate (function)

```ts
// Before
await ctx.semantic.remove((item) => item.id.startsWith('tmp:'));

// After
await ctx.memory.semantic.removeItem((item) => item.id.startsWith('tmp:'));
```

### Type Changes

| Old type | Status | Replacement |
|---|---|---|
| `TaskContext.semantic` | **Removed** | Use `TaskContext.memory.semantic` |
| `SemanticAddInput.entities: Record<string, unknown>` | **Fixed** | Now `Record<string, string>` to match adapter |
| `SemanticRemoveFilter` | **New export** | Use for object-based remove filters |
| `SemanticPredicateFilter` | **New export** | Use for predicate-function removes |

## Current State (Before Change)

### `packages/types/src/IMemory.ts`
`SemanticMemoryBackend` exposes:
- `get<T>(key, opts?): Promise<T | null>`
- `set<T>(key, value, opts?): Promise<void>`
- `delete(key, opts?): Promise<void>`
- `read<T>(input, options?): Promise<MemoryQueryResult<T>[]>`
- `remove(input, options?): Promise<number>`
- `recognize<T>(...)`
- `enrich<T>(...)`

`IMemory.semantic` is typed as `MemoryRegistry<SemanticMemoryBackend>`.

### `packages/core/src/shared/types/index.ts`
`TaskContext.semantic` is typed as:
```ts
semantic?: {
    add: (item: SemanticAddInput) => Promise<void> | void;
    read: (filter?: SemanticReadFilter) => Promise<SemanticItem[]> | SemanticItem[];
    remove: (idOrPredicate: string | ((item: SemanticItem) => boolean)) => Promise<void> | void;
};
```

`TaskContext.memory` is typed as:
```ts
memory: IMemory & {
    mlo?: unknown;
    semantic?: unknown;  // ← weakly typed placeholder
    episodic?: unknown;
    embed?: unknown;
};
```

### `packages/core/src/orchestration/taskEngine.ts`
In `restoreCtx()`, `ctx.semantic` is constructed **at runtime** as a factory closure that calls `ctx.memory.semantic.set/get/delete/read/remove`. The types are cast with `any`, and the facade item `SemanticAddInput` has `entities: Record<string, unknown>` while the underlying `MemorySetOptions.entities` is `Record<string, string>` (a latent type mismatch).

## Proposed Changes

### 1. `packages/types/src/IMemory.ts`
**[MODIFY]** Extend `SemanticMemoryBackend` with the modern facade methods.

```ts
export type SemanticMemoryBackend = {
    // Low-level key-based operations (remain unchanged for internal use)
    get<T>(key: string, opts?: { backend?: string }): Promise<T | null>;
    set<T>(key: string, value: T, opts?: MemorySetOptions): Promise<void>;
    delete(key: string, opts?: { backend?: string }): Promise<void>;

    // Query / bulk operations (unchanged)
    read<T>(input: GetManyInput, options?: GetManyOptions): Promise<Array<MemoryQueryResult<T>>>;
    remove(input: GetManyInput, options?: GetManyOptions): Promise<number>;

    // Advanced (unchanged)
    recognize<T>(candidateData: T, options?: RecognitionOptions): Promise<RecognitionResult<T>>;
    enrich<T>(key: string, additionalData: T[], options?: EnrichmentOptions): Promise<EnrichmentResult<T>>;
    entities?: { ... }; // unchanged

    // NEW: Modern facade methods (matching SemanticFacade interface exactly)
    add(item: SemanticAddInput): Promise<void>;
    readItems(filter?: SemanticReadFilter): Promise<SemanticItem[]>;
    removeItem(idOrFilter: string | SemanticRemoveFilter | SemanticPredicateFilter): Promise<void>;
};
```

> **Note on naming:** We cannot name the new high-level methods `read` or `remove` as those names are already taken by the low-level batch adapter methods with incompatible signatures. The chosen names are `add`, `readItems`, and `removeItem`. The docs will refer to these three as the **"agent API"** of semantic memory. The low-level `set/get/delete/read/remove` are **"adapter API"** for infrastructure use only and will be documented as such.

### 2. `packages/core/src/shared/types/index.ts`
**[MODIFY]** Multiple changes:

#### 2a. Remove `ctx.semantic` from `TaskContext`
Delete the entire `semantic?` block (lines ~204-209).

#### 2b. Fix `TaskContext.memory` typing
Replace the weak `semantic?: unknown` placeholder with the proper `MemoryRegistry<SemanticMemoryBackend>` type:
```ts
memory: IMemory;  // IMemory already has semantic: MemoryRegistry<SemanticMemoryBackend>
```
The extra `mlo?/semantic?/episodic?/embed?` placeholder fields on `TaskContext.memory` were added as temporary stubs. Remove them. `IMemory` is already correct.

#### 2c. Define `SemanticRemoveFilter` and `SemanticPredicateFilter` types
These types are needed by the new `removeItem` signature to avoid `any`:
```ts
export type SemanticRemoveFilter = {
    tag?: string;
    filters?: SemanticReadFilter['filters'];
    limit?: number;
};

export type SemanticPredicateFilter = (item: SemanticItem) => boolean;
```

#### 2d. Fix entity type mismatch in `SemanticAddInput`
The current `SemanticAddInput.entities` is typed `Record<string, unknown>` but the underlying `MemorySetOptions.entities` is `Record<string, string>`. Align:
```ts
export type SemanticAddInput = {
    id: string;
    value: unknown;
    tags?: string[];
    entities?: Record<string, string>;  // was Record<string, unknown>
    backend?: string;
};
```

### 3. `packages/types/src/IMemory.ts` — Import types from core
`SemanticAddInput`, `SemanticReadFilter`, `SemanticItem`, `SemanticRemoveFilter`, and `SemanticPredicateFilter` need to be importable by the `types` package. However, since `@a2arium/callagent-types` is a dependency of `@a2arium/callagent-core` (not the reverse), these types must either:
- Live in `@a2arium/callagent-types` (preferred — keeps types self-contained), OR
- Be defined in a shared contract package.

**Decision:** Move `SemanticAddInput`, `SemanticReadFilter`, `SemanticItem`, `SemanticRemoveFilter`, and `SemanticPredicateFilter` from `packages/core/src/shared/types/index.ts` to `packages/types/src/IMemory.ts`. Re-export them from `packages/core/src/shared/types/index.ts` for backwards compat with the public API surface.

### 4. Implement default `add`, `readItems`, `removeItem` on the real adapter

**[MODIFY] `packages/memory-sql/src/...` (or `packages/memory-engine/src/createMemoryRegistry.ts`)**

The methods need a concrete implementation in the actual backend class. The implementation logic is the same as the current `taskEngine.restoreCtx` facade code. Extract it from `taskEngine.ts` into the registry's factory:

```ts
// Inside createMemoryRegistry (or the SemanticMemoryAdapter class)
add: async (item: SemanticAddInput): Promise<void> => {
    await adapter.set(item.id, item.value, { tags: item.tags, entities: item.entities });
},

readItems: async (filter?: SemanticReadFilter): Promise<SemanticItem[]> => {
    if (filter?.id) {
        const ids = Array.isArray(filter.id) ? filter.id : [filter.id];
        const results: SemanticItem[] = [];
        for (const id of ids) {
            const val = await adapter.get<unknown>(id);
            if (val !== null && val !== undefined) {
                results.push({ id, value: val });
            }
        }
        return typeof filter.limit === 'number' ? results.slice(0, filter.limit) : results;
    }
    const query: GetManyQuery = {};
    if (filter?.tag) query.tag = filter.tag;
    if (filter?.tags && !filter.tag) {
        // multi-tag: fetch unfiltered then apply JS filter
    }
    if (filter?.filters) query.filters = filter.filters;
    if (filter?.limit) query.limit = filter.limit;
    const raw = await adapter.read<unknown>(Object.keys(query).length > 0 ? query : '*');
    return raw.map(x => ({ id: x.key, value: x.value, tags: (x as any).tags }));
},

removeItem: async (idOrFilter: string | SemanticRemoveFilter | SemanticPredicateFilter): Promise<void> => {
    if (typeof idOrFilter === 'string') {
        await adapter.delete(idOrFilter);
        return;
    }
    if (typeof idOrFilter === 'function') {
        const all = await adapter.read<unknown>('*');
        for (const item of all) {
            const mapped: SemanticItem = { id: item.key, value: item.value };
            if (idOrFilter(mapped)) await adapter.delete(item.key);
        }
        return;
    }
    const q: GetManyQuery = {};
    if (idOrFilter.tag) q.tag = idOrFilter.tag;
    if (idOrFilter.filters) q.filters = idOrFilter.filters;
    if (Object.keys(q).length > 0) {
        await adapter.remove(q);
    }
},
```
