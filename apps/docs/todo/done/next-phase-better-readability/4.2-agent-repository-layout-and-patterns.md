> **Historical plan; superseded for new project creation (2026-08-13).** Use
> `callagent create agent-project` and `callagent create agent` for new work.
> See the [current migration guide](../../../migration/callagent-cli-workspace-distribution.md).

> **Internal implementation spec** for framework contributors and maintainers. **Author guide:** [How-to: Agent repository layout](../14-agent_repository_layout_for_aplret.md). **Migration:** [4.2 repo layout](../migration/4.2-agent-repo-layout-migration.md).

---

## Problem

Authors need scaffolds and examples that default to the canonical APLRET repository shape:

- `types.ts` first (closed unions)
- `normalizers/` for source-specific input decoding
- `selectors.ts` + `reducers.ts`
- split effect surfaces (`effects/`, `prompts/`, `contracts/`) when non-trivial
- `flow.md` for branch/await semantics

Without this, new agents regress to flat files, mixed concerns, and inconsistent style that spreads through copy-paste and AI-assisted generation.

## Design requirements

### 1) Reference agent requirements (non-trivial baseline)

At least one maintained non-trivial reference agent MUST satisfy all:

- `flow.md` with branch IDs and await/resume semantics
- closed unions in `types.ts`
- `selectors.ts` used by Policy
- `reducers.ts` used by Learning
- per-source `normalizers/` (minimum `user.ts`; add `tool.ts`/`child.ts` when relevant)
- named effect handlers under `effects/`
- prompt builders/content under `prompts/` when LLM paths are non-trivial
- schema contracts under `contracts/` for structured LLM/tool IO
- tests: `golden`, `resume`, and at least one of `failure`/`invariant`

### 2) Scaffold expectations for 4.2

`create-agent` remains the entry path for new repos, but this task must explicitly document one of:

- **Option A (preferred):** extend `non-trivial` preset to emit `effects/`, `prompts/`, `contracts/` skeletons, OR
- **Option B:** keep generator lean and document explicit post-scaffold steps to reach full doc 14 layout.

Whichever option is chosen MUST be documented in this file under **Tooling / API** and linked from tutorial/migration docs.

#### Required decision record (no ambiguity)

Before 4.2 is marked complete, maintainers MUST record a single explicit decision in this file:

- **Chosen mode:** `A` (generator emits full non-trivial split) or `B` (generator emits canonical subset + documented refactor steps).
- **Why this mode now:** short rationale (scope, maintenance cost, adoption speed).
- **Planned follow-up (if mode B):** concrete next task/file that closes the gap.

“Implicit subset” is not allowed. If mode B is chosen, the subset must be treated as an intentional public behavior with migration/docs alignment.

**Recorded decision (current):**

- **Chosen mode:** `A` (generator emits full non-trivial split, including `effects/`, `prompts/`, `contracts/` placeholders when relevant flags are enabled).
- **Why now:** aligns scaffold output with doc 14’s non-trivial shape and reduces manual follow-up steps for new agents.

### 3) Public API / typing constraints

- No `any` in new public surfaces.
- Schema-first (`zod`) for new structured config surfaces.
- New or changed exported symbols must be reflected in:
  - [APLRET contracts public API inventory](../0-aplret_contracts.md)
  - type tests (`tsd`) where applicable.

## Tooling / API (shipped)

### CLI

```bash
yarn create-agent --name <name> --preset <minimal|non-trivial> --output <path> [flags]
```

Published bin:

```bash
callagent-scaffold --name <name> --preset <minimal|non-trivial> --output <path> [flags]
```

Core flags:

- `--description`
- `--uses-llm`
- `--uses-tools`
- `--uses-children`
- `--uses-plans`
- `--force`
- `--monorepo` / `--no-monorepo`

### Programmatic API

From `@a2arium/callagent-core`:

- `scaffoldAgent(options)`
- `formatScaffoldError(error)`
- `ScaffoldOptionsSchema`
- `ScaffoldOptions`, `ScaffoldResult`, `ScaffoldFailure`, `AgentPreset`

### Presets and layout mapping

- `minimal`: canonical small agent module set + manifests + golden test.
- `non-trivial`: adds `flow.md`, `selectors.ts`, `reducers.ts`, `normalizers/`, and non-trivial test stubs.
- `non-trivial` conditional structure:
  - `effects/llm`, `prompts/`, `contracts/llm` when `--uses-llm`
  - `effects/tools`, `contracts/tools` when `--uses-tools`
  - `normalizers/tool.ts` when `--uses-tools`
  - `normalizers/child.ts` when `--uses-children`

Current expected mapping MUST stay explicit:

- **Generated now:** `flow.md`, `selectors.ts`, `reducers.ts`, `normalizers/`, `effects/`, `prompts/`, `contracts/` (flag-gated), module files, manifests, tests.
- **Author follow-up:** replace placeholders in generated `effects/`, `prompts/`, and `contracts/` with real domain handlers/contracts.
