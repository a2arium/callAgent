## When to implement

Implement this package when a concrete deployment needs Kafka (existing clusters, compliance, org standard) and the same typed ports (`IEventBus`, `MessageLog`, `DurableSubscription`) must back Kafka instead of or in addition to NATS JetStream.

## Integration touchpoints (re-read before coding)

- **Adapter registry:** Extend `AdapterFactory` (or equivalent) so `eventBus.adapter` / `messageLog.adapter` accept `'kafka'` alongside `'in-memory' | 'database' | 'nats'`. The closed union in core must gain `'kafka'` only when this package lands — do not reserve a dead `kafka` id in the first NATS-only ship unless you explicitly want forward-compat stubs (not recommended).
- **Contract bags:** `packages/core/src/testing/{eventBus,messageLog,durableSubscription}Contract.ts` — every adapter must pass unchanged.
- **`BusEventSchema`:** Round-trip lossless through `KafkaEventBus.publish` / subscribe path.
- **`BackpressureManager`:** Remains the sole budget owner; Kafka adapter reports inflight the same way as NATS (see parent §5.4b).

## Implementation notes

- Uses `kafkajs` (latest) as the underlying client; pinned via `yarn workspace add kafkajs` (pin exact version in the PR that adds this package).
- `KafkaMessageLog` implements `MessageLog`:
  - `append`: produces to the Kafka partition derived from a deterministic **partition key** over `(tenantId, conversationId)`, hashed via murmur2. Kafka's per-partition ordering guarantee gives per-conversation ordering; the Kafka topic itself uses a fixed configurable partition count (default `64`, sized to cluster; set via `kafka.partitions`). The planned-architecture doc's "one partition per logical topic" guardrail (`multi-agent-communication.md` § "Resolved questions" 6) is satisfied **by partition key**, not by one physical partition per conversation (which would be operationally unviable for high-fan-out workloads). Configurable via `kafka.partitionKeyStrategy = 'conversation' | 'sticky-tenant'` (default `'conversation'`).
    - `'conversation'`: `murmur2(tenantId + ':' + conversationId)` → partition index. All messages for a conversation land on the same partition → total order within the conversation.
    - `'sticky-tenant'`: `murmur2(tenantId)` → partition index. All conversations within a tenant share a partition → total order per tenant (coarser but lower hot-partition risk for chatty conversations; operators choose).
    - The contract test in §5.4c.1 asserts per-conversation ordering for both strategies; the strategy name is surfaced in `outbound.committed` observations for debuggability.
  - `read` / `replay`: uses Kafka consumer with explicit offsets; `findByIdempotency` is **not** Kafka-native and falls back to an auxiliary index (per-tenant `idempotency_index` Kafka compacted topic). When the Kafka adapter is selected, `MessageLog.findByIdempotency` queries the index topic instead of the SQL store.
- `KafkaDurableSubscription` implements `DurableSubscription`:
  - Maps `streamId` → Kafka topic; `consumerId` → consumer group id.
  - `ack` commits the offset; `nack` does not commit and triggers re-delivery on next poll.
  - `setCursor` uses `seek`; `getCursor` reads committed offset.
- `KafkaEventBus` implements `IEventBus`:
  - `publish` produces to a transient `events.<channel>` topic (configurable retention; default 1 hour).
  - `subscribe` joins a per-process consumer group; events fan out within the process. Cross-process fan-out is the durable subscription path, not the transient bus.

## Configuration shape (runtime config)

```json
{
    "eventBus": { "adapter": "kafka", "kafka": { "brokers": ["host:9092"], "clientId": "callagent" } },
    "messageLog": { "adapter": "kafka", "kafka": { "topicPrefix": "callagent.conversation" } }
}
```

The package depends on `@a2arium/callagent-core` for the public types; it should be an **optional** peer dependency; not pulled into the default install.

## Config migration note (Kafka-only)

If a draft ever used the older key names: `kafka.partitionStrategy` → `kafka.partitionKeyStrategy` (values: `one-per-conversation` → `conversation`, `sticky` → `sticky-tenant`).

1. `KafkaEventBus`, `KafkaMessageLog`, `KafkaDurableSubscription` exist as a separate optional package and pass the three contract bags from parent §5.4c.1 with `RUN_BROKER_TESTS=1`.
