# 5.3 Conversation Phase 3 — Thread lifecycle, `IMessageLog`, `sendTaskToAgent` compatibility sugar, and parent/child trace linkage

> **Internal implementation spec.** This document is for framework contributors and maintainers.
> **For framework users migrating to the new APIs**, create and maintain: **`apps/docs/migration/5.3-conversation-phase-3-thread-lifecycle-and-compatibility-sugar-migration.md`**.
>
> **No backwards compatibility.** See `apps/docs/todo/types-rules.md` Rule 14 and Phase 2a/2b precedent. Phase 3 is a deliberately breaking phase at the thread-lifecycle, `sendTaskToAgent`, and `TurnTrace.childCalls` surfaces. The migration doc above is mandatory and is written incrementally alongside implementation, not after the fact.

**Scope:** Phase 3 closes the long-standing gap between the two parallel parent→child coordination stacks (`ctx.conversation.*` vs `ctx.sendTaskToAgent`) and finishes thread lifecycle semantics. Concretely:

1. **Thread lifecycle polish** — `close` fans out `thread.closed` to both participants, `archive` transitions landed as a first-class operation (not just a schema value), and thread TTL (configurable per manifest; default 1 hour) automatically closes idle threads (emitted as `thread.closed` with `closedReason: 'ttl'`) and optionally archives closed threads. `CloseConversationOptions.reason` is honored end to end. TTL is **idle-reset** — every successful `send` extends `expiresAt = now + threadTtlMs`.
2. **`MessageLog` port (a.k.a. `IMessageLog` in earlier drafts)** — extract the durable conversation-message surface (append, read, replay, idempotency lookup) from `ConversationService` into a first-class port (`MessageLog`, exported from `public-types/messageLog/**` per Rule 10) with a DB-backed implementation. The durable log becomes the authoritative record; `ConversationService` becomes the policy/orchestration layer above it. The final exported type name is `MessageLog` (not `IMessageLog`) — see §5 naming rationale; the phase title retains `IMessageLog` as a stable identifier for the planned-architecture cross-ref.
3. **`sendTaskToAgent` as compatibility sugar over `ctx.conversation`** — collapse the parallel A2A pipeline into thread-start + thread-send + thread-close semantics. `ApiBinder` becomes the single place where conversation and A2A meet; `streamingRunner`'s ad-hoc `sendTaskToAgent` wrapper is replaced by the shared `ApiBinder` path so parent/child telemetry and trace fields are identical regardless of runner.
4. **Parent/child trace linkage** — populate `TurnTrace.childCalls[n].childAgentNodeId` and `childCalls[n].childTraceId` for every child dispatch (both classic `sendTaskToAgent` and conversation-driven dispatches that spawn a child session), so trace consumers can walk parent→child trees without relying on the underlying telemetry tree.

**Normative anchor:** [`apps/docs/planned_architecture/multi-agent-communication.md` § Phase 3](../planned_architecture/multi-agent-communication.md#phased-delivery-with-evolving-example-agent) (table row "Phase 3") and [§ Implementation priorities → Phase 3 rows](../planned_architecture/multi-agent-communication.md#implementation-priorities).

### Out of scope (still deferred)

- Cross-runtime transport adapters (Kafka / NATS / external brokers) — **Phase 4**.
- `IDurableSubscription` (ack/nack, cursor groups) — **Phase 4**. Phase 3 defines the `MessageLog` port only; `IDurableSubscription` is an additive interface that Phase 4 layers on top.
- Selector turn-taking policy (`'selector'`) — **Phase 4**.
- Typed shared topic documents (CRDT-backed or otherwise) — **Phase 4**.
- Manifest `communication` capability expansions beyond `threadTtlMs` (`acceptedSpeechActs`, `acceptedContentTypes`, `jsonSchemas`, `topicPoliciesSupported`) — **Phase 4**.
- Semantic changes to topic `close` fan-out (Phase 2 behavior is already correct; Phase 3 brings the thread path up to parity with it, not the other way around).
- Deprecating `ctx.sendTaskToAgent`. It remains the recommended pattern for directed task delegation (see `multi-agent-communication.md` § Rule E). Phase 3 only **reimplements it over conversation primitives**; the public surface stays.

## Problem Statement

Phase 1 delivered thread primitives (`startThread`, `send`, typed receipts, idempotency, queue semantics) and Phase 2/2a/2b delivered topics, fan-out, multiplicity, and invite lifecycle. Thread close is half-implemented, the A2A dispatch path runs in parallel to `ctx.conversation`, and the `TurnTrace.childCalls` linkage fields exist but are never stamped. Until Phase 3 ships, framework users cannot rely on:

- `thread.closed` reaching both participants (today it is **never emitted** — the schema exists, the reducer handles it, but `ConversationService.close` only flips the DB row for threads).
- Thread TTL / auto-archive (absent at model and service level).
- `sendTaskToAgent` and `ctx.conversation` producing the same persistence rows, the same `outbound.committed` observations, and the same trace linkage — today they do not.
- Walking `TurnTrace.childCalls` to a child trace id without reaching into `telemetry` (today `childAgentNodeId` / `childTraceId` are always absent).

## 🏗 Requirements

### 1. Public conversation contracts — thread lifecycle and options

**Rule enforcement:** Rule 1 (types reflect runtime), Rule 2 (Zod source of truth), Rule 4 (illegal states must not compile), Rule 5 (no public `any`), Rule 11 (typed errors), Rule 12 (avoid overengineering), Rule 14 (breaking changes require migration doc), Rule 15 (simple + advanced modes).

**Files:**
- `packages/core/src/public-types/conversation/schemas.ts` **(MODIFY)**
- `packages/core/src/public-types/conversation/types.ts` **(MODIFY)**
- `packages/core/src/public-types/conversation/projection.ts` **(MODIFY)**
- `packages/core/src/public-types/conversation/index.ts` **(MODIFY)**

Changes:

- `ThreadStatusSchema` **(NEW)** — `z.enum(['open', 'closed', 'archived'])`. A **closed literal union** (not a branded string), exported as the single authority for thread status. Rule 4 compliance is satisfied by the union exhaustiveness, not by branding. Previously duplicated as inline string literals in multiple places; Phase 3 consolidates.
- `StartThreadOptionsSchema` **(MODIFY — breaking)** — add optional `timeoutMs: z.number().int().positive().max(24 * 60 * 60 * 1000).optional()` and `awaitMode: z.enum(['blocking', 'deferred']).optional()` (matches `multi-agent-communication.md` § Public model). Defaults: `awaitMode = 'deferred'`, `timeoutMs = undefined` (no explicit timeout; thread TTL still applies). `timeoutMs` is the upper bound on **one `startThread` call's blocking wait** when `awaitMode === 'blocking'`; for `awaitMode === 'deferred'` the field is validated but unused (runtime invariant documented via a JSDoc `@remarks` note on the schema to satisfy Rule 1: "types reflect runtime").
- `SendOptionsSchema` **(MODIFY — additive)** — add optional `timeoutMs` (same semantics; bounds the blocking portion of the accept/flush path only).
- `CloseConversationOptionsSchema` **(MODIFY — breaking)** — `reason: z.string().min(1).max(500).optional()` (previously unconstrained; Rule 14). Add optional `archiveAfter: z.boolean().optional()` — when `true`, a successful close is immediately followed by an `archive` transition in the same transaction, and a `thread.archived` observation is emitted alongside `thread.closed`. Default: `false`.
  - **Runtime-only invariant (Rule 1).** `archiveAfter` is honored iff `ref.kind === 'thread'`. Calling `close(topicRef, { archiveAfter: true })` raises `ConversationError` with code `ArchiveUnsupportedForTopics`; topic archive is Phase 4. This invariant is explicit in the JSDoc on `archiveAfter` and enforced at runtime in `ConversationService.close`.
- `ArchiveConversationOptionsSchema` **(NEW)** — `{ reasonText?: z.string().min(1).max(500) }`. Distinct option bag for archiving an already-closed thread. Uses `reasonText` (not `reason`) to unambiguously populate `reasonText` on the emitted `thread.archived` payload.
- `ArchiveConversationReceiptSchema` **(NEW)** — `{ ref: ThreadRefSchema, archived: boolean }`. Mirrors `CloseConversationReceiptSchema`.
- `CloseConversationReceiptSchema` **(MODIFY — breaking)** — `{ ref: ConversationRefSchema, closed: boolean, archived?: boolean }`. `archived` is present iff the close was paired with `archiveAfter: true`. Classified as **breaking** (not additive) because downstream code pattern-matching the receipt with exhaustive type checks must handle the new optional field; Rule 14 requires surfacing this in the migration guide.
- `ConversationErrorSchema` **(MODIFY — breaking, additive branches)** — add:
  - `ThreadNotClosed` — attempted to `archive` a thread whose status is not `'closed'`.
  - `ThreadExpired` — attempted to `send` into a thread whose status is `'closed'` **because of TTL expiry** (i.e. the underlying row has `close_reason = 'ttl'`). Distinct from `ConversationClosed` so policies can recover by starting a fresh thread automatically.
  - `ConversationTimeout` — `startThread`/`send` exceeded `timeoutMs`. Typed, observable, never a raw throw.
  - `ArchiveUnsupportedForTopics` — `close(topicRef, { archiveAfter: true })` or `archive(topicRef)` was called. Phase-3 closed world; Phase 4 may remove.
  Each new branch is a discriminated-union member; exhaustiveness in consumer switches is enforced by TypeScript (Rule 4).
- `ConversationApi` **(MODIFY — breaking)**:
  ```ts
  close(ref: ConversationRef, options?: CloseConversationOptions): Promise<CloseConversationReceipt>;
  archive(ref: ThreadRef, options?: ArchiveConversationOptions): Promise<ArchiveConversationReceipt>; // NEW; ref type enforces thread-only
  ```
  Archive is intentionally **thread-only** in Phase 3 and enforced at the type level by requiring `ThreadRef` (not `ConversationRef`) — passing a `TopicRef` is a compile error (Rule 4). Topic archive is a Phase 4 concern (requires fan-out + member notification, which piggybacks on Phase 4 transport work).
- `ConversationProjection` **(MODIFY — breaking)** — `threads[id]` entry shape:
  ```ts
  {
    status: ThreadStatus;
    closedAt?: string;              // ISO; present iff status !== 'open'
    closedReason?: CloseReason;     // 'explicit' | 'ttl' | 'archived'; present iff status !== 'open'
    closedReasonText?: string;      // operator-supplied free text; present iff closedReason === 'explicit' and caller passed reason
    closedByAgentId?: AgentId;      // absent for TTL-driven closures
    archivedAt?: string;            // ISO; present iff status === 'archived'
    archivedByAgentId?: AgentId;    // present iff archive was operator-initiated
    archivedReasonText?: string;
    expiresAt?: string;              // ISO; present when TTL is configured; rewritten on every successful send
  }
  ```
  - **Ordering invariant:** `threads` entries serialized by the projection are sorted by `id` ascending (same discipline as Phase 2a members).
  - **Runtime invariant (Rule 1):** `closedAt`/`closedReason` are either both present or both absent; reducer guarantees this pairing. The type keeps them optional individually because TypeScript cannot express "both or neither" without a sum type, and the sum-type cost is not justified here (Rule 12); the invariant is asserted in the reducer unit tests instead.
- `StartThreadReceiptSchema` **(MODIFY — additive)** — add optional `timedOut: boolean` on the nested `receipt`. Set iff the blocking wait exceeded `timeoutMs`; in that case the receipt `status` is `'rejected'` with error `ConversationTimeout`.

Public type/contract discipline:

- Zero new public `any` anywhere in `public-types/conversation/**` (Rule 5).
- Runtime validation and static typing share one Zod authority per symbol (Rule 2).
- No "soft" enum strings for thread status or close reason; consumer code narrows on `ThreadStatus` / `CloseReason` unions (Rule 4).
- Every field whose presence depends on a runtime condition (e.g. `closedAt` iff `status !== 'open'`) carries a JSDoc `@remarks` sentence that states the invariant in prose; Rule 1 requires documenting such invariants even when the type cannot express them.

### 2. Observation taxonomy — emit `thread.closed`, add `thread.archived`, thread TTL expiry

**Rule enforcement:** Rule 1, Rule 2, Rule 4, Rule 11.

**Files:**
- `packages/core/src/types/observation.ts` **(MODIFY)**
- `packages/core/src/loop/types.ts` **(MODIFY)** (only if inbox helper surfaces need the new payloads)
- `packages/core/src/loop/learning/conversationReducer.ts` **(MODIFY)**

Changes:

- `CloseReasonSchema` **(NEW)** — closed literal union `z.enum(['explicit', 'ttl', 'archived'])` (extensible via a future dedicated phase; adding a new variant is a breaking type change). `'explicit'` is the default when the caller provides no `options.reason`; `'ttl'` is stamped exclusively by the sweeper; `'archived'` is stamped when the caller issues an `archive` on an already-closed thread and we need to distinguish "closed then archived" in the log.
- `ConversationPayloadSchema` **(MODIFY — breaking, additive branch)**:
  - Existing `thread.closed` branch **(MODIFY)** gains:
    - required `ts: z.string().datetime()` (parity with `topic.closed`),
    - optional `closedBy: AgentIdSchema` (the participant who initiated the close; **absent** for TTL-driven closures),
    - optional `closedReason: CloseReasonSchema` (present iff `'ttl'` or when the caller passes an explicit `options.reason` — in which case `closedReason === 'explicit'` and the free-text `reason` rides in a separate optional `reasonText: z.string()` field capped at 500 chars),
    - optional `reasonText: z.string().min(1).max(500)` (caller-supplied free text; sister field to `closedReason === 'explicit'`).
  - New branch `thread.archived`:
    ```ts
    z.object({
      kind: z.literal('thread.archived'),
      thread: ThreadRefSchema,
      ts: z.string().datetime(),
      archivedBy: AgentIdSchema.optional(),
      reasonText: z.string().min(1).max(500).optional(),
    });
    ```
  - **No `thread.expired` kind.** TTL-driven close is encoded on the existing `thread.closed` payload via `closedReason: 'ttl'`. Policies that want to distinguish operator close vs. TTL close narrow on `closedReason`. Rationale: Rule 12 — one observation kind does the job; a second kind doubles surface, tests, reducer branches, and docs with no policy win.
- **Fan-out rule (normative).** `ConversationService.close` (thread branch) MUST call `ConversationRouter.routeObservations` with the `thread.closed` observation targeted at **both** `ownerAgentId` and `participantAgentId` sessions. Same pattern used by `topic.closed` today. If `archiveAfter: true`, a second observation `thread.archived` rides the same transactional boundary to the same two sessions.
- **Reducer behavior (normative).**
  - On `thread.closed`: `threads[id] = { ...cur, status: 'closed', closedAt: ts, closedReason, closedByAgentId: closedBy, closedReasonText: reasonText }` — only fields whose source is present are stamped; others stay undefined.
  - On `thread.archived`: `threads[id] = { ...cur, status: 'archived', archivedAt: ts, archivedByAgentId: archivedBy, archivedReasonText: reasonText }`.
- **Resolution-before-emission invariant (reaffirmed from Phase 2a).** By the time any `conversation/*` observation leaves `ConversationService`, every `ts` is resolved from the single framework `Clock`; no reducer or trace consumer performs clock calls.

### 3. `ConversationService` — thread lifecycle + `archive` + TTL sweeper

**Rule enforcement:** Rule 1, Rule 4, Rule 5, Rule 12.

**Files:**
- `packages/core/src/internal/conversation/ConversationService.ts` **(MODIFY)**
- `packages/core/src/internal/conversation/ThreadLifecycleSweeper.ts` **(NEW)** — mirrors `InviteSweeper.ts`
- `packages/core/src/internal/conversation/Clock.ts` **(REUSE)**
- `packages/core/src/internal/conversation/types.ts` **(MODIFY)**

Responsibilities:

- **`close(ref, options)` for threads (MODIFY — breaking).**
  1. Load the thread row inside a DB transaction (`SELECT ... FOR UPDATE`); if already `'closed'` → idempotent success (same receipt shape, no second observation fan-out); if `'archived'` → reject with `ConversationClosed` (archived is terminal).
  2. Call `sessionManager.updateConversationThreadStatus({ ..., status: 'closed', closedAt, closeReason: 'explicit', closeReasonText: options?.reason })` — store API gains `closedAt`, `closeReason`, and `closeReasonText` parameters (see §4).
  3. Build `thread.closed` observation `{ thread: ref, ts: clock.now(), closedReason: 'explicit', reasonText: options?.reason, closedBy: <senderAgentId> }`.
  4. Fan-out via `router.routeObservations` to both `(tenantId, ownerSessionId, ownerAgentId)` and `(tenantId, participantSessionId, participantAgentId)`.
  5. If `options.archiveAfter === true` **and** `ref.kind === 'thread'`: immediately call the internal `archive` path (same tx, same router batch): emit `thread.archived`, transition status to `'archived'`, stamp `archivedAt`.
  6. If `options.archiveAfter === true` **and** `ref.kind === 'topic'`: reject with `ArchiveUnsupportedForTopics` before step 2 (no partial state).
  7. Return `{ ref, closed: true, archived?: true }`.
- **`archive(ref, options)` (NEW).**
  - Signature is typed to `ThreadRef`, so `TopicRef` is a compile error.
  - Runtime check: must be called on a thread already in status `'closed'`. Otherwise → `ThreadNotClosed`.
  - Emits `thread.archived` to both participants with `{ archivedBy, reasonText: options?.reasonText }`.
  - Returns `{ ref, archived: true }`.
- **`send` (MODIFY — additive + runtime invariants).**
  - **TTL reset.** On successful accept (after idempotency dedupe resolves), the service rewrites `expires_at = clock.now() + threadTtlMs` in the same transaction as the message append (see §4). Both participants' sends reset TTL; only the sweeper closes an idle thread. If `threadTtlMs` is unset, `expires_at` stays `NULL` and the sweeper never matches.
  - **Expiry race (normative).** The flow is: (1) `SELECT ... FOR UPDATE` the thread row inside the send tx; (2) if `status !== 'open'` → reject: `ConversationClosed` if `close_reason !== 'ttl'`, `ThreadExpired` if `close_reason === 'ttl'`; (3) else append via `MessageLog.append` and rewrite `expires_at` in the same tx. The lock prevents the sweeper from closing the thread between read and append.
  - **`options?.timeoutMs`.** If the blocking wait (queue flush, router return) exceeds `timeoutMs`, return a `rejected` receipt with `ConversationTimeout`. Deterministic via the injected `Clock` and an `AbortController`-style cancellation token.
- **`startThread` (MODIFY — additive).**
  - Honor `options?.timeoutMs` and `options?.awaitMode` end to end:
    - `awaitMode === 'deferred'` (default): returns as soon as the initial `send` is accepted. `timeoutMs` is **ignored at runtime** (documented on the schema).
    - `awaitMode === 'blocking'`: waits for a child response observation or `timeoutMs` expiry. Implementation: subscribe to the inbox for the newly created thread at the calling session, resolve on the first `message.received` with matching `correlationId`, or reject on `ConversationTimeout`.
  - Stamp a computed `expiresAt = clock.now() + threadTtlMs` on the created thread row when the manifest supplies `communication.threadTtlMs`. Defaults fall back to **1 hour** when absent (per `multi-agent-communication.md` § FR-1.3). When `communication.threadTtlMs === null` is passed explicitly, TTL is disabled for that agent (column stays `NULL`).
- **`ThreadLifecycleSweeper` (NEW).**
  - Polls (default **every 30 s**; configurable via runtime config `conversation.threadSweeper.intervalMs`) for threads where `status = 'open' AND expires_at IS NOT NULL AND expires_at < now()`.
  - **Concurrency strategy (normative).** The sweeper uses `SELECT ... FOR UPDATE SKIP LOCKED LIMIT batch` (default `batch = 100`; configurable via `conversation.threadSweeper.batchSize`). This guarantees: (a) only one replica touches a given thread per tick, (b) no blocking against in-flight `send` transactions (those hold the row lock; sweeper skips and retries next tick), (c) large backlogs drain across replicas without hot spots. The in-memory session manager uses a narrower analogue (a `Set<conversationId>` of in-flight locks) to produce identical observable behavior under the test harness.
  - For each swept thread:
    1. Transition status to `'closed'`, stamp `closedAt = now()`, `closeReason = 'ttl'`, `closeReasonText = NULL`.
    2. Emit exactly one `thread.closed` observation with `closedReason: 'ttl'`, no `closedBy`, no `reasonText`. Fan out to both participants.
    3. If `conversation.threadSweeper.autoArchiveAfterMs` is configured, a **second sweep pass** (same tick, separate query) handles `status = 'closed' AND closed_at < now() - autoArchiveAfterMs`: transitions `'closed'` → `'archived'`, emits `thread.archived` with `archivedBy = undefined` to both participants. Auto-archive is off by default; operators opt in.
  - Sweeper is a standalone orchestration component; it runs in the same runtime as `ConversationService` for v1. Phase 4 can move it behind a queue/cron if needed (no interface change required — constructor takes only `Clock`, `SessionManager`, `ConversationRouter`, and the runtime config bag).
  - Sweeper MUST be deterministic under the test harness (injectable `Clock` and opt-out `start()` / explicit `tick()` API, same as `InviteSweeper`).

  - Add `expires_at TIMESTAMP NULL`.
  - Add index `@@index([tenantId, status, expiresAt])` — covers the sweeper "open expired" hot query.
  - Add index `@@index([tenantId, status, closedAt])` — covers the sweeper auto-archive pass (closed + old).
  - Add CHECK constraints (migration-only; Prisma does not model CHECK in the DSL):
    - `status IN ('open', 'closed', 'archived')`
    - `close_reason IS NULL OR close_reason IN ('explicit', 'ttl', 'archived')`
    - `(status = 'open') = (closed_at IS NULL)` — pairing invariant; prevents half-closed rows from entering the store directly.
  - **Backfill policy.** The migration leaves all new columns `NULL` on existing rows. This means pre-Phase-3 threads never auto-expire (no `expires_at`) and never report a `closeReason` in the projection even if they were later closed; this is intentional and documented in the migration guide — retroactive TTL would be a behavior change on historical data.
- Store interface changes (`IWorkingMemorySessionStore`):
  - `createConversationThread({ ..., expiresAt? })` — accept `expiresAt` as optional ISO.
  - `updateConversationThreadStatus(input)` where `input` is a **discriminated union** (Rule 4): `{ kind: 'close'; tenantId; conversationId; closedAt; closeReason: CloseReason; closeReasonText?; closedByAgentId? }` | `{ kind: 'archive'; tenantId; conversationId; archivedAt; archivedByAgentId?; archivedReasonText? }`. Replacing the old flat optional bag with a discriminated union makes illegal combinations uncompilable.
  - `refreshConversationThreadExpiry({ tenantId, conversationId, expiresAt })` **(NEW)** — invoked by `send` to advance `expires_at`; single-row update, safe to call even when TTL is unset (no-op if `expires_at` was already NULL and caller passes NULL).
  - `listConversationThreadsForSweep({ tenantId, now, mode: 'expireOpen' | 'archiveClosed', limit })` **(NEW)** — the sweeper's only lookup API. `mode` is a closed literal union so a third sweep mode cannot be introduced accidentally. Uses `SELECT ... FOR UPDATE SKIP LOCKED` on SQL; in-memory parity lock-skip via `Set<conversationId>`.
  - `getConversationThread({ tenantId, conversationId })` **(NEW — additive)** — returns the thread row with the full lifecycle surface. Service code today loads the row via ad-hoc queries inside `ConversationService`; Phase 3 consolidates.

Atomicity: all status transitions, observation emission, and message append share one DB transaction per logical operation, same discipline as Phase 2 `topic.closed`.

Operational posture: the migration is **additive** (new nullable columns + two new indexes). It is **safe online** (no PK / unique-constraint shifts), unlike Phase 2a. The migration guide makes this explicit so operators do not burn an unnecessary downtime window.

**Postgres specifics.** Index creation uses `CREATE INDEX CONCURRENTLY` in the migration SQL (not the default blocking `CREATE INDEX`) so large `conversation_threads` tables do not lock writers for the migration's duration. The migration file includes an explicit `-- concurrent index; split into its own transaction` comment so reviewers know why the index DDL is outside the main `BEGIN` block.

### 10. Clean API constraints (MUST hold after implementation)

5. `ctx.sendTaskToAgent` and `ctx.conversation.startThread` are observationally equivalent at the persistence and trace layer.
6. `streamingRunner` and the default runner produce byte-identical `TurnTrace.childCalls[*]` for the same inputs.
7. `TurnTrace.childCalls[n].childAgentNodeId` and `childTraceId` are present on every successful child dispatch; absent (not stubbed) on failure.
8. No public `any` in any Phase 3-touched public surface.
9. `ThreadStatus` and `CloseReason` are closed literal unions; free-string assignments are compile errors.
10. All new errors (`ThreadNotClosed`, `ThreadExpired`, `ConversationTimeout`, `ArchiveUnsupportedForTopics`) are surfaced as typed `ConversationError` branches, never raw throws.
11. **Runtime-only invariants are documented.** Every field whose presence is conditional on runtime state (e.g. projection `closedAt` iff `status !== 'open'`; `closedBy` iff not TTL) carries a JSDoc `@remarks` line that states the invariant, per Rule 1. 13. Phase 1 / 2 / 2a / 2b single-seat flows compile and run byte-identically (regression guard; failure is a migration bug).

### 11. Isolation and determinism guarantees (normative)

1. **Sweeper determinism.** `ThreadLifecycleSweeper` consumes `Clock`, `SessionManager`, `ConversationRouter`, and the runtime config bag — no implicit clocks, no background timers unless `start()` is called. Tests use explicit `tick()`.
2. **Sweeper concurrency safety.** Uses `SELECT ... FOR UPDATE SKIP LOCKED` on SQL (and an in-memory lock-set analogue in `InMemorySessionManager`). Multi-replica deployments cannot double-close a thread; a thread locked by an in-flight `send` is skipped and retried next tick.
3. **TTL observability.** TTL expiry emits exactly one `thread.closed` with `closedReason: 'ttl'`, fan out to both participants. No silent expiry.
4. **TTL idle-reset invariant.** Every successful `send` rewrites `expires_at = clock.now() + threadTtlMs` in the same transaction as the message append. Readers of the projection see the latest `expiresAt` without racing.
5. **Expiry-vs-send race.** `send` takes a row-level lock on the thread row inside the same transaction as the append; the sweeper uses `SKIP LOCKED`. Result: either the send commits (thread stays `'open'`, TTL extended) or the sweeper commits (send sees `'closed'` and returns `ThreadExpired`). No torn state is observable.
6. **Transactional close.** `thread.closed` observation routing + `conversation_threads.status` transition + (optional) `thread.archived` emission happen in one DB transaction per thread.
7. **Compatibility sugar atomicity.** A `ctx.sendTaskToAgent` call that fails before the child session starts does not leave a `conversation_messages` row behind. Partial-failure rollback mirrors Phase 2 topic post.
8. **Trace linkage non-lie.** When `childTraceId` cannot be resolved (child plugin missing, A2A setup failure before telemetry creation), the field is **absent**, not a placeholder. Consumers of `TurnTrace` never see a stale / fabricated id.

## ✅ Acceptance Criteria

1. `ctx.conversation.close(threadRef)` emits `thread.closed` to both participants with `ts`, `closedBy`, `closedReason: 'explicit'`, optional `reasonText`; stamps `closedAt` / `closedReason` / `closedByAgentId` on the row; and (with `archiveAfter: true`) immediately transitions to `'archived'` and emits `thread.archived` in one transactional observation batch. On topics, `archiveAfter: true` raises `ArchiveUnsupportedForTopics` before any state changes.
2. `ctx.conversation.archive(threadRef)` is a first-class verb on `ConversationApi`, typed to `ThreadRef`; calling it on `open` yields `ThreadNotClosed`; calling it on `closed` emits `thread.archived` and stamps `archivedAt`; passing a `TopicRef` is a compile error.
3. `ThreadLifecycleSweeper` expires idle threads per `communication.threadTtlMs` (default 1 hour); expiry emits exactly one `thread.closed` observation with `closedReason: 'ttl'` and `closedBy === undefined`; a subsequent `send` returns typed `ThreadExpired` (distinct from `ConversationClosed`). **TTL is idle-reset:** every successful `send` rewrites `expires_at`. Sweeper uses `SELECT ... FOR UPDATE SKIP LOCKED` on SQL.
4. `StartThreadOptions.awaitMode` (`'blocking' | 'deferred'`) and `timeoutMs` are honored end-to-end; blocking waits return typed `ConversationTimeout` on expiry; `timeoutMs` is unused at runtime for `'deferred'` (documented in schema JSDoc).
5. `MessageLog` port (public types under `public-types/messageLog/**`) is the single durable-log interface used by `ConversationService`; no agent code path calls `sessionManager.appendConversationMessage` directly after Phase 3 (enforced by executable `rg`-guard test); `dbMessageLog` is the default implementation. `append` returns a discriminated `{ kind: 'appended' | 'dedupeHit', ... }` union.
6. `ctx.sendTaskToAgent` is implemented over `ctx.conversation.startThread` / `send` / `close`; the same call produces a `conversation_messages` row, an `outbound.committed` observation on the parent, and a `message.received` on the child — identical to `ctx.conversation.startThread`. Public signature is unchanged (verified by a `d.ts` diff step).
7. `streamingRunner` no longer carries a local `sendTaskToAgent` wrapper; both runners produce byte-identical `TurnTrace.childCalls[*]` for the same inputs.
8. `A2ACallOptions.timeout` is enforced (maps to conversation-level `timeoutMs`); `A2ACallOptions.childTaskId` maps to `idempotencyKey`; a new `A2ACallOptions.conversation?: ThreadRef` (thread-only; `TopicRef` is a compile error) enables thread reuse for multi-turn patterns.
9. `TurnTrace.childCalls[n].childAgentNodeId` and `childTraceId` are populated on every successful child dispatch (both `sendTaskToAgent` and `ctx.conversation.startThread` paths); **absent** (not stubbed or null) on failures (runtime-honesty rule).
10. `ConversationProjection.threads[id]` grows `closedAt`, `closedReason`, `closedReasonText`, `closedByAgentId`, `archivedAt`, `archivedByAgentId`, `archivedReasonText`, `expiresAt`; reducer is idempotent; projection serialization is ordered by `id` ascending; pairing invariants (`closedAt`⇔`closedReason`) hold in every test replay.
11. `conversation_threads` gains `closed_at`, `close_reason`, `close_reason_text`, `closed_by_agent_id`, `archived_at`, `archived_by_agent_id`, `archived_reason_text`, `expires_at` columns and two `CONCURRENTLY`-created indexes (`(tenant_id, status, expires_at)` and `(tenant_id, status, closed_at)`); migration is additive, safe online, and leaves existing rows' lifecycle columns NULL.
12. Zero new public `any`; all new/extended public types are Zod-sourced; illegal states (wrong `ThreadStatus`, wrong `CloseReason`, missing `ConversationError` branch, `archive(topic)`, `A2ACallOptions.conversation = topicRef`) fail compile.
13. Every new/extended optional public field has a JSDoc `@remarks` line stating the runtime presence invariant (Rule 1).
14. `yarn build` and `yarn test` pass across all workspaces; type tests enforce new constraints; deterministic sweeper tests do not rely on wall-clock.
15. Phase 1 / 2 / 2a / 2b single-seat and multi-seat scenarios continue to pass byte-identically (regression guard).
16. Migration guide at `apps/docs/migration/5.3-conversation-phase-3-thread-lifecycle-and-compatibility-sugar-migration.md` is written incrementally alongside implementation and covers every user-visible change listed in §9.
17. Canonical example `apps/examples/conversation-reference-agent` demonstrates Phase 3 behaviors end-to-end (close/archive, TTL via deterministic clock, `closedReason` narrowing, `sendTaskToAgent` parity, trace linkage) without touching any private API.
