# 3.3.1 Migrate vars to worldModel

## Problem Statement
The codebase currently uses `M.memory.vars` (and `(M as any).memory.vars` or `ctx.vars`) as a catch-all for state that doesn't fit into the structured mental state. This violates:
- **Rule 5 (No any in public APIs)**: Accessing `vars` often requires explicit `as any` casting because it was removed from the `MentalState` type definition in 3.3.
- **Rule 2 (Schemas are source of truth)**: `vars` is untyped and not part of the core Zod-backed mental state schema.
- **APLRET contracts**: State should be properly categorized (e.g., in `worldModel`, `goalState`, or `episode` events).

## Goal
Fully migrate all usage of the `vars` property to either `worldModel` or `scratch` (for short-term turn state), ensuring type safety and schema compliance.

## Tasks
- [ ] Define Zod schema for `worldModel` if not already comprehensive.
- [ ] Identify all locations using `memory.vars` or `ctx.vars`.
- [ ] Migrate `TaskContext.vars` to `TaskContext.worldModel` (or similar typed accessor).
- [ ] Update `TaskExecutor.mergeVarsIntoMental` to merge into `worldModel` instead of `vars`.
- [ ] Update `taskEngine.ts` (`flushContextSnapshot`, `attachWorkingMemory`, `persistChildContext`) to use the new location.
- [ ] Update all tests using `vars` to use the new location.
- [ ] Finally, remove the `memory.vars` property from the physical snapshot structure if possible.
