# 2.4 `Intent` vs `ProposedAction` Naming & Shape

## Problem Statement

The typing for agent intentions across the codebase is disjointed from the APLRET contract payload envelopes as defined in `0-aplret_contracts.md`. Currently, `oneTurn.ts` (in both `packages/core` and externally copied to `packages/memory-engine`) uses an ambiguously defined `ProposedAction` type bridging internal actions (`subagent`, `language`) with standard interactions (`tool`).

```typescript
// Current outdated signature
export type ProposedAction =
    | { kind: 'ask_user'; prompt: string; schema?: unknown }
    | { kind: 'subagent'; target: string; input: unknown; awaitCompletion?: boolean }
    | { kind: 'tool'; name: string; args: unknown; awaitCallback?: boolean }
    | { kind: 'language'; content: string }
    | { kind: 'internal'; intent: string; data?: unknown };
```

This violates the canonical definitions of `Intent` introduced in the latest APLRET architectural rewrite, creating inconsistencies in the Policy, Shield, and Execution modules.

---

## 🏗 Requirements

### 1. Deprecate `ProposedAction` and Introduce `Intent`
Replace all instances of `ProposedAction` with a strictly discriminated `Intent` type. 

**Required Types (as per `0-aplret_contracts.md`):**
```typescript
export type Intent =
  | { kind: 'prompt_user'; prompt?: string }
  | { kind: 'answer_with_llm'; query: string; contextKey?: string }
  
  // Tools / children
  | { kind: 'call_tool'; toolName: string; args: Record<string, unknown>; mode: 'sync' | 'async' }
  | { kind: 'delegate_to_child'; agentId: string; input: unknown }
  
  // Planning
  | { kind: 'create_plan'; goalId: string }
  | { kind: 'execute_next_step'; planId: string }
  | { kind: 'repair_plan'; planId: string; reason: string }
  
  // Terminal / idle
  | { kind: 'complete'; result: unknown }
  | { kind: 'wait' };
```

### 2. Affected Modules Refactoring
Update the type signatures, variable namings, and logic handling in:
- **`packages/core/src/loop/oneTurn.ts`**:
  - Replace `ProposedAction` export with `Intent`.
  - Update `Modules.policy`, `Modules.shield`, `Modules.execution`, and `Modules.learning` generic signatures and implementations.
- **`packages/core/src/loop/loopRunner.ts`**:
  - Update the fallback default module implementations (e.g. `execution`, `shield`) to parse `Intent` structures correctly. Re-map `kind === 'call_tool'`, `kind === 'delegate_to_child'`, etc.
- **`packages/memory-engine/src/types/external/loop/oneTurn.ts`**:
  - Ensure the duplicate declarations match exactly or consider deduplication by importing the core type depending on workspace topology constraints.

### 3. Execution Module Routing & `ExecutableAction` refactor
`ExecutableAction` must also align with `Intent`:
```typescript
export type ExecutableAction =
    | { kind: 'prompt_user'; token: string }
    | { kind: 'delegate_to_child'; token?: string }
    | { kind: 'call_tool'; token?: string }
    | { kind: 'answer_with_llm'; echoed: boolean }
    | { kind: 'internal'; done: boolean }; // Adjust based on new internal intents like 'create_plan'
```
Refactor how `loopRunner.ts` maps `Intent` (previously `ProposedAction`) to `ExecResult` and `ExecutableAction`. Make sure the default `modules.execution` block uses the strictly correctly mapped types.

### 4. Clean API Constraints
- **NO backwards compatibility**: The framework will not support old `ProposedAction` schemas.
- **NO `any` usage**: Strictly define schemas, e.g. mapping `Record<string, unknown>` correctly and utilizing type guards where necessary. Ensure `args` for `call_tool` are properly typed, dropping any implicit `any` behavior.
