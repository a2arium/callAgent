# Migration: Conversation Phase 2b (invite delivery and join lifecycle)

This document tracks **breaking changes** for Phase 2b.
There is **no backward compatibility shim** for pre-2b invite contracts.

> This migration guide is updated incrementally while Phase 2b is being implemented.
> Items marked as implemented are already in code; remaining items are added as implementation progresses.

## Summary of breaking changes (implemented so far)

1. `InviteToken` is now a branded public type (`InviteTokenSchema`).
2. `TopicJoinOptions.inviteToken` now requires `InviteToken` (not raw `string`).
3. `TopicInviteReceipt.status === 'ok'` now includes required `expiresAt`.
4. `ConversationApi` now includes `decline(topic, options)`.
5. `TopicDeclineOptions` and `TopicDeclineReceipt` are added.
6. `TopicInviteOptions` now includes optional:
   - `ttlSeconds`
   - `idempotencyKey` (when set, repeated `invite` calls return the same `{ token, expiresAt }` without duplicating delivery)
   - `correlationId` (stored on the invite row and echoed on `topic.invite.issued` for tracing)
7. `ConversationError` replaces `InviteInvalid` with:
   - `InviteNotFound`
   - `InviteExpired`
   - `InviteAlreadyConsumed`
   - `InviteTargetMismatch`
8. `ConversationPayload` adds invite lifecycle observations:
   - `topic.invite.issued`
   - `topic.invite.received`
   - `topic.invite.accepted`
   - `topic.invite.declined`
   - `topic.invite.expired`

## SQL / persistence migration

Apply migrations **in order**:

1. `packages/memory-sql/prisma/migrations/20260417180000_conversation_phase2b_invite_lifecycle/migration.sql`
2. `packages/memory-sql/prisma/migrations/20260417220000_conversation_invite_idempotency_columns/migration.sql`

Key DB changes (current implementation):

- `conversation_topic_invites` adds:
  - `expires_at` (required after backfill)
  - `inviter_agent_id` (required after backfill)
  - `inviter_member_id` (required after backfill)
  - `inviter_session_id` (required after backfill)
  - `declined_at`
  - `decline_reason`
  - `delivery_attempted_at`
  - `delivered_at`
  - `delivery_attempts` (default `0`)
  - `delivery_failure_reason`
- From migration (2), `conversation_topic_invites` also adds:
  - `idempotency_key` (optional; participates in idempotent re-issue)
  - `correlation_id` (optional metadata)
  - partial unique index `conversation_topic_invites_idempotency_partial_uidx` on `(tenant_id, conversation_id, idempotency_key)` where `idempotency_key` is not null
- New index:
  - `(tenant_id, expires_at)`

## Runtime behavior changes (implemented so far)

- Invites now emit `topic.invite.issued` to inviter session and publish on in-process event bus.
- Invite delivery is coordinated through `InviteDeliveryCoordinator`.
- Invitee delivery target defaults to `agent-inbox:<agentId>` unless override exists.
- Invite delivery attempts and success are audited (`delivery_attempted_at`, `delivery_attempts`, `delivered_at`).
- `join`/`decline` now use typed invite error branches.
- Expired invites can be closed by `InviteSweeper` and emit `topic.invite.expired`.
- Startup recovery sweep can republish undelivered issued invites.

## Code migration checklist (for framework consumers)

1. Replace raw invite token values in call sites:
   - from: `join(topic, { inviteToken: "..." })`
   - to: `join(topic, { inviteToken: inviteToken("...") })`
2. Update invite receipt handling:
   - `invite(...).status === 'ok'` now returns `{ token, expiresAt }`.
3. Update error matching logic:
   - remove checks for `InviteInvalid`
   - match on new specific invite errors.
4. Extend conversation observation switch statements with `topic.invite.*` variants.
5. If using `ConversationApi`, add handling for `decline(...)`.
6. If reading projection state directly, prepare for:
   - `topics[id].pendingInvites`
   - top-level `invitesInbox`

## Operational note

Treat this as a **breaking migration window** for persistent environments:

- stop writers
- apply DB migration
- run Prisma generate/build
- restart services
