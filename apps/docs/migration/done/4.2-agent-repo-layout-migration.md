# Migration guide: Agent repository layout (4.2)

> **Superseded for new project creation (2026-08-13).** New multi-agent
> projects use `callagent create agent-project` and `callagent create agent`.
> This document remains historical guidance for migrating legacy flat projects.

This guide helps you **refactor an existing flat agent** toward the **recommended layout** for non-trivial agents: `normalizers/`, `selectors.ts`, `reducers.ts`, `effects/`, `prompts/`, `contracts/`, and **`flow.md`**.

There is **no mandatory framework API change** for adopting the layout; it is a **source organization** migration. Aligns with [APLRET contracts](../0-aplret_contracts.md) and [How-to: Agent repository layout](../14-agent_repository_layout_for_aplret.md).

**Related:** [todo 4.2](../todo/4.2-agent-repository-layout-and-patterns.md) · [How-to: `flow.md`](../13-flow_md_for_aplret_agents.md) · [Migration: `flow.md` adoption](./4.1-flow-md-adoption-migration.md)

Starting a new agent? Use scaffold first (`yarn create-agent`) and then apply this guide for deeper refactors/customization. Scaffold details: [Migration: scaffold tooling (4.1)](./4.1-scaffold-agent-tooling.md).

---

## Who is affected

| You… | Action |
|------|--------|
| One large `perception.ts` with mixed routing and decoding | Extract **`normalizers/`** per source family. |
| Policy with deep `m.memory...` reads everywhere | Introduce **`selectors.ts`** and narrow Policy inputs. |
| Learning as a long imperative chain | Move updates into **`reducers.ts`** (or similar) with `switch (obs.kind)`. |
| `execution.ts` with prompts + schemas + giant `switch` | Split **`prompts/`**, **`contracts/`**, **`effects/llm/`**, **`effects/tools/`**. |
| Multi-turn / branchy agent without `flow.md` | Add **`flow.md`** per [4.1 migration](./4.1-flow-md-adoption-migration.md). |

---

## Principles

1. **Do not split for symmetry** — only add folders/files when a module mixes responsibilities or is hard to scan.
2. **Types first** — `types.ts` should define closed unions before large refactors.
3. **Incremental moves** — compile after each step; prefer small PRs internally.

---

## Suggested order of operations

### Phase A: Types and vocabulary

- Ensure `Obs`, intents, execution payloads, and stages are **closed unions** in `types.ts`.
- Fix any stringly `kind` patterns as part of this pass.

### Phase B: Perception and normalizers

- Keep `perception.ts` as an inbox router.
- Move source-specific decoding to `normalizers/user.ts`, `normalizers/tool.ts`, etc.
- Perception returns the same `Obs` union as before (behavior unchanged).

### Phase C: Learning and reducers

- Extract `reduceObs(m, obs)` or per-kind functions in `reducers.ts`.
- `learning.ts` calls reducers and returns new `MentalState`.

### Phase D: Policy and selectors

- Add `readPolicyView(m)` (or multiple selectors) in `selectors.ts`.
- Policy reads only selector output; intents stay domain-named.

### Phase E: Execution split

- Move LLM call sites to `effects/llm/*.ts`.
- Move prompt strings / builders to `prompts/`.
- Move Zod/JSON schemas to `contracts/llm/` and `contracts/tools/`.
- `execution.ts` dispatches by intent to named handlers (or re-exports).

### Phase F: Documentation

- Add or update **`flow.md`**.
- Update imports in tests; keep turn-script assertions on traces.

## Before / after (conceptual)

**Before (flat):**

```txt
agent.ts
types.ts
perception.ts   # everything inline
learning.ts     # long mutations
policy.ts       # deep reads
execution.ts    # prompts + llm + tools in one file
transition.ts
```

**After (non-trivial):**

```txt
agent.ts
flow.md
types.ts
perception.ts
normalizers/user.ts
reducers.ts
selectors.ts
policy.ts
execution.ts          # thin dispatch
effects/llm/...
effects/tools/...
prompts/...
contracts/llm/...
contracts/tools/...
transition.ts
```

---

## Risks

- **Merge conflicts** if multiple authors touch the same giant file — splitting reduces this over time.
- **Circular imports** — keep `types.ts` free of imports from effects; effects import types.
- **Test brittleness** — update test imports when moving modules; behavior should be unchanged.

---

## Checklist

- [ ] `types.ts` closed unions intact
- [ ] Perception → normalizers only; no new cognition writes
- [ ] Learning → reducers; Policy → selectors
- [ ] Execution effects only in `effects/*`; prompts/contracts split when non-trivial
- [ ] Transition still exhaustive on execution results
- [ ] `flow.md` added/updated for non-trivial flow
- [ ] Tests green; traces still assertable
