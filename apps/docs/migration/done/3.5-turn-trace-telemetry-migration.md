# Migration Guide: TurnTrace, Telemetry Redesign, and Manifest Provenance (v3.5)

This guide describes how to migrate to the new telemetry model: one structured **TurnTrace** per turn, no per-module spans, manifest provenance on every trace, and LLM/tool/child calls as sub-spans of the turn. There is **no backwards compatibility** for custom telemetry providers: `ModuleNode` is removed and `onTurnTrace(trace)` is required.

**Related docs:** [How to debug with TurnTrace](../12-how_to_debug_with_turn_trace.md), [APLRET Contracts](../0-aplret_contracts.md) § TurnTrace

---

## Overview

The telemetry system has been redesigned:

- **Per-module spans are removed.** Each turn now emits **one** structured `TurnTrace` record. Module timings are fields inside `TurnTrace.timings`, not separate telemetry nodes.
- **LLM/tool/child calls are sub-spans of the turn.** They are children of `TurnNode`, not of removed module nodes. Child agent execution is linked through `ChildCallNode`.
- **Manifest provenance** (`agentCardSource`, `runtimeManifestSource`, `agentCardHash`, `runtimeManifestHash`) is computed when the session is created, persisted in session/snapshot metadata, restored on every turn-entry path (including resume), and stamped on every TurnTrace.

---

## 1. `ModuleNode` removal (breaking for custom providers)

**Before:** Providers received 7 `ModuleNode` `onNodeStart` / `onNodeEnd` calls per turn.

```typescript
onNodeEnd(node: TelemetryNode): void {
    if (node instanceof ModuleNode) {
        // handle per-module span
    }
}
```

**After:** No `ModuleNode` events. Use `onTurnTrace` for structured per-turn data. Per-module timings are in `trace.timings`; module outputs (intent, shield, etc.) are on the trace object.

```typescript
onTurnTrace(trace: TurnTrace): void {
    // trace.timings has per-module timings (attentionMs, perceptionMs, ...)
    // trace.intent, trace.shield, trace.transition, etc. have module outputs
}
```

---

## 2. `TelemetryProvider` interface change

**Before:**

```typescript
interface TelemetryProvider {
    name: string;
    onNodeStart(node: TelemetryNode): void;
    onNodeEnd(node: TelemetryNode): void;
    onNodeFailure(node: TelemetryNode, error: Error): void;
    onUsageUpdate(node: TelemetryNode, usage: UsageInfo): void;
}
```

**After (breaking; required):**

```typescript
type TelemetryProvider = {
    name: string;
    onNodeStart(node: TelemetryNode): void;
    onNodeEnd(node: TelemetryNode): void;
    onNodeFailure(node: TelemetryNode, error: Error): void;
    onUsageUpdate(node: TelemetryNode, usage: UsageInfo): void;
    /** Called exactly once per turn with the complete TurnTrace. */
    onTurnTrace(trace: TurnTrace): void;
};
```

All providers must implement `onTurnTrace`. `onNodeEnd(TurnNode)` is not used as a second structured turn-export path; the single source of truth for turn data is `onTurnTrace`.

---

## 3. `TurnNode` now carries `TurnTrace`

**Before:** `TurnNode` had no structured data.

```typescript
const turnNode = new TurnNode(turnIndex, parentId);
// turnNode has no structured data
```

**After:** After the turn completes, the assembled TurnTrace is attached to the node.

```typescript
const turnNode = new TurnNode(turnIndex, parentId);
// ... turn runs ...
turnNode.turnTrace = assembledTurnTrace;
```

---

## 4. LLM / tool / child sub-span hierarchy

**Before:**

```
Agent → Turn → Module:execution → LLM call
Agent → Turn → Module:execution → Tool call
```

**After:**

```
Agent → Turn → LLM call (module: 'execution')
Agent → Turn → Tool call (module: 'execution')
Agent → Turn → ChildCallNode → Child Agent → Child Turn...
```

LLM and tool nodes have an optional `module` field for attribution (e.g. `'execution'`). Child dispatch creates a `ChildCallNode` under the parent `TurnNode`; the child task’s `AgentNode` is parented by that `ChildCallNode` via `parentTelemetryNodeId`.

---

## 5. Collecting TurnTrace in tests

**Before:** No structured trace collection from the loop.

```typescript
const result = await runLoop(ctx, M, env, modules);
```

**After:** Opt-in trace collection via `collectTraces: true`. Result includes `traces?: TurnTrace[]`.

```typescript
const result = await runLoop(ctx, M, env, modules, { collectTraces: true });
const traces = result.traces; // TurnTrace[]
expect(traces).toHaveLength(1);
expect(traces[0].intent).toEqual({ kind: 'call_tool' });
expect(traces[0].shield?.action).toBe('pass');
```

---

## 6. Manifest provenance

Provenance is computed when the session is created, persisted in session/snapshot metadata, restored on resume, and stamped on every TurnTrace. In tests you can assert:

```typescript
expect(traces[0].agentCardSource).toBe('defaultPath'); // or 'pathOverride' | 'inline'
expect(traces[0].agentCardHash).toMatch(/^[a-f0-9]{64}$/);
expect(traces[0].runtimeManifestHash).toMatch(/^[a-f0-9]{64}$/);
```

---

## 7. Console output change

**Before:** Noisy per-module output.

```
[START] TURN ID=...
[START] MODULE ID=... (attention)
[END] MODULE (attention) ID=... Duration=2ms
[START] MODULE ID=... (perception)
[END] MODULE (perception) ID=... Duration=1ms
... (5 more per turn)
[END] TURN ID=... Duration=150ms
```

**After:** One compact line per turn (from `ConsoleProvider.onTurnTrace`).

```
[TURN] Turn 1 | stage: idle → running | intent: call_tool | shield: pass | transition: await_tool | total: 150ms | tokens: 1234 | cost: $0.0012
```

---

## 8. New exports

From `@a2arium/callagent-core`:

- **Types:** `TurnTrace`, `TurnTimings`, `TurnUsage`, `PendingSummary`, `ShieldTrace`, `ManifestProvenance`, `ManifestSource`, `JsonValue`
- **Collection:** `TurnTraceCollector`
- **Provenance:** `resolveManifestProvenance`, `computeStableHash`, `validateManifestIdentity`
- **Nodes:** `ChildCallNode` (in addition to existing `AgentNode`, `TurnNode`, `LLMNode`, `ToolNode`)

---

## 9. Removed exports

- **`ModuleNode`** — No longer used; module timings are in `TurnTrace.timings`.
- **`WorkflowNode`** — Was not part of the stable public API; internal to the bridge provider.

---

## Summary

| Change | Action |
|--------|--------|
| Custom `TelemetryProvider` | Add required `onTurnTrace(trace: TurnTrace)`; remove any `ModuleNode`-specific logic. |
| Relying on per-module spans | Use `trace.timings` and `trace.intent` / `trace.shield` / etc. in `onTurnTrace`. |
| Tests that need turn data | Call `runLoop(..., { collectTraces: true })` and assert on `result.traces`. |
| Importing `ModuleNode` or `WorkflowNode` | Remove import; use `TurnTrace` and `ChildCallNode` as needed. |
