# Migration: 4.0 — TaskContext goals, episodic, input guards, and createAgent typing

This document is **self-contained**: you can migrate agent and integration code using only what follows.

## What changed (summary)

- **Runtime behavior** of goals, episodic append, input guards, and `createAgent` is **unchanged**.
- **TypeScript** types were tightened. Code that compiled before only because values were typed as `any`, or because stubs used loose signatures, may now **fail typecheck**.
- **No database or config migration** is required.

## Who needs to act

| You are… | Action |
|----------|--------|
| Calling `ctx.goals.*` or `ctx.episodic.add` in `handleTask` or tests | Align arguments and filters with the shapes below (or import the exported helper types). |
| Implementing a **mock** or **fake** `TaskContext` | Update `goals` / `episodic` method signatures to match. |
| Using **`createAgent`** with top-level `attention`, `policy`, etc. | Ensure each supplied field is a **function** with the correct **module signature**; invalid shapes now error earlier. |
| Using **`isChildCompletionInput`**, **`isToolCompletionInput`**, **`isDirectInput`**, **`isExternalEventInput`** | Prefer passing **`unknown`** (e.g. resume payloads) into these guards instead of `any`. |

If you only use JavaScript, or you do not touch these APIs, you can ignore this migration.

## Canonical type shapes (copy of the contract)

These definitions match the framework. If your editor shows the same fields, you are aligned.

### Goal vocabulary

```ts
type GoalId = string;
type GoalType = 'long' | 'mid' | 'short';
type GoalStatus = 'active' | 'blocked' | 'done' | 'failed' | 'dropped';

type GoalContext = {
  tags?: string[];
  deadlineTs?: string;
  budget?: { timeMs?: number; cost?: number };
  metadata?: Record<string, unknown>;
};

type GoalNode = {
  id: GoalId;
  title: string;
  type: GoalType;
  priority: number; // 0..1
  status: GoalStatus;
  parentId?: GoalId;
  order?: number;
  context?: GoalContext;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
};
```

### `ctx.goals.add` input (`TaskContextGoalAddInput`)

The framework fills timestamps and defaults when applying through `addGoal`. Callers supply at least **`title`**.

```ts
type TaskContextGoalAddInput = {
  id?: GoalId;
  title: string;
  type?: GoalType;
  priority?: number;
  parentId?: GoalId;
  context?: GoalContext;
};
```

**Migration examples**

- **Before (loose):** `await ctx.goals.add(myGoal as any)` where `myGoal` had no `title`.
- **After:** `await ctx.goals.add({ title: 'Ship release', type: 'short' })`  
  If you already had a full `GoalNode`, pass a **narrow** object: `{ id, title, type, priority, parentId, context }` — still must include **`title`**.

### `ctx.goals.update` patch (`TaskContextGoalUpdatePatch`)

Equivalent to `Partial<Omit<GoalNode, 'id' | 'createdAt'>>`: you may patch any goal field **except** `id` and `createdAt` (those are owned by the store).

**Example:** `await ctx.goals.update('g_1', { status: 'done' })`

### `ctx.goals.read` filter (`TaskContextGoalsReadFilter`)

```ts
type TaskContextGoalsReadFilter = {
  status?: GoalStatus;
  parentId?: GoalId;
  type?: GoalType;
};
```

**Migration:** replace ad hoc filters (extra keys, `any`) with this object. Only these three filter keys are typed; if you relied on undocumented filter fields, move that logic to application code after calling `read` with a supported filter.

### `ctx.goals.clear` predicate

- **Before:** `(g: any) => boolean`
- **After:** `(g: GoalNode) => boolean`

**Example:** `await ctx.goals.clear((g) => g.status === 'failed')`

### `ctx.episodic.add` (`EpisodicEvent`)

```ts
type EpisodicEvent = {
  t: number;
  obs: unknown;
  act: unknown;
  rew?: number;
  out?: unknown;
};
```

**Example:** `ctx.episodic.add({ t: Date.now(), obs: observation, act: proposedAction })`

## `TaskContext.goals` method cheat sheet

When `goals` exists on the context:

| Method | Arguments | Returns (may be sync or Promise) |
|--------|-----------|----------------------------------|
| `add` | `TaskContextGoalAddInput` | `GoalId` |
| `update` | `id: GoalId`, `patch: TaskContextGoalUpdatePatch` | `void` |
| `remove` | `id: GoalId` | `void` (framework maps this to failing/removing the goal per engine behavior) |
| `clear` | optional `(g: GoalNode) => boolean` | `void` |
| `read` | optional `TaskContextGoalsReadFilter` | `GoalNode[]` |

## Input discriminators (guards)

These functions are **unchanged at runtime**. Their parameters are typed as **`unknown`**.

- `isChildCompletionInput(x: unknown): x is ChildCompletionInput`
- `isToolCompletionInput(x: unknown): x is ToolCompletionInput`
- `isDirectInput(x: unknown): x is DirectInput`
- `isExternalEventInput(x: unknown): x is ExternalEventInput`

**Payload shapes (for your own narrowing):**

```ts
type ChildCompletionInput = {
  kind: 'child';
  token: string;
  childTaskId?: string;
  agentId?: string;
  result: unknown;
};

type ToolCompletionInput = {
  kind: 'tool';
  token: string;
  toolId?: string;
  result: unknown;
};

type DirectInput = { kind: 'input'; token?: string; value: unknown };

type ExternalEventInput = { kind: 'external'; event: unknown };
```

**Migration:** if you had `isChildCompletionInput(x as any)`, use `isChildCompletionInput(x as unknown)` or type the variable as `unknown` from the boundary (HTTP, queue, resume handler).

## `createAgent` top-level module sugar

You may pass loop modules either under **`loop.modules`** or as **top-level** fields on the options object:

`attention`, `perception`, `learning`, `policy`, `shield`, `execution`, `transition`

They are **merged** into `loop.modules` when present. Each must be a **function** matching the corresponding slot on **`Modules<…>`** for your agent’s type parameters (`Sensory`, `Obs`, etc.).

**What breaks typecheck now**

- A top-level field that is **not** a function (typo, wrong export).
- A function whose parameters/return type do not match the expected module signature.

**Fix:** correct the export or move the implementation under `loop: { modules: { … } }` with an explicitly typed partial modules object.

## Step-by-step migration checklist

1. **Search** your repo for `goals.add`, `goals.update`, `goals.read`, `goals.clear`, `episodic.add`, and test doubles of `TaskContext`.
2. **`add`:** ensure every call includes **`title: string`**; add `type`, `priority`, `parentId`, `context` only when needed.
3. **`update`:** use `TaskContextGoalUpdatePatch` (no `id` / `createdAt` in the patch).
4. **`read`:** use only `status`, `parentId`, `type` in the filter object.
5. **`clear`:** type the predicate parameter as **`GoalNode`**.
6. **`episodic.add`:** pass an **`EpisodicEvent`** (`t`, `obs`, `act`, optional `rew`, `out`).
7. **Guards:** pass **`unknown`** into `isChildCompletionInput` / `isToolCompletionInput` / `isDirectInput` / `isExternalEventInput`.
8. **`createAgent`:** fix any top-level module field that is not a correctly typed module function.
9. Run your project’s typecheck (`tsc`, IDE, CI) until clean.
