# Migration Guide: Removal of `ctx.vars`

## Overview
As part of the recent architectural changes and in accordance with the `0-aplret_contracts.md` V2 specifications, the internal memory proxy wrapper (`ctx.vars`) has been completely removed from the A2A (Agent-to-Agent) and Task Execution frameworks.

The removal enforces a robust and predictable separation between persistent data memory (Semantic/Episodic) and execution orchestration state (Control variables).

## What Changed?
1. **`ctx.vars` is no longer available**. Any attempt to read from or write to `ctx.vars` inside an execution step or task will result in an `undefined` property error or silent failure.
2. The proxy mapping logic that asynchronously synchronized `ctx.vars` with `env.memory.vars` has been eliminated to reduce race conditions and complex CAS failures during high-throughput orchestration.
3. Cross-turn state and Agent-to-Agent data passing are now handled strictly through **Memory Facades** and **Control Variables**.

## How to Migrate 

### 1. Migrating Persistent Agent State 
If your agent previously relied on `ctx.vars` to hold state across multiple turns for the *same* execution session (e.g. keeping track of a list of collected items, flags, or ongoing reasoning tasks), you must migrate directly to structured **Semantic Memory**.

**Before (Deprecated)**
```typescript
// Inside agent module
export const execution = async (ctx, env, action) => {
    // Reading state
    const collectedFiles = ctx.vars.collectedFiles || [];
    
    // Writing state
    ctx.vars.collectedFiles = [...collectedFiles, newFile];
}
```

**After (New Pattern)**
```typescript
// Inside agent module
export const execution = async (ctx, env, action) => {
    // Read state using semantic memory
    const memoryRecord = await ctx.memory.semantic.readItems({ tag: 'collected_files_state' });
    const collectedFiles = memoryRecord?.[0]?.value?.files || [];
    
    // Write state
    await ctx.memory.semantic.add({ 
        id: 'collected_files_state',
        value: { files: [...collectedFiles, newFile] },
        tags: ['collected_files_state']
    });
}
```
*Note: Any data placed into `ctx.memory.semantic` will persist across executions depending on your underlying engine, so make sure to manage tags and limits intentionally.*

### 2. Migrating Agent-to-Agent Tokens & Control Flow
If your parent agent utilized `ctx.vars` to pass control tokens or specific execution instructions down to a child agent and subsequently retrieve them, you must now use `options.setToken` and `controlVars`.

**Before (Deprecated)**
```typescript
// Parent Agent
export const execution = async (ctx, env, action) => {
    // Setting control data into vars
    ctx.vars.pendingChildTask = 'calculate-metrics';
    
    // Delegating task
    return ctx.sendTaskToAgent('metrics-agent', { input: {} });
}

// Resuming...
export const completion = async (ctx, env, result) => {
    // Comparing using vars
    if (ctx.vars.pendingChildTask === 'calculate-metrics') {
        // ...
    }
}
```

**After (New Pattern)**
When invoking a child agent, provide the `setToken` option. The task engine will assign that token into the active `controlVars` automatically, which is preserved exactly for the duration of the child delegation.

```typescript
// Parent Agent
export const execution = async (ctx, env, action) => {
    // Token automatically set in control state
    return ctx.sendTaskToAgent('metrics-agent', { input: {} }, { 
         setToken: 'calculate-metrics',
         autoClearToken: true // Recommended to avoid leaking token across new branches
    });
}

// Resuming...
export const executionLoopResume = async (ctx, env, action) => {
    // Check pending state if needed using controlVars directly
    if (env.pending?.controlVars?.['calculate-metrics']) {
      // Logic for resumed child
    }
}
```

## Summary
By enforcing strict separation between A2A communication state (`controlVars`) and persistent task knowledge (`ctx.memory.semantic`), the framework ensures higher orchestration stability. Update all execution, policy, and translation layers to drop `ctx.vars` entirely.
