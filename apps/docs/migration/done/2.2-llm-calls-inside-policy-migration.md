# Migration Guide: Removal of `llm` from Pure Modules (v2.2)

> [!IMPORTANT]
> The `llm` parameter (of type `PureLLMPort`) has been **completely removed** from all pure module signatures (`policy`, `perception`, `learning`, `attention`, `shield`, `transition`, `extrinsicReward`, `intrinsicReward`).
> All LLM calls must now occur exclusively within the `execution` module.

## Why

APLRET architecture enforces a strict "Single Effect Boundary" (Rule 3) and "Sync, M-only Policy" (Rule 5). Calling an LLM is a side effect (network request, latency, non-determinism). Passing `PureLLMPort` to pure data-transformation modules like `policy` or `perception` encouraged inline reasoning that destroyed the predictability and determinism of the cognitive loop.

All agent cognition must follow the canonical data flow:
`Intent (Policy) → Effect (Execution) → Observation (Transition) → Inbox → Perception → MentalState (Learning) → (Policy)`

## What Changed?

1. The `llm?: PureLLMPort` property was removed from `PolicyFn` and all pure module type definitions (`core/loop/oneTurn.ts`).
2. Agents relying on inline LLM reasoning in `policy`, `perception`, or `learning` will now fail at compile time.
3. The framework utility `extractPureLLMPort` has been deleted.

## How to Migrate 

If your agent previously called the LLM inline inside `policy` or `perception`, you must unroll that operation into a standard multi-turn intent flow.

### Migrating Inline Policy Reasoning

The canonical intent for LLM reasoning is `answer_with_llm`.

**Before (Deprecated & Violating Purity)**
```typescript
policy: async (m, mem, llm) => {
  const answer = await llm.call("Should I proceed?");
  return answer[0]?.content.includes("Yes") ? { kind: 'proceed' } : { kind: 'abort' };
}
```

**After (New Canonical Pattern)**
```typescript
// 1. Policy decides it needs to reason — sync, reading only MentalState
policy: (m) => {
  if (!m.memory.scratch?.evalResult) {
    return { kind: 'answer_with_llm', query: 'Should I proceed?' };
  }
  return m.memory.scratch.evalResult === 'yes' ? { kind: 'proceed' } : { kind: 'abort' };
}

// 2. Execution handles the LLM call — the sole effect boundary
execution: async (intent, ctx) => {
  if (intent.kind === 'answer_with_llm') {
    const res = await ctx.llm.call(intent.query);
    return {
      action: { kind: 'internal', done: false }, // Loops back around
      result: { status: 'ok', data: { answer: res[0]?.content } }
    };
  }
}

// 3. Transition converts the result into an Observation
transition: (_env, exec, _m, _mem) => {
  if (exec.result.data?.answer) {
    return {
      kind: 'continue',
      observations: [{
        source: 'internal',
        kind: 'llm.answered',
        payload: { answer: exec.result.data.answer }
      }]
    };
  }
  return { kind: 'complete', result: { ok: true } };
}

// 4. Learning stores it in MentalState for the next turn
learning: (prev, _action, obs) => {
  if (obs?.answer) {
    const next = { ...prev, memory: { ...prev.memory } };
    const scratch = { ...((next.memory.scratch || {}) as Record<string, unknown>) };
    scratch.evalResult = String(obs.answer).toLowerCase().includes('yes') ? 'yes' : 'no';
    next.memory.scratch = scratch;
    return next;
  }
  return prev;
}
```

### Migrating Perception Extraction

**Before (Deprecated)**
```typescript
perception: async (env, alpha, mem, llm) => {
  const raw = env.inbox.current[0]?.payload?.value;
  const extracted = await llm.call(`Extract name from: ${raw}`);
  return { name: extracted[0]?.content };
}
```

**After (New Pattern)**
1. `perception` returns the raw text.
2. `learning` marks it as pending extraction in `m.memory.scratch`.
3. `policy` yields an `extract_name` intent.
4. `execution` uses `ctx.llm.call` with structured output schemas to safely parse the name.
