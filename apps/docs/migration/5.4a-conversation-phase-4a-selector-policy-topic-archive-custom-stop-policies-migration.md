# 5.4a — Migration (incremental)

This document is updated as Phase 4a ships. **Sub-phase 5.4a** covers foundation items, selector policy, topic archive, and `TopicStopPolicy` (see the implementation spec).

## Typed close / archive receipts (5.4a.0.iii)

- **`CloseConversationReceipt`** and **`ArchiveConversationReceipt`** are now **discriminated unions** with `status: 'ok' | 'rejected'`.
- On success: `status: 'ok'` and the previous fields (`ref`, `closed`, `archived`, …).
- On failure: `status: 'rejected'` and `error: ConversationError` (no `throw new Error('…')` for public vocabulary).
- **Migrate callers** from `if (!receipt.closed)` to `if (receipt.status !== 'ok' || !receipt.closed)` (and similarly for `archive`).

## ConversationError changes

- **Removed:** `ThreadNotClosed`, `ArchiveUnsupportedForTopics`.
- **Added:** `ConversationNotClosed`, `ConversationNotFound`, `NoEligibleRecipients`.
- **Rename:** use `ConversationNotClosed` where you previously handled `ThreadNotClosed` (e.g. `archive` on an open thread/topic).
- Fan-out when **no recipient** could accept delivery now uses **`NoEligibleRecipients`** instead of overloading **`ThreadBusy`**.

## Topic archive

- **`close(topicRef, { archiveAfter: true })`** is supported: closes the topic, then archives it, emits **`topic.archived`** to members.
- **`ctx.conversation.archive(topicRef, …)`** is allowed (signature widens from `ThreadRef` to **`ConversationRef`**).

## Observations

- **`topic.archived`** payload is defined in `ConversationPayloadSchema` (see `packages/core/src/types/observation.ts`).

## `selector_policy` topic selector (5.4a.1–5.4a.2)

- **`TopicSelectorSchema`** adds **`kind: 'selector_policy'`** with `policyId` and optional `params` (`JsonValue`).
- Register implementations with **`TopicSelectorPolicyRegistry`** (`createTopicSelectorPolicyRegistry()`); **`ConversationService`** uses **`topicSelectorPolicyRegistry`** from **`ConversationServiceDeps`** (defaults to an empty registry).
- New **`ConversationError`** branches: **`SelectorPolicyNotRegistered`**, **`PolicyParamsInvalid`**, **`PolicyInternalError`** (optional `policyId` on each).
- Successful / partial **`FanoutSendReceipt`** may include **`selectorPolicyTrace`** (`policyId`, `result`, optional `paramsHash`).
- **`conversation_messages.selector_policy_id`** (nullable) stores the policy id for `selector_policy` posts; **`MessageLogAppendParams`** / **`MessageLogRecord`** expose **`selectorPolicyId`**.
- **`outbound.committed`** observations for topics may include **`selectorKind`**, and for **`selector_policy`** also **`selectorPolicyId`** and **`selectorParamsHash`**.
- Canonical **`paramsHash`** uses `canonicalJsonStringify` + SHA-256 (`packages/core/src/internal/util/canonicalJson.ts`).

## TurnTrace `stopPolicy` (post-append stop rules)

- Successful topic **`post`** receipts (`accepted` / `partial`) may include **`stopPolicyTrace`**: `result: 'stop' | 'rejected'` (omitted when evaluation is skipped or every rule continues).
- **`TurnTrace.stopPolicy`** mirrors that payload when the harness / runtime stamps topic posts (see `topicTurnTraceStamp.ts` + `loopRunner`).

## Runtime manifest: topic lifecycle sweeper

- **`communication.topicSweeper`** (optional, `.strict()` object):
  - **`intervalMs`** (positive int): while a **`runLoop`** is active, **`TaskEngine.triggerTopicLifecycleSweep`** may run when at least this many milliseconds of wall time have passed since the last sweep (gating is evaluated at the **start of each loop turn**; the first check may run immediately).
  - **`autoArchiveAfterMs`** (positive int): passed through to the sweeper (closed topics older than this are archived).
  - **`batchSize`** (optional positive int, max 10_000): sweep batch; default **100** when omitted.
- Sweeps are invoked only when **`EngineLocator`** holds a **`TaskEngine`** that implements **`triggerTopicLifecycleSweep`** (e.g. CLI / streaming runner). Pure **`TestHarness.runTurn`** loops do not register an engine unless tests call **`EngineLocator.setEngine`**.
- Manual **`tickTopicLifecycleSweep`** / **`triggerTopicLifecycleSweep`** are unchanged.

## Harness policy purity (`policyPurityStrict`)

- **`HarnessConfig.policyPurityStrict`** defaults to **`true`**: topic **`selector_policy`** and custom **stop** policies invoked via the harness **`ConversationService`** must not call **`Date.now`**, **`Date#getTime`**, or **`Math.random`** inside **`select`** / **`evaluate`** (use framework **`nowIso`** / **`Clock`**).
- Set **`policyPurityStrict: false`** in **`createTestHarness(..., { policyPurityStrict: false })`** only when a test intentionally exercises impure policies.

## Lint: `ConversationService` throws

- Root **`.eslintrc.cjs`** adds a **`no-restricted-syntax`** override for **`packages/core/src/internal/conversation/ConversationService.ts`** banning **`throw new Error(...)`** (in addition to the existing **`ctx.vars.*`** assignment rule for that file).

## Test harness (Phase 4a)

- **`HarnessConfig.maxTurns`** is passed into each **`runTurn()` → `runLoop`** (was previously fixed at `1`).
- **`HarnessConfig.topicSweeper`** — same shape as manifest **`communication.topicSweeper`**; applies the same turn-aligned sweep gating during **`runLoop`** when **`EngineLocator`** holds a **`TaskEngine`**.
- **`harness.registerTopicSelectorPolicy(policy)`** / **`harness.registerStopPolicy(policy)`** — register on the same **`ConversationService`** instance as **`ctx.conversation`** (respects **`policyPurityStrict`** wrapping).
- **`harness.setCommunicationManifest`** / **`setCommunicationCapabilities`** — deep-merge **`AgentRuntimeManifest.communication`** fields into harness state (TTL, auto-join, **`topicSweeper`** merge with **`HarnessConfig`**).
- **`harness.useEventBusAdapter`** / **`useMessageLogAdapter`** — optional **`publishConversationEvent`** and **`MessageLog`** overrides for adapter-style tests.
- **`HarnessConfig`**: optional aliases **`strictPolicies`** and **`__strict__`** for **`policyPurityStrict`**.
