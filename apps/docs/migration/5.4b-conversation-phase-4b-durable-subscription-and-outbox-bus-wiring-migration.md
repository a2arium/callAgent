# 5.4b — Migration (incremental)

This document tracks **Phase 4b**: durable subscription port, typed event bus envelope, outbox → `IEventBus` dispatch, cursor / dead-letter persistence, and backpressure trace hooks.

## `DurableSubscription` (public seam)

- New types live under **`packages/core/src/public-types/messageLog/`** (`DurableSubscription`, related schemas).
- **Naming:** the public surface is **`DurableSubscription`** (no `I-` prefix), consistent with **`MessageLog`** and project `type`-alias conventions.

## `BusEvent` / `IEventBus`

- **`IEventBus.publish`** accepts a **`BusEvent`** (see **`BusEventSchema`** / **`CloudEventSchema`** in **`public-types/eventbus/`**).
- Use **`createBusEvent({ channel, cloud: { id, type, source, time, datacontenttype, data } })`** and **`busEventData(event)`** for CloudEvent `data` (`packages/core/src/eventbus/busEventHelpers.ts`).
- **`createInMemoryEventBus()`** is the supported factory; the former **`eventBus`** singleton export from **`inMemoryEventBus`** is **removed**. Composition roots must hold their own bus instance (e.g. **`TaskEngine`** owns **`readonly eventBus`**; optional **`opts.eventBus`** override).

## `OutboxPublisher`

- Construct with **`{ eventBus, getPrisma?, maxRetries?, pollIntervalMs? }`**. Dispatch calls **`eventBus.publish`** with a **`BusEvent`** (no log-only path).
- The **`outboxPublisher`** module singleton is **removed**; **`TaskEngine`** constructs **`OutboxPublisher`** when **`DISABLE_OUTBOX_PUBLISHER`** is unset. Tests and tooling should rely on **`process.env.DISABLE_OUTBOX_PUBLISHER`** or **`TaskEngine.stopOutboxPublisher()`** (via **`EngineLocator.getEngine()`** where applicable).

## Prisma / SQL (`memory-sql`)

- Migration adds **`outbox.retry_count`**, **`DurableSubscriptionCursor`**, **`ConversationDeadLetter`**, and widens message-log delivery status to include **`buffered`**, **`throttled`**, **`paused`**, **`dead-lettered`** (see migration folder under **`packages/memory-sql/prisma/migrations/`**).
- Regenerate clients: **`yarn prisma generate`** in **`packages/core`** and **`packages/memory-sql`** after pulling.

## Backpressure & traces

- **`BackpressureManager`** participates in topic fan-out; **`TurnTrace`** may include optional **`backpressure`**.
- **`ConversationService`** deps may include **`backpressureManager`**; HTTP **`post`** hooks can integrate via **`setTopicPostBackpressureSink`** / **`ApiBinder`** as wired in **`TaskEngine`**.

## Test harness & invites

- **`publishConversationEvent`** and **`runInviteStartupSweep`** must publish **`BusEvent`** envelopes (same shape as **`TaskEngine`**), not raw **`(channel, payload)`** to **`publish`**.
- **`InviteDeliveryCoordinator.start` / `stop`** are **async**; tests should **`await coordinator.start()`** before relying on delivery.

## Integrator checklist

1. Replace any import of **`eventBus`** / **`outboxPublisher`** singletons with injected instances or **`createInMemoryEventBus()`**.
2. Replace **`bus.publish(channel, payload)`** with **`bus.publish(createBusEvent({ channel, cloud: { …, data: payload } }))`** (or a shared helper).
3. Run SQL migration + **`prisma generate`** if you use the memory SQL store.
4. Teardown: stop outbox via **`TaskEngine.stopOutboxPublisher()`** (or keep **`DISABLE_OUTBOX_PUBLISHER=1`** in tests).
