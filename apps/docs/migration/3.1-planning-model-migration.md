# Migration Guide: 3.1 Planning Model (`M.plans`)

This guide explains how to migrate your agents to the new APLRET Planning Model introduced in version 0.2.x.

## Overview
The planning model has been refactored to support multi-step reasoning. The `MentalState` now includes a `plans` property, which is the single source of truth for all complex reasoning flows. 

### Key Changes
1. **MentalState**: Added `plans: PlanState`.
2. **Observations**: New internal observation kinds: `plan.proposed`, `plan.updated`, `plan.step.updated`.
3. **Schemas**: Strict Zod validation for all plan-related data.

## Migration Steps

### 1. Update MentalState Usage
If you were previously storing plans in custom `scratch` or `window` properties, you should now move them to `M.plans`.

**Old:**
```typescript
M.memory.scratch = { currentPlan: { ... } };
```

**New:**
```typescript
M.plans = { 
    plans: { 
        'my-plan-id': { ... } 
    }, 
    activePlanId: 'my-plan-id' 
};
```

### 2. Update Plan Generation
Plans must now be emitted as `internal/plan.proposed` observations from the `Execution` module or via tool results. They will be validated by the `Perception` layer using `PlanSchema`.

### 3. Use Strongly Typed Schemas
Import `PlanSchema` and `PlanStateSchema` from `@a2arium/callagent-core` to ensure your plan data is valid.

```typescript
import { PlanSchema } from '@a2arium/callagent-core';

const plan = PlanSchema.parse(myData);
```

## Backward Compatibility
> [!WARNING]
> This change is **not** backward compatible. Existing snapshots containing old plan structures in `scratch` will still work, but they will not be managed by the new planning system. We recommend clearing old snapshots or manually migrating the state.
