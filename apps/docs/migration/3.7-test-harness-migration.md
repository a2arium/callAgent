# Migration guide: Test Harness and deterministic testing (v3.7)

This guide helps you migrate agent tests after the **3.7** work on the official APLRET test harness. It replaces manual `runLoop()` / `oneTurn()` invocations with a canonical `createTestHarness()` factory, provides deterministic LLM/Tool stubs, and standardises turn-by-turn assertions via `TurnAssertionContext`.

There is **no backward compatibility** guarantee for the items below: plan a normal upgrade pass (bump package, fix compile errors, adjust tests).

**Related docs:** [How to test APLRET agents](../11-how_to_test_aplret_agents.md) · [How to debug with TurnTrace](../12-how_to_debug_with_turn_trace.md) · [APLRET contracts](../0-aplret_contracts.md) · [Specification (framework)](../todo/3.7-test-harness.md)

---

## Overview

### Who is affected

| You… | Action |
|------|--------|
| Call `runLoop()` or `oneTurn()` directly in tests | **Replace** with `createTestHarness(modules)` + `.runTurn()`. |
| Construct `ctx: any` manually for tests | Use `createTestHarness()` — builds full `TaskContext` internally. |
| Push observations directly into `env.inbox.current` | Use `harness.injectObservation()` / `.injectUserInput()` / `.injectToolCompleted()`. |
| Mock LLM callers with `jest.fn()` or inline stubs | Use `harness.llmStub()` (FIFO queue + call recording). |
| Assert raw JSON paths on `result.exec.result.data`, `result.m.*` | Use `harness.expectTurn(t => t.expectIntent(...))` and typed assertion helpers. |
| Use `as any` casts for `MentalState`, `EnvironmentState`, modules | Use `harness.seedMentalState()` with `DeepPartial` — typed, no casts needed. |
| Return `{ result: { success: true }, transition: { kind: ... } }` from execution mocks | Return canonical `ExecOutcome`: `{ action, result: { status: 'ok', data } }`. Transition is a **separate module**. |
| Throw `InvariantError` with `(message, code, detail)` args | Constructor takes a single `InvariantErrorPayload` object: `new InvariantError({ code, message, detail })`. |

## 1. Initialising the Harness (replaces manual setup)

**Before (deprecated):**
```typescript
// Type-unsafe: all 'any' casts, manual inbox, no real context
const ctx: any = { task: { id: 't', input: 'hello' }, reply: jest.fn() };
const M: any = initialM(ctx);
M.memory.longTerm.semantic.concepts = [{ id: 'old', data: { x: 1 } } as any];
const env = baseEnv({ inbox: undefined as any });

const modules = { /* manually assembled */ };
const result = await runLoop(ctx, M, env, modules);
```

**After (v3.7):**
```typescript
import { createTestHarness } from '@a2arium/callagent-core';

// Safe, deterministic, strictly typed
const harness = createTestHarness(modules)
    .seedMentalState({
        memory: {
            longTerm: {
                semantic: { concepts: [{ id: 'old', data: { x: 1 } }] }
            }
        }
    });
```

`createTestHarness(modules)` does all of the following automatically:
- Constructs a complete `TaskContext` (reply, LLM, tools, memory, artifacts, etc.)
- Initialises `MentalState` via `initialM(ctx)`
- Normalises the observation inbox
- Sets up trace collection

## 2. Module Signatures

This is the most common migration failure. Your module mocks **must** match these exact signatures from `Modules<Sensory>`:

| Module | Signature |
|--------|-----------|
| `attention` | `(mPrev: MentalState, env: EnvironmentState, mem: MemoryReader) => Alpha` |
| `perception` | `(env: EnvironmentState, alpha: Alpha, mem: MemoryReader) => Obs` |
| `learning` | `(mPrev: MentalState, prevAction: Intent \| undefined, o: Obs, mem: MemoryReader, writer: MemoryWriter, rPrev?: number) => MentalState` |
| `policy` | `(m: MentalState, mem: MemoryReader) => Intent \| Array<{ action: Intent; prob: number }>` |
| `shield` | `(m: MentalState, a: Intent, mem: MemoryReader) => ShieldOutcome` |
| `execution` | `(a: Intent, ctx: TaskContext, mem: MemoryReader, m: MentalState) => Promise<ExecOutcome>` |
| `transition` | `(env: EnvironmentState, exec: ExecOutcome, m: MentalState, mem: MemoryReader) => TransitionOut` |

> [!WARNING]
> **`execution` and `transition` are separate modules.** Older tests often embedded the transition decision inside the execution return value. This no longer works — `execution` returns `ExecOutcome` (action + result), and `transition` decides the next state.

## 3. `ExecOutcome` Return Shape

**Before:**
```typescript
// OLD: mixed execution + transition, wrong shape
execution: async (a) => ({
    action: a,
    result: { success: true },
    transition: { kind: 'complete' }
})
```

**After:**
```typescript
import type { ExecOutcome, ExecResult } from '@a2arium/callagent-core';

execution: async (a, ctx, mem, m): Promise<ExecOutcome> => ({
    action: a,
    result: { status: 'ok', data: null } as ExecResult,
})
```

The `ExecResult` type uses `status: 'ok' | 'error'` — **not** `success: boolean`.

## 4. Running Turns and Injecting Observations

**Before:**
```typescript
env.inbox.current.push({ source: 'user', kind: 'input.provided', payload: { value: 'hello' } });
const result = await runLoop(ctx, M, env, modules);
expect(result.outcome.kind).toBe('await_input');
```

**After:**
```typescript
await harness.injectUserInput('hello').runTurn();

harness.expectTurn(t => t.expectTransition('await_input'));
```

Available injection methods:
- `injectUserInput(value)` — creates `source: 'user', kind: 'input.provided'`
- `injectToolCompleted({ token, tool, result })` — creates `source: 'tool', kind: 'tool.completed'`
- `injectToolFailed({ token, tool, error })` — creates `source: 'tool', kind: 'tool.failed'`
- `injectChildCompleted({ token, agentId, result })` — creates `source: 'child', kind: 'child.completed'`
- `injectChildFailed({ token, agentId, error })` — creates `source: 'child', kind: 'child.failed'`
- `injectObservation(obs)` — raw observation injection (validated via `normalizeObservationInbox`)

## 5. Typed Assertions (`TurnAssertionContext`)

**Before:**
```typescript
expect(result.traces[0].intent.kind).toBe('call_tool');
expect(result.traces[0].transition.kind).toBe('await_tool');
expect(result.traces[0].transition.token).toBe('123');
```

**After:**
```typescript
harness.expectTurn(t => {
    t.expectIntent('call_tool');
    t.expectTransition('await_tool');
    t.expectAwaitToken('123');
});
```

Full list of assertion helpers:

| Method | Checks |
|--------|--------|
| `expectIntent(kind)` | `trace.intent?.kind === kind` |
| `expectShield(action)` | `trace.shield?.action === action` |
| `expectTransition(kind)` | `trace.transition?.kind === kind` |
| `expectAwaitToken(token)` | `trace.transition?.token === token` |
| `expectStageTransition(from, to)` | `trace.stageTransition?.from === from && to` |
| `expectStageBefore(stage)` | `trace.stageBefore === stage` |
| `expectStageAfter(stage)` | `trace.stageAfter === stage` |
| `expectInboxKinds(kinds)` | `trace.inboxCurrent` contains all specified kinds |
| `expectMemoryChanged()` | `mentalStateBeforeHash !== mentalStateAfterHash` |

All assertion methods throw `HarnessAssertionError` (not generic `Error`) with `expected`, `actual`, and `turn` fields. All methods return `this` for chaining.

Top-level harness assertions:
- `harness.expectComplete()` — asserts `transition.kind === 'complete'`
- `harness.expectFail()` — asserts `transition.kind === 'fail'`

## 6. LLM & Tool Stubs

Stubs are built automatically when calling `createTestHarness()`. No need to `jest.fn()` them.

**Before:**
```typescript
const llmCall = jest.fn(async () => [{ role: 'assistant', content: 'hello' }]);
const ctx: any = { llm: { call: llmCall } };
```

**After:**
```typescript
const harness = createTestHarness(modules);

// Queue the next LLM response (FIFO)
harness.llmStub().enqueue({ content: 'hello', role: 'assistant' });

// After runTurn(), inspect what was called
const calls = harness.llmStub().getCalls();
expect(calls[0].message).toBe('hello query');
```

> [!IMPORTANT]
> The `DeterministicLLMStub` implements `getHistoryMode()` (returns `'stateless'`). This means the default `answer_with_llm` execution module treats the LLM as "configured" and will call `ctx.llm.call()`. If you need to test the unconfigured/echo fallback path, provide a custom `execution` module.

Tool stubs use `register`/`invoke`:
```typescript
harness.toolStub().register('myTool', { result: 'ok' });
// then in execution: ctx.tools.invoke('myTool', args) returns { result: 'ok' }
```

## 7. Error Assertions

### InvariantError

**Before:**
```typescript
// WRONG constructor (no longer works)
throw new InvariantError('bad input', 'TOKEN_MISMATCH', { type: 'token_validation' });
```

**After:**
```typescript
// Correct: single InvariantErrorPayload object
throw new InvariantError({
    code: 'TOKEN_MISMATCH',
    message: 'bad input',
    detail: { type: 'token_validation', category: 'input', reason: 'missing' },
});
```

Testing invariant errors in the harness:
```typescript
await harness.runTurn();

harness.expectInvariantError(e => {
    expect(e.code).toBe('TOKEN_MISMATCH');
    expect(e.message).toBe('bad input');
});
```

### ModuleExecutionError

```typescript
harness.expectModuleError(e => {
    expect(e.module).toBe('perception');
    expect(e.originalMessage).toContain('null reference');
});
```

## 8. Resume Flow Testing

Tests validating async callback states (child/tool await → resume) use `lastAwaitToken()`:

```typescript
// Turn 1: ends in await_tool
await harness.injectUserInput('search for X').runTurn();
harness.expectTurn(t => t.expectTransition('await_tool'));

// Resume with the tool result using the captured token
const token = harness.lastAwaitToken();
await harness.injectToolCompleted({ token, tool: 'search', result: 'found it' }).runTurn();

harness.expectTurn(t => t.expectTransition('complete'));
```

## 9. `TurnTrace` Changes

### `rewards` field (new)

`TurnTrace` now includes an optional `rewards: { total: number }` field, populated from the `oneTurn` reward computation (extrinsic + intrinsic reward sum).

```typescript
const trace = harness.lastTrace();
expect(trace.rewards?.total).toBe(5);
```

### Accessing traces

| Method | Returns |
|--------|---------|
| `harness.lastTrace()` | Last `TurnTrace` |
| `harness.allTraces()` | `readonly TurnTrace[]` |
| `harness.currentM()` | `Readonly<MentalState<Sensory>>` |
| `harness.replies()` | `readonly unknown[]` of `ctx.reply()` calls |

## 12. Test and tooling checklist

- [ ] Replace all `runLoop()` / `oneTurn()` calls in tests with `createTestHarness().runTurn()`.
- [ ] Update module mock signatures to match the `Modules<>` type table (§2).
- [ ] Update `execution` mocks to return `ExecOutcome` (`{ action, result: { status, data } }`).
- [ ] Move `transition` logic out of `execution` into a separate `transition` module.
- [ ] Replace `InvariantError` constructor calls with payload object form.
- [ ] Replace manual LLM mocks with `harness.llmStub().enqueue()`.
- [ ] Replace manual tool mocks with `harness.toolStub().register()`.
- [ ] Replace raw JSON trace assertions with `harness.expectTurn()` helpers.
- [ ] Remove all `as any` casts from test files.
- [ ] Run `npm test` — all tests pass.
- [ ] Run `npx tsc --noEmit` — zero errors.

## 13. Breaking changes (summary)

1. **`runLoop()` / `oneTurn()` in tests** — deprecated; use `createTestHarness()`.
2. **`Modules.execution` return type** — must return `ExecOutcome` (`{ action, result: { status, data } }`), not mixed execution+transition objects.
3. **`transition` is a separate module** — no longer embedded in execution return.
4. **`ExecResult.status`** — uses `'ok' | 'error'`, not `success: boolean`.
5. **`InvariantError` constructor** — takes `InvariantErrorPayload` object, not positional args.
6. **`TurnTrace.rewards`** — new optional field `{ total: number }`.
7. **`DeterministicLLMStub.getHistoryMode()`** — stub exposes `getHistoryMode()`, making default `answer_with_llm` treat it as "configured" (calls `ctx.llm.call()`).
8. **`TaskContext` construction** — `createTestContext()` replaces manual `ctx: any` objects.
9. **Observation injection** — validated through `normalizeObservationInbox()`, not raw push.
10. **Assertion errors** — `HarnessAssertionError` replaces generic `Error` in test assertions.
