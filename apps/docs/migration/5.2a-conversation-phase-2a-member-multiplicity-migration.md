# Migration: Conversation Phase 2a (topic member multiplicity)

This document tracks **breaking changes** for Phase 2a.
There is **no backward compatibility shim** for pre-2a topic contracts.

## Summary of breaking changes

1. Topic membership identity is now **`memberId`** (seat identity), not `agentId`.
2. `TopicMember` input adds optional `memberId`; resolved outputs always include `memberId`.
3. `TopicSelector.kind === 'explicit_recipient'` now uses:
   - `{ recipient: { by: 'agentId', agentId } }`, or
   - `{ recipient: { by: 'memberId', memberId } }`
4. `OutboundTopicMessage` adds optional `senderMemberId`.
5. `InboundMessage` adds required `recipientMemberId`.
6. `DeliverySummary` adds required `memberId`.
7. `FanoutSendReceipt.partial.rejected[]` adds required `memberId`.
8. New `ConversationError` branches:
   - `RecipientAmbiguous`
   - `SenderAmbiguous`
   - `RecipientNotResolvable`
9. `TurnTrace.topicSelectorDecision.resolvedRecipients` is renamed to:
   - `topicSelectorDecision.resolvedMembers: Array<{ memberId, agentId }>`
10. `ConversationProjection.topics[id].members` entries now include `memberId`.

## SQL / persistence migration

Apply migration:

- `packages/memory-sql/prisma/migrations/20260417120000_conversation_phase2a_member_multiplicity/migration.sql`

Key DB changes:

- `conversation_topic_members`
  - add `member_id`
  - PK changes from `(tenant_id, conversation_id, agent_id)` to `(tenant_id, conversation_id, member_id)`
  - add unique `(tenant_id, conversation_id, session_id)`
- `conversation_topic_invites`
  - add `invitee_member_id`
- `conversation_message_deliveries`
  - add `member_id`
  - uniqueness changes to `(tenant_id, conversation_id, sequence_number, member_id)`
- `conversation_messages`
  - add `sender_member_id`
  - idempotency uniqueness changes to `(tenant_id, conversation_id, sender_member_id, idempotency_key)`
- `conversation_topics.rotation_cursor`
  - switched to nullable text member cursor

## Runtime behavior changes

- Default topic session routing is now per seat (`memberId`), enabling multi-seat participation for the same `agentId`.
- Topic post idempotency key scope is now per sender seat (`senderMemberId`).
- `outbound.committed` routing is stamped to the resolved sender seat session.

## Code migration checklist

1. Replace explicit recipient old shape:
   - from: `{ kind: 'explicit_recipient', recipientAgentId: 'x' }`
   - to: `{ kind: 'explicit_recipient', recipient: { by: 'agentId', agentId: 'x' } }`
2. Add `recipientMemberId` where thread/topic inbound messages are injected in tests.
3. Update assertions and handlers to key on `memberId` (not only `agentId`) for topic membership.
4. Update TurnTrace readers from `resolvedRecipients` to `resolvedMembers`.
5. If you call low-level store APIs directly, migrate to:
   - `getConversationTopicMemberByMemberId`
   - `listConversationTopicMembersByAgent`

## Operational note

Treat this as a **breaking migration window** for persistent environments:

- stop writers
- apply DB migration
- run Prisma generate/build
- restart services
