# Migration: Conversation Phase 2 (topics, fan-out, policy-safe projection)

This document tracks **breaking changes** for Phase 2. There is **no** backwards compatibility with pre–Phase 2 conversation contracts.

## Summary of breaking changes

1. **`ConversationError`**: `ThreadClosed` was removed; use **`ConversationClosed`** for closed threads and topics.
2. **`CloseConversationReceipt`**: the field **`thread`** was renamed to **`ref`** and widened to **`ConversationRef`** (`ThreadRef | TopicRef`).
3. **`ConversationApi.close`**: accepts **`ConversationRef`** (thread or topic).
4. **`InboundMessage.conversation`**: widened to **`ConversationRef`**; narrow with `conversation.kind === 'thread' | 'topic'`.
5. **`TopicCreateReceipt`**: **`status: 'ok'`** with **`topic`** + **`members`**, or **`status: 'rejected'`** with a typed **`ConversationError`** (e.g. capacity, forbidden owner).
6. **`conversation_messages` (SQL)**: `recipient_agent_id` is **nullable** for topic posts; **`conversation_kind`** (`thread` | `topic`) and **`selector_kind`** added. Apply migration **`20260416160000_conversation_phase2_topics`** (`yarn workspace @a2arium/callagent-memory-sql db:migrate`).
7. **Observations**: conversation events are **`{ source: 'conversation', payload: { kind: ... } }`**; **`kind` on the root** is produced by schema transform after parse.
8. **`TurnTrace`**: optional **`topicSelectorDecision`** and **`fanoutSummary`** on topic **`post`** turns; **`conversation.kind`** widened to **`'thread' | 'topic'`**.
9. **New APIs**: `createTopic`, `invite`, `join`, `leave`, `post` (topic-only), per `ConversationApi`.

## Policy / Learning

**`M.memory.conversation`** is populated by the default Learning path via **`reduceConversationProjection`**. Treat it as read-only in Policy (no `ctx.conversation.*` in Policy).

## Idempotent topic `post`

Replay with the same `(tenantId, conversationId, senderAgentId, idempotencyKey)` returns the **same** `FanoutSendReceipt` status and delivery summaries with **`dedupeHit: true`** on each summary; the runtime does not re-deliver to recipients that were previously queued or rejected.

## Example agents

- **`conversation-reference-agent`**: user lines **`go`** (thread Phase 1), **`phase2`** (full Phase 2 owner demo: 3 members with one `sessionIdOverride`, broadcast, round-robin ×2, explicit non-member rejection, idempotent replay, invite token), **`phase2-close`** (topic close).
- **`conversation-responder-agent`**: user **`join`** with env **`CALLAGENT_TOPIC_INVITE_TOKEN`** (from reference `phase2` logs), topic fan-in handling, **`leave-topic`** to leave the room. Thread **`send`** reply flow unchanged.
