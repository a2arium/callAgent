# Migration: Phase 3 — Thread lifecycle, `MessageLog`, `sendTaskToAgent`, trace linkage

This guide tracks **5.3 / Phase 3** as specified in [`../todo/5.3-conversation-phase-3-thread-lifecycle-and-compatibility-sugar.md`](../todo/5.3-conversation-phase-3-thread-lifecycle-and-compatibility-sugar.md). It is organized into the **19 sections** required by that spec’s “Mandatory Migration Guide”.

## 1. Overview

Phase 3 delivers:

- **Thread lifecycle** — `ctx.conversation.close` emits `thread.closed` to both participants; optional `archiveAfter` and `ctx.conversation.archive` emit `thread.archived`; **idle TTL** with deterministic sweeper; `ThreadExpired` vs `ConversationClosed` distinction.
- **`MessageLog` port** — public types under `packages/core/src/public-types/messageLog/**`, default **DB-backed** implementation `createDbMessageLog` in `packages/core/src/eventbus/dbMessageLog.ts`. `ConversationService` appends via `MessageLog`; idempotency uses `findByIdempotency`.
- **`ctx.sendTaskToAgent` as sugar** — single composition path via `ApiBinder` / shared builder; bootstraps a thread (`startThread` / `send` with `skipRecipientActivation`) before `A2AService.sendTaskToAgent`.
- **Trace linkage** — `TurnTrace.childCalls[*].childAgentNodeId` and `childTraceId` stamped on successful child dispatch when telemetry allows; absent on failure (not stubbed).
- **Blocking options** — `StartThreadOptions` / `SendOptions`: `awaitMode: 'blocking' | 'deferred'`, `timeoutMs`; typed **`ConversationTimeout`** when a blocking wait times out.

**No backwards compatibility** — see §9-style list below and the normative spec §9.

## 2. No backwards compatibility (summary)

Enumerated breaks match the spec (projection shape, new errors, `MessageLog` seam, `sendTaskToAgent` side effects, `A2ACallOptions.timeout` enforcement, runner parity, trace fields, store method shapes, additive DB columns). Integrators should read spec §9 for the full table.

## 3. Operational posture

- **Database:** additive columns on `conversation_threads` and indexes. Follow-up migrations may use **`CREATE INDEX CONCURRENTLY`** for large tables (see `packages/memory-sql/prisma/migrations/`).
- **Unlike Phase 2a:** no “stop writers” window required for Phase 3 DDL; still validate in staging.

## 4. Thread lifecycle changes

- **`close(thread)`** — emits **`thread.closed`** to **both** inboxes with `ts`, optional `closedBy`, optional `closedReason` / `reasonText` (`explicit` close).
- **`close(thread, { archiveAfter: true })`** — closes then archives in one orchestration path; emits **`thread.archived`** as specified in the implementation. **`archiveAfter: true` on a topic** → **`ArchiveUnsupportedForTopics`** (Phase 4 topic archive).
- **`archive(thread)`** — requires thread **`closed`** first; else **`ThreadNotClosed`**. Signature is **`ThreadRef` only** (topics do not compile).
- **TTL expiry** — exactly one **`thread.closed`** with `closedReason: 'ttl'`, `closedBy` omitted; subsequent **`send`** → **`ThreadExpired`** (distinct from operator **`ConversationClosed`**).

## 5. Manifest changes

- **`communication.threadTtlMs`** — default **3600000** ms (1 hour); use **`null`** to disable TTL for the runtime (see manifest doc).
- **`conversation.threadSweeper.intervalMs`** — default **30000**.
- **`conversation.threadSweeper.batchSize`** — default **100**.
- **`conversation.threadSweeper.autoArchiveAfterMs`** — default **`null`** (sweeper does not auto-archive closed threads unless set).

## 6. `StartThreadOptions.awaitMode` / `timeoutMs`

- Default **`awaitMode`** is **`'deferred'`** — non-blocking; **`timeoutMs`** is ignored at runtime for deferred (documented on schemas).
- **`awaitMode: 'blocking'`** — requires a **`message.correlationId`** for `startThread` when blocking; waits for a correlated **`message.received`** on the sender session or returns **`ConversationTimeout`**.

## 7. `ConversationError` branches (Phase 3)

New/updated branches include: **`ThreadNotClosed`**, **`ThreadExpired`**, **`ConversationTimeout`**, **`ArchiveUnsupportedForTopics`**. Prefer exhaustive `switch (err.type)` with `default: satisfies never` in application code.

## 8. `MessageLog` port

- Types: `@a2arium/callagent-core` re-exports from `public-types/messageLog`.
- Default wiring: **`createDbMessageLog(sessionManager)`**.
- Advanced: provide a custom adapter implementing **`MessageLog`**; keep **`ConversationService`** on the port.

## 9. `sendTaskToAgent` reimplementation

- Public **`TaskContext.sendTaskToAgent` overloads** unchanged for callers.
- Observable: **`conversation_messages`** row(s), parent **`outbound.committed`**, child **`message.received`** aligned with `startThread`/`send`.
- **`A2ACallOptions.timeout`** — enforced (maps to conversation **`timeoutMs`** / race).
- **`A2ACallOptions.conversation?: ThreadRef`** — multi-turn reuse of an existing thread (**not** `TopicRef` / `ConversationRef`).

## 10. `A2ACallOptions.conversation: ThreadRef`

Use when continuing an existing thread across multiple child invocations without closing the thread.

## 11. Streaming runner parity

`streamingRunner` delegates to the **same** `sendTaskToAgent` implementation as the classic runner (no duplicate child-call bookkeeping).

## 12. `TurnTrace.childCalls` linkage

- **`childAgentNodeId`** / **`childTraceId`** — present on **success** when A2A/telemetry provides them; **absent** on failure.
- Debug: walk parent → child using **`childTraceId`** (see [`../12-how_to_debug_with_turn_trace.md`](../12-how_to_debug_with_turn_trace.md)).

## 13. Projection shape

`ConversationProjection.threads[id]` may include: **`closedAt`**, **`closedReason`**, **`closedReasonText`**, **`closedByAgentId`**, **`archivedAt`**, **`archivedByAgentId`**, **`archivedReasonText`**, **`expiresAt`**. Policy may narrow on **`status`** and **`closedReason`** (e.g. **`'ttl'`**) without calling APIs.

## 14. Store API surface (integrators)

`IWorkingMemorySessionStore` gains thread lifecycle helpers (`updateConversationThreadStatus` discriminated union, **`refreshConversationThreadExpiry`**, **`listConversationThreadsForSweep`**, **`getConversationThread`**, etc.). Custom stores must implement the updated interface.

## 15. Persistence migration (SQL)

- Columns on **`conversation_threads`**: lifecycle and archive metadata, **`expires_at`**.
- Indexes (including concurrent rebuilds in follow-up migrations): support sweeps by **`expires_at`** and **`closed_at`**.
- **CHECK** constraints may enforce **`status`** and **`close_reason`** literals (see migrations under `packages/memory-sql/prisma/migrations/`).

## 16. Testing migration

- Harness: register **`TaskEngine`** with **`EngineLocator.setEngine`** where **`tickThreadLifecycleSweep`** / TTL is used.
- Prefer deterministic **`Clock`** / explicit sweeper ticks — avoid wall-clock sleeps in CI.

## 17. Export changes (library)

Re-exports include thread lifecycle types, **`MessageLog`** schemas/types, sweeper-related config surfaces as documented in `public-types`.

## 18. No manifest registry change

**`agentId`** registry semantics unchanged (still 1:1 agent identity; topic seats remain **`MemberId`** from Phase 2a).

## 19. Canonical example

See **`apps/examples/conversation-reference-agent`** (Phase 3 demo: user line **`phase3-archive`** after **`go`**). Related: **`apps/examples/conversation-responder-agent`**.
