# 5.4d — Migration (incremental)

Phase **4d** adds **shared topic projections** (named folds over the topic `MessageLog`), **`readProjection` / `appendSignal`** on the conversation API, manifest **`communication`** capability fields, and related validation and observations.

## Agent manifest: `communication`

Optional block on **`AgentRuntimeManifest`** (validated in `@a2arium/callagent-types`):

| Field | Role |
| --- | --- |
| `threadable` | When `false`, **`startThread`** targeting this agent is rejected (`RecipientNotThreadable`). |
| `wakeOnTopicMessage` | Default **`false`**. When `true`, topic deliveries may run the same activation path as thread deliveries for that agent. |
| `acceptedSpeechActs` | If set, only listed speech acts are accepted for deliveries to this agent (`SpeechActNotAccepted`). |
| `acceptedContentTypes` | If set, outbound content must carry a matching `mimeType` (`ContentTypeNotAccepted`). |
| `jsonSchemas` | Reserved for future payload validation (`JsonSchemaValidationFailed` exists in core errors; enforcement is not wired end-to-end yet). |
| `topicPoliciesSupported` | Declares topic policy ids the runtime claims to support; mismatches with coordinator-required policies emit **`topic.policy.unsupported`** (see coordinator `topicPoliciesSupported` on create/invite). |

Integrators should treat **`communication`** as the capability contract between coordinator and agent runtime.

## Core API

- **`ctx.conversation.readProjection(topic, token, options?)`** — folds the topic log through a registered projection (e.g. built-in **`topic.transcript`**). Returns **`ReadProjectionReceipt`** (`ok` with `state` + `asOfSequence`, or `rejected` with **`ConversationError`**).
- **`ctx.conversation.appendSignal(topic, input, options?)`** — appends a **`signal`** speech act with `content: { signalType, body }` after validating **`signalType`** against **`SignalKindSchema`**.

Built-in registrations: call **`ensureBuiltinTopicProjectionsRegistered()`** once per process ( **`TaskEngine`** does this in its constructor). Use **`topicTranscriptProjectionToken`** with **`readProjection`**.

Custom projections: **`defineTopicProjection`** + **`getTopicProjectionRegistry().register(...)`** (or test helpers) before use.

## Message log: `speechAct`

Append/read paths use the closed **`SpeechActSchema`** enum. Persisted rows must use valid enum values; invalid historical rows will fail when read through **`dbMessageLog`** / projection folds.

## Testing

- No broker requirement beyond existing Phase 4c transport tests.
- For registry isolation in unit tests, reset the registry and builtins via test hooks if you register custom projection names (see **`resetTopicProjectionRegistryForTests`** and ensure builtins are re-registered afterward).
