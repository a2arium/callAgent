# Migration Guide: Stage Facade (v3.4)

This guide describes how to migrate from the pre-3.4 stage facade API to the new first-class Stage Facade: Zod-backed config, restricted `onEnter`, atomic transitions, and consolidated control-var accessors. There is **no backwards compatibility**: code that used the old optional `createStageFacade` form, full `TaskContext` in `onEnter`, or the removed control-var helpers will no longer compile or run as before.

**Related docs:** [How to use StageFacade in APLRET](../5-how_to_use_stage_facade_in_aplret.md) (usage guide)

---

## Why this change?

The previous stage facade was a thin helper with several architectural gaps:

- **No runtime validation** — Invalid config (e.g. typo in stage name, wrong invariant keys) was only caught at runtime when a transition failed. Config is now validated at **creation time** via a Zod schema keyed by your `stages` array.
- **`onEnter` had full `TaskContext`** — Hooks could call `reply`, `requestInput`, tools, or child dispatch, blurring the line between control-plane telemetry and real effects. That violated the APLRET rule that stage entry should be telemetry-only. **`onEnter` now receives only `StageEnterContext`** (`progress` and `complete`).
- **Non-atomic transitions** — Stage was set first, then autoMarks, then `onEnter`. If `onEnter` threw, stage and marks were already committed and there was no rollback. The new facade **validates before commit**: it checks invariants against the state that would exist after stage + autoMarks; only then does it commit. **`onEnter` runs post-commit** and is explicitly non-transactional (if it throws, stage and marks are not rolled back).
- **Scattered control-var sync** — Three different code paths synced control vars into the active loop (`stageHelpers`, `ControlVars`, `TaskStateUtils`), with `as any` casts. Control-var access is now **consolidated** in `readControlVar` / `writeControlVar` / `deleteControlVar` / `resolveControlVars`, with proper types and a single source of truth.
- **Missing API surface** — No `is()`, no normalized `summary()`, and `setStage` returned `void`. The facade now exposes **`is(ctx, stage)`**, **`summary(ctx)`** (normalized shape without leaking raw control keys), and **`set()`** returns **`StageTransitionResult`** for logging and tests.

This migration brings the stage facade in line with the APLRET contracts and makes stage transitions predictable and testable.

## Breaking changes at a glance

| Breaking change | Impact | Section |
|----------------|--------|---------|
| **`stages` is required** in `createStageFacade` options | Compile error if missing | §1 |
| **`onEnter`** receives **`StageEnterContext`** (only `progress`, `complete`), not `TaskContext` | Compile error if you pass full `ctx` to effects; runtime change if you relied on `reply`/`requestInput`/etc. in `onEnter` | §2 |
| **`getStage` → `get`**, **`setStage` → `set`**, **`assertStage` → `assert`** | Compile error at every call site | §3 |
| **`StageInvariants`** type removed | Use **`StageInvariantMap`**; compile error on old type import | §4 |
| **`validate?`** on stage invariants removed | Compile error; custom validation must move to Transition (or Execution before `Stage.set()`) | §5 |
| **`TaskStateUtils.syncControlVarIntoActiveLoop`** and **`clearControlVarInActiveLoop`** removed; **`ControlVars.syncIntoActiveLoop`** and **`ControlVars`** removed | Compile error; use **`writeControlVar`** / **`deleteControlVar`** from `@a2arium/callagent-core` | §6 |

## Overview of what changed

- **Single options object** with **required** `stages` array. No backwards compatibility with the old optional form.
- **`onEnter`** callbacks receive **`StageEnterContext`** with only `progress(pct, message)` and `complete(pct, message)`.
- **`set()`** returns **`StageTransitionResult<St>`** and supports **atomic** stage + autoMarks (validate-before-commit); **`onEnter`** runs post-commit and does not roll back stage/marks if it throws.
- New methods: **`is(ctx, stage)`**, **`summary(ctx)`** (normalized shape `{ current, hasPendingInput, hasPendingTool, hasPendingChild, markCount }`).
- Method renames: **`getStage` → `get`**, **`setStage` → `set`**, **`assertStage` → `assert`**.
- **`StageInvariantRule`** is canonical (require/forbid only); **`validate?`** is removed.
- Control-var sync is consolidated in **`readControlVar`** / **`writeControlVar`** / **`deleteControlVar`** / **`resolveControlVars`** from `@a2arium/callagent-core`.

## End-to-end example: agent module before and after

**Before (pre-3.4):** Agent used optional `createStageFacade`, full `TaskContext` in `onEnter`, and old method names. Transition called `TaskStateUtils.syncControlVarIntoActiveLoop` for tokens.

```typescript
import { createStageFacade } from '@a2arium/callagent-core';
import type { StageInvariants } from '@a2arium/callagent-core';
import { TaskStateUtils } from './utils/TaskStateUtils.js';

type AgentStage = 'idle' | 'awaiting_fetch' | 'analyzing' | 'completed';

export const Stage = createStageFacade<AgentStage>({
  initial: 'idle',
  invariants: {
    awaiting_fetch: { require: ['fetch.token'] },
    completed: { forbid: ['fetch.token'] },
  },
  autoMarks: { completed: { 'completed.called': true } },
  onEnter: {
    idle: (ctx) => {
      ctx.progress(5, 'idle');
      ctx.reply('Starting…');  // was allowed
    },
    completed: (ctx) => ctx.complete(100, 'completed'),
  },
});

// In transition or execution:
Stage.setStage(ctx, 'awaiting_fetch');
TaskStateUtils.syncControlVarIntoActiveLoop(ctx, 'fetch.token', token);
const current = Stage.getStage(ctx);
```

**After (v3.4):** Required `stages`, `StageEnterContext` in `onEnter`, new method names, and consolidated control-var API. Side effects moved out of `onEnter`.

```typescript
import { createStageFacade, defineControlKeys, writeControlVar } from '@a2arium/callagent-core';
import type { StageFacade, StageEnterContext, StageTransitionResult, StageInvariantMap } from '@a2arium/callagent-core';

const stages = ['idle', 'awaiting_fetch', 'analyzing', 'completed'] as const;
type AgentStage = (typeof stages)[number];

export const CK = defineControlKeys({
  fetchToken: 'fetch.token',
  completedCalled: 'completed.called',
});

export const Stage = createStageFacade<AgentStage>({
  stages,
  initial: 'idle',
  invariants: {
    awaiting_fetch: { require: [CK.fetchToken] },
    completed: { forbid: [CK.fetchToken] },
  },
  autoMarks: { completed: { [CK.completedCalled]: true } },
  onEnter: {
    idle: (ctx) => ctx.progress(5, 'idle'),   // ctx is StageEnterContext; reply moved to Execution
    completed: (ctx) => ctx.complete(100, 'completed'),
  },
});

// In transition or execution:
const result: StageTransitionResult<AgentStage> = Stage.set(ctx, 'awaiting_fetch');
writeControlVar(ctx, CK.fetchToken, token);
const current = Stage.get(ctx);
if (Stage.is(ctx, 'analyzing')) { /* ... */ }
const summary = Stage.summary(ctx);  // { current, hasPendingInput, hasPendingTool, hasPendingChild, markCount }
```

(If you previously sent "Starting…" from `onEnter`, move that to **Execution** or **Transition** after the stage transition, e.g. by having Execution call `ctx.reply('Starting…')` when the intent indicates start.)

## 1. `createStageFacade` signature

**Before:** Options could omit `stages`; `initial` and others were optional in practice.

**After:** You must pass a **`stages`** array (used for Zod validation and stage enum). Derive your stage type from it.

```typescript
// Before
const Stage = createStageFacade<AgentStage>({
  initial: 'idle',
  invariants: { ... },
  autoMarks: { ... },
  onEnter: { ... },
});

// After
const stages = ['idle', 'awaiting_fetch', 'analyzing', 'completed'] as const;
type AgentStage = (typeof stages)[number];

const Stage = createStageFacade<AgentStage>({
  stages,
  initial: 'idle',
  invariants: { ... },
  autoMarks: { ... },
  onEnter: { ... },  // ctx is StageEnterContext
});
```

---

## 2. `onEnter` callback (breaking)

**Before:** `onEnter` received full **`TaskContext`** and could call `reply`, `requestInput`, tools, child dispatch, etc.

**After:** `onEnter` receives **`StageEnterContext`** with only:

- `progress(pct: number, message: string) => void`
- `complete(pct: number, message: string) => void`

Any other effect (replies, tool calls, child agents) must move to **Execution** or **Transition**.

```typescript
// Before
onEnter: {
  idle: (ctx) => {
    ctx.progress(5, 'idle');
    ctx.reply('Starting…');  // was allowed
  },
}

// After
onEnter: {
  idle: (ctx) => {
    ctx.progress(5, 'idle');
    // ctx.reply('Starting…');  // compile error — not on StageEnterContext
  },
}
```

If your `onEnter` performed side effects, move that logic into the code path that runs after the transition (e.g. in Execution when handling the intent that leads to that stage).

## 3. Method renames and new methods

| Before | After |
|--------|--------|
| `Stage.getStage(ctx)` | `Stage.get(ctx)` |
| `Stage.setStage(ctx, s)` | `Stage.set(ctx, s)` |
| `Stage.assertStage(ctx, s?)` | `Stage.assert(ctx, s?)` |
| — | `Stage.is(ctx, s)` |
| — | `Stage.summary(ctx)` |

- **`set(ctx, stage)`** returns **`StageTransitionResult<St>`**: `{ from, to, autoMarksApplied, invariantChecks }`. Use it for logging or tests; if you ignore the return value, behavior is unchanged.
- **`summary(ctx)`** returns **`StageSummary<St>`**: `{ current, hasPendingInput, hasPendingTool, hasPendingChild, markCount }` (no raw control keys). Use it when you need a normalized view of control state (e.g. in tests or harnesses).

## 5. Invariants: no `validate?`

**Before:** A stage invariant could include **`validate?: (ctx: TaskContext) => void`** for custom checks.

**After:** Invariants support only **`require`** and **`forbid`** (arrays of control keys). Any custom validation must run in **Transition** (or in Execution before calling `Stage.set()`).

**Before:**

```typescript
invariants: {
  completed: {
    require: ['token'],
    validate: (ctx) => {
      const v = (ctx as any).controlVars;
      if (v?.token && typeof v.expires === 'number' && v.expires < Date.now()) {
        throw new Error('Token expired');
      }
    },
  },
},
```

**After:** Run the same check in Transition (or Execution) before calling `Stage.set(ctx, 'completed')`:

```typescript
// In transition (or execution), before Stage.set(ctx, 'completed'):
const controlVars = resolveControlVars(ctx);
const token = controlVars?.token;
const expires = controlVars?.expires;
if (token && typeof expires === 'number' && expires < Date.now()) {
  throwInvariantError('TOKEN_EXPIRED', 'Token expired', { type: 'token_validation', category: 'input', token, reason: 'expired' });
}
Stage.set(ctx, 'completed');
```

Invariants stay declarative:

```typescript
invariants: {
  completed: { require: ['token'] },  // no validate
},
```

## 6. Control vars and removed APIs

Control-var sync is consolidated in **`readControlVar`**, **`writeControlVar`**, **`deleteControlVar`**, and **`resolveControlVars`** from `@a2arium/callagent-core`. The following are **removed**:

- **`TaskStateUtils.syncControlVarIntoActiveLoop`**
- **`TaskStateUtils.clearControlVarInActiveLoop`**
- **`ControlVars.syncIntoActiveLoop`** and the **`ControlVars`** class/file

**Before:**

```typescript
import { TaskStateUtils } from './utils/TaskStateUtils.js';

TaskStateUtils.syncControlVarIntoActiveLoop(ctx, 'token', token);
TaskStateUtils.syncControlVarIntoActiveLoop(ctx, 'stage', 'awaiting_fetch');

// elsewhere
TaskStateUtils.clearControlVarInActiveLoop(ctx, 'token');
```

**After:**

```typescript
import { writeControlVar, deleteControlVar } from '@a2arium/callagent-core';

writeControlVar(ctx, 'token', token);
writeControlVar(ctx, 'stage', 'awaiting_fetch');

deleteControlVar(ctx, 'token');
```

Snapshot-level helpers **remain** on `TaskStateUtils`: **`applyControlVarToSnapshot`** and **`removeControlVarFromSnapshot`** (they do not take `ctx`).

## 7. Atomicity and post-commit `onEnter`

Behavioral change to be aware of:

- **Stage + autoMarks** are applied **only after** invariant checks pass. The facade computes the would-be state (current control vars + new stage + autoMarks for that stage), runs the invariant rules, and **only then** writes stage and marks. If any check fails, it throws and **nothing** is committed.
- **`onEnter`** runs **after** stage and autoMarks are committed. If `onEnter` throws, the framework **does not** roll back the stage or marks; the error propagates. So: stage transitions are atomic with respect to invariants, but `onEnter` is best limited to telemetry (`progress`/`complete`) so that failures there do not leave you in an inconsistent control state from a business perspective.

No code change is required if you already use `onEnter` only for `progress`/`complete`; just be aware that any throw in `onEnter` does not undo the transition.

## 8. Optional: typed control keys

Using **`defineControlKeys`** centralizes control key names and avoids typos. Recommended but not required.

```typescript
import { defineControlKeys } from '@a2arium/callagent-core';

export const CK = defineControlKeys({
  fetchToken: 'fetch.token',
  completedCalled: 'completed.called',
});

const Stage = createStageFacade({
  stages,
  initial: 'idle',
  invariants: {
    awaiting_fetch: { require: [CK.fetchToken] },
    completed: { forbid: [CK.fetchToken] },
  },
  autoMarks: {
    completed: { [CK.completedCalled]: true },
  },
});
```

## 10. Compilation error resolution

| Error / symptom | Fix |
|-----------------|-----|
| `Property 'getStage' does not exist on type …` | Use `Stage.get(ctx)` |
| `Property 'setStage' does not exist on type …` | Use `Stage.set(ctx, stage)` |
| `Property 'assertStage' does not exist on type …` | Use `Stage.assert(ctx, stage?)` |
| `Type '(ctx: TaskContext, stage: …) => void' is not assignable to type …` (in `onEnter`) | Change callback to `(ctx: StageEnterContext, stage: St) => void`; remove any use of `ctx.reply`, `ctx.requestInput`, etc. |
| `Property 'stages' is missing in type …` | Add `stages` array (e.g. `const stages = ['idle', '…'] as const`) to options |
| `Type 'StageInvariants' is not found` | Use `StageInvariantMap<St>` and update imports |
| `Property 'validate' does not exist on type 'StageInvariantRule'` | Remove `validate`; move validation logic to Transition or Execution before `Stage.set()` |
| `syncControlVarIntoActiveLoop is not a function` / `clearControlVarInActiveLoop is not a function` | Use `writeControlVar(ctx, path, value)` and `deleteControlVar(ctx, path)` from `@a2arium/callagent-core` |
| `ControlVars.syncIntoActiveLoop is not a function` or `ControlVars` not found | Same as above; `ControlVars` is removed |

## 11. Verification

After migrating:

1. **Build** — Run `yarn build` (or your project build). All TypeScript errors from renamed methods, missing `stages`, or changed `onEnter` signature should be resolved.
2. **Tests** — Run `yarn test`. Update any tests that call `getStage`/`setStage`/`assertStage` or assert on the old control-var helpers. Tests that expect `Stage.set()` to return a value can assert on **`StageTransitionResult`** (`from`, `to`, `autoMarksApplied`, `invariantChecks`).
3. **`onEnter`** — Confirm no `onEnter` hook calls `ctx.reply`, `ctx.requestInput`, `ctx.sendTaskToAgent`, `ctx.requestTool`, or any other effect. Only `ctx.progress` and `ctx.complete` are allowed.
4. **Control vars** — Grep for `syncControlVarIntoActiveLoop`, `clearControlVarInActiveLoop`, and `ControlVars`; replace with `writeControlVar`/`deleteControlVar` and fix imports.

---

## 12. Data migration

Persisted snapshots (e.g. `M`, `pending`, `controlVars`) are **not** changed by this migration. The shape of control vars in storage is the same; only the **code paths** that read/write them have changed. No one-time data migration is required.

## 13. FAQ

**Can I still use `createStageFacade` without passing `stages`?**  
No. The option is required and the type will fail at compile time. Derive your stage type from the `stages` array (e.g. `type St = (typeof stages)[number]`).

**My `onEnter` used to call `ctx.reply(...)`. Where should that go?**  
Move it to **Execution** or **Transition**. For example, in Execution, after you perform the action that corresponds to “entering” that stage, call `ctx.reply(...)` there. Keep `onEnter` limited to `progress` and `complete`.

**What happens if `onEnter` throws after the stage is committed?**  
Stage and autoMarks remain committed; the framework does not roll back. The thrown error propagates. Design `onEnter` so it only does telemetry; avoid throwing from it for business logic.

**Do I have to use `defineControlKeys`?**  
No. It’s optional. Using it reduces typos and keeps key names in one place; you can still pass string literals to `require`/`forbid` and `autoMarks`.

**Are existing snapshots or persisted state affected?**  
No. Control var storage shape is unchanged. Only the APIs used to read/write them in code have changed.

**Where is the full list of stage-related types and the contract?**  
See [How to use StageFacade in APLRET](../5-how_to_use_stage_facade_in_aplret.md). In v3.4 the facade and oneTurn only **plumb** stage transition data (`ctx.__stageTrace`, optional `stageTrace` on oneTurn’s return); **full TurnTrace emission** (so debug tools and tests see `stageBefore`, `stageAfter`, etc.) is planned for a later release. Until then, use `Stage.get(ctx)`, `Stage.summary(ctx)`, and the return value of `Stage.set()` for debugging and assertions.
